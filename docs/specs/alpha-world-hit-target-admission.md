# Alpha world-hit target admission

Status: FINAL / STABLE / HELD.

## Image and scope

Supported original client: `binary/Cube.exe` in the relative evidence root `disassembled alpha cube world`, 3,885,568 bytes, SHA-256 `84a7a132a84d4282338e7ea45a1940d32066d64e39cbafed8f2418d5a6dc30bf`, preferred base `0x400000`. All addresses below are RVAs. Evidence consists of that original image, `decompiled/client/assembly.txt` and individually identified original function files. No other contract, reconstruction, replacement implementation, runtime observation or implementation history was read for this audit.

The audited world application is `0x195A60`. Its receiver is the world; its explicit arguments are a hit-record pointer, an output-aggregate pointer and a further four-byte argument saved for fatal processing. That last argument's full type and ownership remain unresolved. This contract closes admission and ordinary local effects through the final health test at `0x196133–0x196143`, and identifies the ensuing fatal boundary. It does not reconstruct fatal rewards, removal, linked-actor cleanup or downstream transport.

This is not the client frame's socket-hit consumer. A world-step call to this routine is directly visible at `0x20CD9B`; generic producer `0x196D30` also calls it, including `0x19700F`, `0x197229`, `0x1974DD` and `0x1986D0`. Their enclosing routes are separate caller dependencies. No server counterpart is inferred. Evidence: `binary/Cube.exe`, those call sites; original direct-call inventory in `decompiled/client/assembly.txt`.

The 72-byte record supplies source identifier at `+0`, target identifier at `+8`, binary32 amount at `+0x10`, signed four-byte timers at `+0x18` and `+0x1C`, binary32 response components at `+0x38/+0x3C/+0x40`, and category byte at `+0x45`. Creature identifiers are eight bytes at `+8`. Role/discriminator `+0x60` is one byte, kind `+0x64` is four bytes, health `+0x16C` is binary32, and flags `+0x7E` are read as a 16-bit word. Numeric roles and kinds are retained without assigning unsupported faction or ownership names.

## Target lookup and delivery-only admission

The routine first looks up the record's target identifier in the world's creature table at `+4`, using helper `0x077D90`. A table miss, a matching node whose creature pointer is null, or target health at most zero returns immediately. These returns precede source lookup, event delivery and local target mutation. Zero health is rejected, not admitted for a second fatal pass. Evidence: `binary/Cube.exe`, RVAs `0x195AAB–0x195AF7`.

The identifier lookup compares the complete eight-byte key. Its ordering treats the high four bytes as signed and, when they are equal, the low four as unsigned. A matching identifier must match both halves. A zero identifier is not intrinsically treated as an absent key: an actual matching table entry can be found. The table sentinel and a null stored creature pointer are distinct rejection cases. Evidence: `binary/Cube.exe`, helper `0x077D90–0x077E03`.

For an admitted living target, world pointer `+0xB8` null **and** target role byte `+0x60` zero selects a delivery-only route: the incoming record is appended to the output aggregate's leading hit list through helper `0x086290`, and this routine returns. It does not look up source or apply the ordinary local mutations described below. World byte `+0xB4` is not tested before this route. A role-zero target therefore need not be locally mutated merely because its record reached the world application. Evidence: `binary/Cube.exe`, RVAs `0x195AFD–0x195B18`.

The copy helper preserves the semantic record fields, not an assurance of identical opaque padding. Its copy includes four-byte fields through `+0x10`, byte `+0x14`, four-byte fields `+0x18` through `+0x40`, and bytes `+0x44/+0x45/+0x46`; it does not establish bytes `+0x15–+0x17` or `+0x47`. The list container's append/allocation failure behavior is outside ordinary completion. Evidence: `decompiled/client/functions/00486290.c`, `00451ee0.c`, `004599a0.c`.

All other admitted targets take the local route. For this document only, **designated target** means pointer identity with world `+0xB8`; this avoids equating that field's meaning with an unproved role label. A nonnull `+0xB8` removes the delivery-only test for every target, but later checks still distinguish pointer equality with it. The complete initialization and transition lifecycle of world `+0xB4/+0xB8` is not established here.

## Source identity and effects before protection

The local route next looks up the record's source identifier in the same world table. A miss produces a null source pointer; a matched null stored pointer likewise remains null. There is no source-health requirement. Neither source nor target is replaced here by an owner identifier, the designated pointer, the source's `+0x198` identifier, or the target's linked identifiers. Source and target may resolve to the same object. Evidence: `binary/Cube.exe`, RVAs `0x195B1D–0x195B43`.

For a strictly positive amount, the target first loses binary32 `+0x1190` according to a level-dependent relation. Its signed four-byte `+0x190` less one is combined with its zero-extended byte `+0x1A8`; that integer is converted to binary32 and multiplied by 0.25, then widened for the original precise power call with binary64 base 2. The power result is narrowed to binary32. The record amount is separately multiplied by binary32 0.25, divided by the narrowed power result, and subtracted from target binary32 `+0x1190`, with binary32 rounding at each arithmetic boundary. A negative result is replaced with zero; equality to zero is retained. If the target action byte is 84, it is cleared and signed four-byte stun timer `+0x12C` is set to 3000. These effects precede the contributor protection gate and the later health-admission helper, and do not require an admitted health reduction. Evidence: `binary/Cube.exe`, RVAs `0x195B3E–0x195BD5`; constants RVAs `0x345E18` (binary64 2), `0x345D98` (binary32 0.25).

For amount at least zero and a nonnull source, further effects follow in this order:

1. The source's eight-byte `+0x11D0` becomes the record target identifier, then the target's `+0x11D0` becomes the record source identifier.
2. In source map `+0x13AC`, the binary32 value keyed by record target identifier is increased by 1.
3. In target map `+0x13A4`, the binary32 value keyed by record source identifier receives a weighted amount plus binary32 constant bits `0x3C23D70A` (approximately 0.01). The weighted amount is formed first, the constant is added next, and the previous map value is added last, with separate binary32 rounding.
4. Helper `0x1A0970` is called with world receiver, source first, target second, and the output aggregate third.

Map lookup/creation helper `0x068AD0` supplies a zero-valued entry when absent. The weight multiplier is 1 when source predicate `0x044520` is true; otherwise 10 for source kind 25; otherwise 20 when source equipment byte `+0xAA8` is 3, item predicate `0x044820` succeeds on that embedded item, and source specialization byte `+0x141` is 1; otherwise 2. Equal source and target identifiers do not skip these writes: an existing self source can create a self-keyed positive map value even for amount zero. Evidence: `binary/Cube.exe`, RVAs `0x195BD5–0x195CE4`; original helpers `0x068AD0`, `0x044520`, `0x044820`; constants RVAs `0x2FCDA0`, `0x345DC0`, `0x345E74`, `0x2FCD74`, `0x345E10`.

Predicate `0x044520` is true for source class byte 3, source kind 117/86/104, or source embedded-item bytes `+0xAA8/+0xAA9` equal to first byte 3 and second byte in `{6,7,8,10,11,12}`. Item predicate `0x044820` requires first item byte 3 and second byte in `{5,6,7,8,10,11,15,16,17,18}`. These numeric sets affect tracking weights; they are not themselves health-admission sets. Evidence: original `decompiled/client/functions/00444520.c`, `00444820.c`.

Helper `0x1A0970` first appends an aggregate `+0x50` record containing target identifier, source identifier and the current target-map value for that source. It then visits other nonnull world creatures, excluding pointer-equal source and target. For candidate C, it tests relationship helper `0x196CA0` with **C first, source second**. A successful candidate must also be strictly within squared distance 64 of the target. Coordinates are signed 64-bit fixed values at actor `+0x10/+0x18/+0x20`; each candidate-minus-target difference is rounded to binary32 before multiplication by `1/65536`. The squared components are separately rounded and accumulated in Y, X, Z order. Equality to squared distance 64 does not pass. If C's map `+0x13A4` value for the source identifier is exactly zero, it becomes binary32 0.5 and another aggregate `+0x50` record is appended for C and source. There is no candidate-health test in this helper. These are relationship-state output records, not re-appended 72-byte hits. Evidence: `binary/Cube.exe`, RVAs `0x1A0970–0x1A0BD0`; constant RVA `0x2FD330` (64).

## Contributor protection and its established producers

After the preceding effects, target flag word `+0x7E` mask `0x2000` controls an additional gate. With the bit clear, processing continues. With it set, the routine searches the target's `+0x13A4` map in native map traversal order. It requires at least one entry whose binary32 value is strictly positive, whose eight-byte key resolves in the world creature table, whose stored creature pointer is nonnull, and whose resolved role byte `+0x60` is zero. The first qualifying entry admits continued processing. An empty map or no qualifying entry returns. There is no comparison of that contributor with the current source, the target's owner, or world `+0xB8`, and no contributor-health test. A positive entry for a missing actor, a null actor, or a nonzero-role actor does not qualify. Zero and negative values do not qualify. Evidence: `binary/Cube.exe`, RVAs `0x195CE7–0x195D6A`.

This gate is not a transaction around earlier effects. The current nonnegative hit can already create or increase its source's target-map contribution before this search, and the relationship helper can already have appended output. For a source resolved with role zero, that newly positive contribution can itself satisfy the gate. Conversely a rejected hit can leave tracking state, `+0x1190` reduction and action/stun interruption already changed.

Recoverable upstream state is bounded as follows. The target map entry updates and helper fanout immediately above are verified value producers. Client construction explicitly writes the controlled creature's role byte to zero at `0x06216C`; original load routine `0x04BE40` also writes its destination creature's role byte to zero at `0x04BF98`. These establish actual role-zero writes, not a proof that role zero uniquely means local ownership. The complete producers of role values, kind values, status masks and, specifically, mask `0x2000` in the actual creature flag word are not closed. No similarly numbered flag in an unproved prototype/object layout is treated as that creature field's producer. Evidence: `binary/Cube.exe`, RVAs `0x062166–0x062176`, `0x04BF98`; original `decompiled/client/functions/0044be40.c`.

## Response, timers and category exits

An admitted category byte 3 returns immediately after the contributor gate. It therefore skips all following response/timer/resource/health work, while retaining any preceding tracking and positive-amount effects. Evidence: `binary/Cube.exe`, RVAs `0x195D70–0x195D74`.

For every other category and amount at least zero, the record's response vector is considered first. When the target's existing signed stun `+0x12C` is positive and the record's signed timer `+0x18` is at most zero, each incoming component is multiplied by binary32 bits `0x3DCCCCCD` (approximately 0.1). Otherwise it is used unchanged. Response storage at target binary32 `+0x4C/+0x50/+0x54` can be replaced only when target role is not 6 and either world byte `+0xB4` is zero with target role nonzero, or target pointer equals world `+0xB8`. The incoming squared magnitude must be at least the existing squared magnitude; equality replaces. Both squared magnitudes use separate binary32 squares and Y-plus-X, then Z accumulation. Stores are in increasing component-offset order. Independently of response replacement, a positive record timer `+0x18` clears all three main-velocity fields `+0x34/+0x38/+0x3C`. Negative amounts skip this entire vector/velocity portion. Evidence: `binary/Cube.exe`, RVAs `0x195D7A–0x195E51`.

Next, a positive signed record timer `+0x1C` raises target signed four-byte `+0x130` to the larger of its old value and the record value; a zero or negative record value leaves it unchanged. Category 1 then adds binary32 0.25 to target resource `+0x170`, caps a result strictly above 1 to 1, and returns. It does not enter the following stun/health ownership gate. Category 4 calls target helper `0x03CF20` with the output aggregate and returns. Evidence: `binary/Cube.exe`, RVAs `0x195E51–0x195EB5`.

Helper `0x03CF20` is admitted by nonzero four-byte target lock `+0x128`, class byte 4 and specialization byte 1. It adds 0.25 to resource with an upper cap of 1, locally applies resident type 11 with amount zero, duration 30000 and source identifier zero, then appends a self-to-self 40-byte buff event at aggregate `+0x58`. Its resident application/overwrite policy remains a dependency. A failed helper admission produces none of those effects, but the caller still returns after the category-4 call. Evidence: `binary/Cube.exe`, RVAs `0x03CF20–0x03CFE1`.

For all remaining category bytes, a positive signed record timer `+0x18` raises target signed stun `+0x12C` to the larger of its current value and that timer. The timer update precedes health ownership. World byte `+0xB4` nonzero then returns unless the target pointer is exactly world `+0xB8`. Thus non-designated targets can receive earlier local effects and still be denied health processing. World byte `+0xB4` zero permits this health phase for every target that has reached it. Evidence: `binary/Cube.exe`, RVAs `0x195EBA–0x195EE7`.

## Amount and health admission

The health phase distinguishes strictly positive, exactly zero and strictly negative binary32 amounts. A positive category-5 amount visits every resident type-6 record in target list `+0x1178`, in forward list order. Its binary32 amount is reduced by the full hit amount; a nonpositive difference sets both that resident amount and its four-byte duration to zero. For each matching record, a 40-byte buff event is appended at aggregate `+0x58`, with the hit record's source and target identifiers followed by that updated resident record. No matching record is removed by this body, and no health subtraction occurs in this category-5 path. Evidence: `binary/Cube.exe`, RVAs `0x195EED–0x195FC7`.

Every other positive category reaching this phase calls health-admission helper `0x03E310` on the **target first**. Only if it succeeds and source is nonnull is it called on the **source second**. A missing source skips the source predicate and does not by itself block positive health subtraction. On success, the stored health becomes old binary32 health less the record amount, with one binary32 subtraction. Failure of either required predicate leaves health unchanged at this point. The category byte's ordinary positive-health branch is not restricted to a single named category. Evidence: `binary/Cube.exe`, RVAs `0x195FCC–0x196003`.

The complete `0x03E310` relation is true for role bytes 0, 1, 3 and 5. It is also true for role 6 when the four-byte kind is not 140, 141 or 142. It is false for role 6 with one of those three kinds and for every other role byte, including 2, 4 and ordinary out-of-set byte values. Neither current health nor world ownership, map membership, source/target equality, damage amount or a resident buff is tested inside this helper. Evidence: `binary/Cube.exe`, RVAs `0x03E310–0x03E344`.

Exactly zero amount makes no health change, but it can already have executed the nonnegative tracking, response and timer work. A negative amount bypasses both health-admission helper calls: it is subtracted from target health as a binary32 operation, thereby increasing ordinary health. Maximum-health helper `0x044DB0` is called once and its result rounded to binary32 for comparison. If the newly stored health is strictly greater, that helper is called again and the second result is stored as health. Equality does not cause the second call. The maximum-health/stat calculation itself is outside this contract. Evidence: `binary/Cube.exe`, RVAs `0x196008–0x196052`.

For a negative amount only, world byte `+0xB4` zero additionally starts a world-creature traversal. For each nonnull candidate C, relationship helper `0x196CA0` receives **source first, C second**, which reverses the argument roles used by the earlier fanout helper. If true, C's `+0x13A4` map must contain an entry keyed by the healed target's identifier. Membership is sufficient; its value is not required positive. C's map entry keyed by the source's identifier is then created if needed and reduced by the negative record amount multiplied by binary32 0.1, which increases the ordinary map value. Helper `0x1A0970` is subsequently called with source first and C second. These operations occur before the final fatal-health test. Evidence: `binary/Cube.exe`, RVAs `0x196058–0x19612D`.

There is no null-source guard before that negative-amount relationship traversal. Under a stable ordinary world table containing the admitted target, a missing/null source and world byte zero cause a relationship-helper invocation with a null first pointer when the traversal reaches a nonnull creature. That helper directly dereferences its first argument. The earlier health increase and clamp can already have occurred; this combination has no proven successful-return behavior and must not be described as a safely supported source-free heal. With world byte nonzero, this fanout is skipped. Positive source-free application has a different native admission path.

The critical byte at record `+0x44` is not used by these admission and amount branches to double or otherwise rescale the amount. They consume the amount already present in the record. This does not specify how a producer calculated it.

## Relationship predicate identity

For `0x196CA0`, argument order is observable. Its first early rejection is first actor role 5 together with second actor role 0. Either actor having role 6 also rejects. Thereafter, exactly one actor having role 1 accepts. When both have role 1, helper `0x044680` is called on the first then the second: differing low-byte results accept immediately. Equal results lead to another first-then-second pair of calls, followed by the remaining status checks. Finally, mask `0x20` in byte `+0x124` of either actor accepts; with neither mask set it rejects. No pointer-identity, identifier, owner lookup, health or distance test occurs in this predicate. A nonnull valid object for each argument is required. Evidence: `binary/Cube.exe`, RVAs `0x196CA0–0x196D2A`.

Helper `0x044680` is true only when creature word `+0x7E` has no bit in mask `0x1A00` and four-byte kind belongs to this decimal set:

`19, 20, 22, 23, 25, 26, 27, 30, 31, 32, 33, 34, 35, 53, 55, 56, 57, 58, 59, 67, 68, 74, 87, 92, 93, 98, 100, 106, 107, 145, 146, 147`.

It returns false otherwise. The upstream complete producers of these kind/flag classifications and of status mask `0x20` are not closed. This predicate's truth value is not renamed as an unproved faction or owner relationship. Evidence: `binary/Cube.exe`, RVAs `0x044680–0x044759`.

## Fatal boundary and output distinction

All paths that reach `0x196133` re-read target binary32 health. Strictly positive health returns through the ordinary exit. Health at most zero takes the fatal path at `0x196149`; equality is fatal here, although it was rejected at initial admission. Its first visible effects set health to zero, append presentation kind 27 at the target's main position with volume/pitch 1, and reset the target action clock to zero. This is followed by object/region work and a call at `0x19622E` to `0x19B180`, with the target and the saved opaque four-byte argument under the world receiver. Everything from that fatal boundary onward, including helper `0x19B180`, removal, rewards, linked actors and eventual return behavior, is explicitly outside this contract. Evidence: `binary/Cube.exe`, RVAs `0x196133–0x196193`, `0x19621E–0x19622E`.

Category-3, category-1 and category-4 exits, a failed contributor gate and a failed ownership gate leave before that final test. Their side effects must therefore be distinguished from entering this routine's own fatal path. Called resident/stat helpers and exceptions are not subsumed into a guarantee of harmless or atomic failure.

The local route does not automatically append another 72-byte hit merely because local mutation was accepted. Its relationship records, resident-buff events and fatal presentation have their own lists and order. Conversely the special delivery-only route appends the incoming hit without applying its local effects. The routine has no established Boolean acceptance result suitable for substituting for those separate outcomes. The generic producer can append a hit before a mode-gated local call; for example `0x196FF3–0x19700F` tests world byte `+0xB4` before calling this application. The world-step caller at `0x20CD9B` invokes the same routine while traversing a separate input list. Neither observation establishes socket delivery, remote replay, or a client-frame health-consumer equivalence.

Ordinary finite amounts, valid pointers and stable native containers under their real caller protection are assumed. Nonfinite amounts/health, power overflow or underflow, malformed identifiers/containers, concurrent mutation, allocation/length failures, complete map initialization, full source/target owner lifecycle, world mode initialization and all unclosed caller gates remain unresolved. No random draw appears in the audited pre-fatal application, health-admission or relationship bodies; this absence is not extended to fatal processing or unclosed helper internals. Prior held files were not opened or modified. The entire saved document was read back before handoff.
