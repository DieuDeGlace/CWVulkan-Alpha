# Alpha front-end terrain readiness

**Author status — FINAL / STABLE / HELD**

## Scope and evidence

This record follows an ordinary local launch of the original 32-bit Windows Alpha client, from the host window through character selection, character creation and entry into a saved or newly created local world. All addresses are RVAs in the owner's `Cube.exe`, 3,885,568 bytes, SHA-256 `84a7a132a84d4282338e7ea45a1940d32066d64e39cbafed8f2418d5a6dc30bf`. Evidence comprises the original image, its client assembly listing, string/reference tables and the corresponding original routine decompilations. The conclusions concern control flow and presentation decisions.

## Window and first ordinary frame

The host creates an initially hidden 800 by 600 window at 0x0C8BC8. On the successful launch path it prepares the graphics and input devices, attempts to create the save directory and calls the client constructor at 0x0C8FF9. The constructor builds the front-end widgets, including the title root at 0x05AA95 and title action widget at 0x063FAB. It also attempts to read the saved character and world lists. The host requests a maximized window at 0x0C900F after the constructor returns, updates the window at 0x0C902B and requests focus at 0x0C9037. The window procedure at 0x0C83F0 delegates ordinary paint messages to Windows.

Some world preparation precedes the show request. The constructor initializes the requested world name to empty, obtains a timer value for the initial seed and calls the world initializer with that seed and name at 0x05A72D–0x05A741. The initializer at 0x1A52E0 sets the current seed, seeds world parameters and takes the supplied world name. The constructor starts background threads at 0x06353F, 0x063595 and 0x0635EC. The first dispatches to the terrain mesh worker at 0x0690A0 and the third to the world worker at 0x06A8A0, through the thread launcher at 0x050E70 and callbacks at 0x06DB70 and 0x06DBA0. The ordinary show path has no test for a generated region, a published mesh, a minimum resident area or an idle worker.

On each ordinary pass the host checks for a Windows message and dispatches it if present. When input is active and the window has focus it also samples keyboard and mouse device state. It then calls the frame routine at 0x0C9432. With a device and a client, the frame routine samples time, updates the client at 0x0C8633, performs any required graphics reset, calls the renderer at 0x0C86EC and presents at 0x0C86FF. The initial zero previous-tick value gives the first update a zero time difference. A size, focus or graphics-setting change can invoke the device reset at 0x0C8940, which sleeps for 100 milliseconds between failed reset attempts. The pump can sleep after presentation to satisfy its frame interval. Neither sleep measures terrain readiness.

## The decision that displays “Please wait...”

The client initializes its smoothed terrain fog distance at offset 0x1D4 to zero at 0x059E9A. Each update scans the in-world part of its current terrain-slot square at 0x089034–0x0892B8. A slot with zero active primary terrain groups, or with stored coordinates different from the requested coordinates, can reduce the distance to the nearest missing terrain. The update starts with the square of the configured maximum distance, takes the square root of the resulting minimum, subtracts 22.4 and smooths the result using elapsed update time. It floors the smoothed value at 0.0001 and also resets it to that floor when the requested and current world identities differ. See 0x0892B8–0x089372 and 0x0AC150.

The update sets the visibility of the wait widget at 0x08942C–0x08950C. A difference in either the integer seed or the world name turns it on for any screen. With matching identities, a smoothed distance strictly below 8.0 turns it on only when all four of the title, character picker, server-address panel and world picker are hidden. Exactly 8.0 clears the low-distance condition. The relevant client offsets are 0x800A50 and 0x800A54 for requested seed and name, 0x800448 and 0x378 for current seed and name, and 0x800898 for the wait widget. Its original text is “Please wait...” at 0x2FFE74, referenced at 0x05B5FC.

The renderer acquires the world lock at 0x0AC37E and processes available terrain transfers before it checks the wait widget at 0x0AD47E. If the widget is visible, it temporarily hides the title, character creation, character selection, world selection and world creation roots, and hides the ordinary HUD. It draws the UI at 0x0AD5C0, restores the five front-end roots, ends the scene and releases the lock at 0x0AD676–0x0AD67F. The caller still presents this frame. A subsequent update evaluates the condition again. On the ordinary scene path, a missing terrain column in the camera material lookup yields a fallback block value and rendering continues. See 0x0AD6E2, 0x02F860, 0x02F7E0, 0x0347A0 and 0x034D10. The ordinary scene reaches its UI draw at 0x0BB07B.

## Screen transitions and input

| Screen or action | What can be shown or accepted |
| --- | --- |
| Title | Matching world identity allows the title and its actions to be drawn even when the smoothed distance is at its floor. The title widget resolves its font resource, checks the cursor and draws Start Game, Options and Exit at 0x183320. Its hover choice starts empty at 0x183270. A primary-button press over Start Game with the title and its actions visible hides the title and shows the character picker at 0x07B684–0x07B70F. This action has no terrain test. The drawn background on that pass depends on the terrain already available. |
| Character selection | The picker at client offset 0x800888 has the same low-distance exemption. Its list and preview update requires the picker to be visible and the wait widget to be hidden at 0x089D53–0x089D77. The selection handler at 0x083E70 hides the picker. A saved selection loads that character and shows the world picker at 0x083EDB–0x083EF9. The new-character choice opens the creation form at 0x083F54 and initializes its preview character and edit field. Neither choice requires terrain residency before changing screens. |
| Character creation | The creation form at offset 0x800880 has no low-distance exemption. The first frame after choosing it can therefore show the wait message even when the preceding picker was visible and the world identity is unchanged. At matching identity and a smoothed distance of at least 8.0, this terrain gate clears. The update checks the active form's name and creation eligibility at 0x0896AF–0x0899A6. That check has no wait-widget condition. When the Create Character callback is invoked, it switches to the world picker and records the character at 0x0821A0. Form state can exist and update while its drawing is suppressed. |
| World selection and creation | The world picker at offset 0x80088C is exempt from low fog. As in character selection, its own list update skips the wait state at 0x08A818–0x08A83C. Selecting a saved world hides the picker and submits its seed and name at 0x084209. Selecting a new slot opens the world-creation form at 0x084210. This form, offset 0x800890, also lacks the low-distance exemption. Its Create World callback hides the form and submits the new world's seed and name at 0x082939. |
| Entry into the chosen world | Both routes submit through 0x06F620. Under locks the client records the requested identity at 0x06F6E6–0x06F6FB and removes other entities on this route. The world worker compares identities at 0x06A901 and initializes the requested world at 0x06AFAB on the change path. While the identities differ, a rendered frame uses the wait UI. Once they match and the menu roots are hidden, the ordinary scene and HUD can return when the smoothed distance reaches 8.0. The test does not count all generated regions, require the entire slot square to be meshed, or join the workers. |

Windows continues dispatching key, character and button messages through 0x0C83F0, including during frames for which the wait UI is selected. The cursor/input-mode test at 0x07F1D0 recognizes the title, pickers and creation forms. The wait widget alone does not select that mode. The keyboard handler at 0x07E1B0 has separate tests for front-end forms and an active UI control before dispatching gameplay keys. The wait widget is absent from that test. These paths establish ongoing input processing and the specific menu checks above. They do not establish that every hidden control can receive a click, or that every gameplay action will succeed before its world data arrives.

## Timing limits

Showing the host window, presenting a frame, drawing a particular menu and accepting its selection are distinct events. The update samples the terrain state before that frame's renderer transfers available groups. A transfer later in the same frame cannot change the wait decision already sampled for that draw. World synchronization, file reads, device work and thread scheduling can affect when the presentation occurs. Static evidence gives no fixed elapsed time, guaranteed count of placeholder frames, or guaranteed amount of visible terrain on first presentation. Multiplayer connection timing and exceptional startup or recovery paths are outside this local route.
