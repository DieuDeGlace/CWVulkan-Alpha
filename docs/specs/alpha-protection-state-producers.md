# Alpha protection and classification state producers

Status: FINAL / STABLE / HELD.

This is a bounded original-client contract for the storage, production and consumption of the creature word at `+0x7E`, the `0x20` bit of the byte at `+0x124`, and the world fields at `+0xB4` and `+0xB8`. It establishes concrete initialization, copying, streaming and behavioral changes. It does not assign faction, allegiance, ownership or player-interface meanings to raw flags without an original relation proving that meaning. It is not a complete hit-application or generation contract.

The evidence root is `disassembled alpha cube world`. The supported image is `binary/Cube.exe`, a 32-bit image with preferred base `0x00400000`, length 3,885,568 bytes and SHA-256 `84a7a132a84d4282338e7ea45a1940d32066d64e39cbafed8f2418d5a6dc30bf`. Addresses below are RVAs. Evidence consists of that image and its original instruction listing, `decompiled/client/assembly.txt`, checked against native disassembly, with individually selected original function files under `decompiled/client/functions/`. No server image, replacement implementation, runtime observations or earlier project contract was used as evidence.

## Storage identities

For a creature object, its embedded data starts at creature `+0x10`. Its appearance-related object starts at creature `+0x78`, which is embedded-data `+0x68`. The two-byte flags member of that appearance object is at its `+0x06`, hence creature `+0x7E` and embedded-data `+0x6E` identify the same storage. A generation descriptor has an appearance object at descriptor `+0x74`; its corresponding word is descriptor `+0x7A`. These bases matter: equal numeric offsets in an item or another object are not evidence of a creature flag write.

| Storage | Width and interpretation established here |
| --- | --- |
| Creature `+0x7E` | Raw 16-bit word. Classification reads it as an unsigned word and tests mask `0x1A00`, comprising bits `0x0200`, `0x0800` and `0x1000`. Hit application separately tests `0x2000`. |
| Creature `+0x124` | Low byte of a raw 16-bit embedded-data flags word at embedded-data `+0x114`. The relationship helper reads only the byte and tests `0x20`; copies, resets and the selected stream field operate on both bytes. |
| Creature `+0x60` | One-byte discriminator consumed by the scoped relationship and hit paths. Its complete taxonomy is unresolved here. |
| Creature `+0x64` | Full 32-bit identifier compared by the classification helper; comparison is exact over all 32 bits. |
| World `+0xB4` | One-byte state, with zero versus nonzero tests in the scoped consumers. |
| World `+0xB8` | Four-byte native pointer compared with creature addresses. It is not an actor identifier. |

In the client object, the embedded world begins at client `+0x2E4`. Consequently client `+0x398` and `+0x39C` are the same storage as world `+0xB4` and `+0xB8`. The client’s current creature pointer is at client `+0x8006D0`. Evidence: image/listing at `0x03B6CB–0x03B6D1`, `0x03C180–0x03C1BC`, `0x059827–0x05982B`, `0x059F31–0x059F57`, `0x062220–0x06222C`, `0x21002B–0x210059`.

## What the scoped consumers actually decide

The classifier at `0x044680` returns a Boolean in the low result byte. Any bit from `0x1A00` in creature `+0x7E` makes this result false, regardless of the identifier. Otherwise the result is true exactly for the following `+0x64` values, all shown in hexadecimal:

`13, 14, 16, 17, 19, 1A, 1B, 1E, 1F, 20, 21, 22, 23, 35, 37, 38, 39, 3A, 43, 44, 4A, 57, 59, 5C, 5D, 62, 64, 6A, 6B, 91, 92, 93`.

All other 32-bit identifiers produce false. For example, `0x00000013` and `0x00000113` differ; a matching low byte is insufficient. This routine does not examine `+0x60`, `+0x124`, an owner identifier or a world pointer. It makes no helper or random calls and changes no creature storage. Only the low result byte is defined as the Boolean; upper result bits are not a Boolean extension contract. Evidence: `binary/Cube.exe`, RVAs `0x044680–0x044759`; `decompiled/client/functions/00444680.c`.

The ordered two-creature relation at `0x196CA0` requires valid creature pointers. Its first argument and second argument have distinct roles: first discriminator `5` with second discriminator `0` produces false, and discriminator `6` in either argument produces false. Those exclusions take precedence over the `0x20` bits. With those exclusions absent, exactly one discriminator equal to `1` produces true. When both are `1`, differing classifier results produce true. When neither is `1`, or both are `1` with matching classifier results, either actor’s byte `+0x124` containing `0x20` produces true; otherwise the result is false.

For two discriminator-`1` actors whose classifications match, the original makes four classifier calls, in first, second, first, second order, before the byte tests. A classification mismatch on the first pair returns earlier. There are no random calls or mutations in these helpers. Equal pointers have no special rejection: the same discriminator-`1` actor with `0x20` clear yields false; setting that bit yields true. A high-byte bit such as word `0x2000` at creature `+0x124` does not satisfy the low-byte `0x20` test. Null pointers are not admitted internally. No identifier, link or owner lookup occurs inside this relation. Evidence: image/listing `0x196CA0–0x196D2C`; `decompiled/client/functions/00596ca0.c`.

World hit application at `0x195A60` has additional admission independent of those classification results. It first resolves the record’s 64-bit target identifier at record `+0x08` in world `+0x04`; missing entries, null mapped pointers and ordinary health at creature `+0x16C` less than or equal to zero end this route. For a surviving target with byte `+0x60` equal to zero and null world `+0xB8`, it appends the hit to the supplied output through `0x086290` and returns from this route before source lookup and the later local mutations. This is an event-delivery route, not proof of a successful local health change.

On the other route, source lookup uses the record’s separate 64-bit identifier at `+0x00`. Some amount-dependent shield, action/contact and map changes can precede the target’s `0x2000` protection test. In particular, the original nonnegative-amount/source-present contact and map path, including `0x1A0970`, is earlier than that test. Thus failing the protection test does not roll back those earlier effects.

At `0x195CE7–0x195D6A`, a target with word `+0x7E` containing `0x2000` can continue only if its map at `+0x13A4` has at least one entry whose binary32 value is strictly positive and whose 64-bit key resolves in world `+0x04` to a nonnull actor with discriminator byte `+0x60` equal to zero. Zero-valued entries, missing identifiers and null mapped actors do not qualify. No comparison with the current hit source is required by this test. With no qualifying entry the routine exits before later response and ordinary health/fatal processing. Clearing `0x2000` bypasses this particular map requirement.

The later response and health gates are different. The velocity-selection portion allows a non-`6` target when either world `+0xB4` is zero and target `+0x60` is nonzero, or the target pointer equals world `+0xB8`. The later ordinary amount/health/fatal portion instead requires world `+0xB4` equal to zero or target pointer equal to world `+0xB8`; it is reached only through the record-category route leading to `0x195ED2`. Earlier response/resource/status effects are not made conditional on this later gate retroactively. The `0x1A00` classifier mask is therefore not a universal hit-immunity test. Other category and type predicates remain relevant; this document does not replace them with that mask. Evidence: image/listing `0x195AAB–0x195B55`, `0x195BD5–0x195D74`, `0x195DBD–0x195E36`, `0x195ED2–0x195EED`; selected original portions of `decompiled/client/functions/00595a60.c`.

## Default values, reset scope and preservation

The creature constructor at `0x03B690` constructs embedded data at creature `+0x10` through `0x03C100`. That constructor invokes the appearance constructor `0x028750` for embedded-data `+0x68`. The appearance constructor clears its complete flags word at `+0x06`. It then follows that a normally constructed creature starts with word `+0x7E` zero. Embedded-data construction also clears the complete word at `+0x114`, so the low-byte `0x20` bit starts clear. These are actual stores, not assumptions about allocator contents. The same data constructor sets creature `+0x60` to byte `3` and creature `+0x64` to 32-bit zero; later producers can replace both.

Reset scope matters. The data reset at `0x0465C0`, called on creature `+0x10` from `0x046330`, clears embedded-data `+0x114`, then constructs a fresh temporary appearance and copies it into embedded-data `+0x68`. Thus both scoped flags words become zero through this reset. The narrower data reset at `0x047270`, reached from creature routine `0x047110`, also clears embedded-data `+0x114`, but contains no appearance replacement. That helper preserves the existing `+0x7E` word. This distinction concerns those verified reset operations, not every possible effect of their callers or later callbacks.

Appearance assignment at `0x059800` transfers the complete source word at appearance `+0x06` to the destination. Data assignment `0x04B040` and data copy construction `0x066050` both use that appearance assignment and separately transfer the complete word at embedded-data `+0x114`. Neither strips `0x1A00`, `0x2000` or the low-byte `0x20`. These word transfers are semantic field copies; they do not establish that all appearance padding is copied identically. Their scoped word operations do not draw random values, publish hit events or reinterpret the flags as a faction.

Evidence: image/listing `0x028750–0x02875C`, `0x03B6CB–0x03B6D1`, `0x03C180–0x03C1BC`, `0x04633A–0x04633D`, `0x046697–0x046699`, `0x046738–0x046754`, `0x047113–0x047134`, `0x0472D0`, `0x04B0E7–0x04B0FA`, `0x059827–0x05982B`, `0x0660F6–0x066109`; original function files `00428750.c`, `0043c100.c`, `004465c0.c`, `00447270.c`, `0044b040.c`, `00459800.c`, `00466050.c`.

## Concrete generation and world-update producers

Descriptor construction at `0x1ADB20` constructs an appearance at descriptor `+0x74`, initially clearing descriptor `+0x7A`. A concrete nondefault producer exists inside generator `0x1CC510`. At its branch boundary `0x1D3AC3`, the second byte of the current two-byte grid record must contain `0x04`; otherwise this descriptor-producing branch is skipped. This statement leaves the broader generator and grid-production admission unclosed.

For normal successful allocation/construction of this branch’s descriptor, the original sets descriptor `+0x28` to 32-bit `1`, adds `0x1000` to the appearance flags at `0x1D3BA0`, selects and stores a full 32-bit kind at descriptor `+0x2C`, runs item-generation/insertion helpers, then adds `0x0200` at `0x1D3C2C`. Both flag additions retain every other bit. Before appending the descriptor pointer to the cell’s pointer vector at cell `+0x18`, it also sets descriptor byte `+0x10E8` to `1` at `0x1D3D2F`. The append is at `0x1D3D40`. Thus this is a verified producer of both classifier-excluding bits `0x1000` and `0x0200`, and of the later activation byte gate.

Between the two flag additions, one direct imported random draw selects the kind by unsigned remainder over a nonempty candidate count. A later direct draw occurs after the `0x0200` addition and before `+0x10E8` and the append. The item-generation and other nested helpers have not been audited for all transitive draws. These observations establish the relative placement of the flag stores; they do not establish a complete random-consumption count for descriptor creation. Empty candidate arrays and allocation failure are outside this ordinary successful construction relation. Evidence: image/listing `0x1ADBA0–0x1ADBB1`, `0x1D3AC3–0x1D3D40`; original generator function `decompiled/client/functions/005cc510.c`.

The descriptor-to-creature route in world update `0x20C510` carries these flags into an actor. At `0x21002B–0x210059`, the low byte of descriptor `+0x28` becomes creature `+0x60`, full descriptor `+0x2C` becomes creature `+0x64`, and appearance assignment transfers descriptor `+0x74` to creature `+0x78`. Consequently descriptor word `+0x7A` becomes creature word `+0x7E` unchanged by that copy. The source is the selected descriptor, not its vector index or a world-owner identifier.

There is also a concrete descriptor `0x2000` producer before that creation/copy. After earlier descriptor-context/distance admission not fully characterized here, `0x20FCFE–0x20FD19` requires a nonnull context object whose 32-bit `+0x34` equals `5`, and descriptor flags containing `0x1000`. A seed call occurs, followed by helper `0x1C7730` with the descriptor and an explicit `1` argument. Only after that helper returns does the original re-read the descriptor flags: if the resulting word contains `0x0200` and resulting descriptor byte `+0x10E8` is nonzero, it adds `0x2000` while preserving the rest of the word. Descriptor discriminator `+0x28` equal to `6` skips intervening level/byte copies, but does not itself bypass these post-helper flag tests. Failure of the `0x0200` or nonzero-byte test does not, at this location, clear an already present `0x2000` bit. The later appearance copy can then carry `0x2000` into the hit-protection consumer described above. The context object’s broader identity and all effects of `0x1C7730` are unresolved here. Evidence: image/listing `0x20FCFE–0x20FD70`, `0x21002B–0x210059`.

A separate actor-creation branch in world update establishes a concrete `0x0800` producer. The audited boundary starts at `0x2157A8`; the dispatch selector that reaches it is not assigned an action name by this contract. Its local execution admission is world `+0xB4` zero with current actor discriminator nonzero, or current actor pointer equal to world `+0xB8`. It calls `0x03CAA0` twice with the current actor and signed argument `-1`: the old signed 32-bit action clock must be no greater than the first returned integer, and the 32-bit sum of that clock and the already prepared integer step must be strictly greater than the second returned integer. Equality at the second boundary does not create an actor. The conversion that prepared that step and the threshold helper’s internals are outside this contract.

The branch counts nonnull world-map actors whose full 64-bit link at `+0x198` equals the current actor’s full identifier at `+0x08`. A signed count greater than `2` rejects creation; `2` passes. No discriminator filter is added to that count by the audited scan. Normal creation constructs a new creature and sets its discriminator to `3` if the current actor discriminator is zero, otherwise to `1`.

The original next considers the current actor’s 32-bit candidate collection at `+0x13F8`: a nonempty collection causes a direct imported random draw and selection by unsigned remainder; an empty collection provides identifier `0x25` without that draw. This selection occurs before the subsequent `+0x13F4` choice, including when its result is discarded by a copy route. Current actor `+0x13F4` equal to `1` copies the current actor’s kind, equipment and appearance. Value `2` uses the actor resolved by current actor identifier field `+0x11D0`, falling back to the current actor when lookup yields null, and copies that selected actor’s kind, equipment and appearance. Other values use the previously selected kind and call appearance producer `0x03F7C0` with explicit zero as its final argument. Nested calls in that producer remain unclosed.

After all these alternatives, the new actor’s complete `+0x7E` word is changed at `0x215A2E–0x215A42`: `0x0200` is cleared and `0x0800` is set; all other bits survive. In particular a copied `0x1000` or `0x2000` bit is not removed by this operation. Later this branch copies the current actor’s 64-bit identifier into new actor `+0x198`, then inserts the new actor pointer into the world map, at `0x215B88–0x215BA6`. This establishes an actual stored link relation, without establishing a universal ownership label for it. Allocation failures, exceptional callbacks and complete created-actor lifetime are unclosed. Evidence: image/listing `0x2157A8–0x215A42`, `0x215B88–0x215BA6`.

The direct draw import used at these identified sites is `rand` from `MSVCR110.dll`, at IAT RVA `0x2FC468`; the seed import used at `0x20FD38` is `srand` from that DLL, at IAT RVA `0x2FC4B4`. These identities come from `binary/Cube.exe`’s PE import descriptors and call operands. No random algorithm, seed lifetime or cross-thread equivalence follows from those API names.

## The low-byte `0x20` producer boundary

The general data-word flag setter at `0x02F160` can change the scoped low-byte bit when supplied the appropriate mask. Its data receiver is embedded data, not a creature base. A nonzero low byte of its Boolean argument adds the supplied 16-bit mask to embedded-data `+0x114`; zero removes precisely those mask bits. Other bits survive. This helper has no validation of a semantic flag category, random call or event publication.

The directly identified constant-mask call sites in the client instruction listing use `0x0001`, `0x0004`, `0x0008`, `0x0010`, `0x0040`, `0x0080`, `0x0200` or `0x0400`. This audit did not establish a direct call that supplies `0x0020`. Several direct word modifications outside that helper also affect other bits while retaining `0x20`; examples include masks `0xFFEF` at `0x07E8EC` and `0x2194BA`, `0xFFFB` at `0x0A6E41`, and `0xFDFF` at `0x21F034`. These examples do not establish a complete indirect-writer inventory.

Therefore the verified ways for a set `0x20` bit to reach an actor include whole-word/data copies and the raw state-transfer fields below. Its first native behavioral setter, any interface toggle, any authority requirement for setting it, and any unobserved indirect setter remain unresolved. It would be unsupported to promote this bit to a named faction or permission based only on its relationship-reader use. Evidence: image/listing `0x02F160–0x02F185`, identified direct calls to `0x02F160`, and the cited word modifications; original `decompiled/client/functions/0042f160.c`.

## State transfer and connection replacement

The selected creature-data serialization at `0x0CDAA0` has separate fields for the appearance group at embedded-data `+0x68` and flags word at embedded-data `+0x114`. In its 64-bit presence header these are zero-based field positions `13` and `14`, respectively. The appearance group occupies `0xAC` bytes; when included, the `+0x7E` creature flags are carried within that group. Its selection helper `0x0CB930` includes the group when forced or when its appearance comparison differs. The comparison at `0x0CC840` explicitly compares the entire appearance `+0x06` word, so changing any of those 16 flag bits can require the group. This is not a claim that padding participates in equality. The flags-word selector `0x0CB670` includes two bytes when forced or when the full word differs. It does not isolate or normalize `0x20`. Appearance precedes the separate flags word in the selected-field order.

The matching memory reader `0x0CCFA0` and socket reader `0x0CD3E0` use those same two fields. An absent field leaves existing storage unchanged; it does not clear flags. For a present, complete field, the memory reader copies all `0xAC` appearance bytes or the two flags bytes without testing any protection/classification mask. On ordinary valid buffer indices, an undersized field moves the memory cursor to the buffer end and does not perform that field’s copy. Earlier successful field copies are not rolled back. The socket helpers receive directly into the destination group or word. A short/failing receive can therefore leave a partially overwritten destination; no transactional field rollback is established. Whole-message admission, staging and publication locks are not characterized by these field helpers alone. Evidence: original files `004cdaa0.c`, `004cb930.c`, `004cb670.c`, `004cc840.c`, `004ccfa0.c`, `004cd3e0.c`, `004cc1c0.c`, `004cbed0.c`, `004cc240.c`, `004cbf40.c`, confirmed with their corresponding native instruction ranges.

The connection-start path at `0x06FC50` provides a useful limit on treating every received block as adopted actor state. It receives a separate 64-bit identifier and a `0x1168`-byte data block into temporary data. In the successful nonnegative-identifier route, it also copy-constructs a temporary from the previous current creature’s embedded data at `0x070211–0x070221`, before deleting the previous world-map actors. It resolves or creates the replacement current creature, then assigns that saved old data into the replacement creature’s `+0x10` at `0x070333–0x070343`. That assignment preserves the old appearance flags and separate flags word as described above. The mere receipt of the earlier raw block is consequently insufficient evidence that its protection flags become the replacement current creature’s flags in this path. This document does not extend that observation to every incoming snapshot route. Evidence: original `0046fc50.c`; image/listing `0x0701A1–0x070343`.

## World mode and designated-pointer lifetime

World construction at `0x18EB00` stores its supplied argument’s low byte into world `+0xB4` and initializes world `+0xB8` to a null four-byte pointer. It does not normalize the mode byte to Boolean. The client constructor `0x059C40` supplies zero for this argument when constructing its embedded world at `0x059F57`. After inserting its initial current creature into the world map, the client constructor calls pointer setter `0x087E90` with client `+0x8006D0`. That setter simply assigns the supplied four-byte value to world `+0xB8`; it does not reject null, validate membership or derive an identifier. Thus normal initial client setup has mode zero and a designated creature pointer, rather than requiring the mode to be nonzero for designation. Evidence: image/listing `0x18EC09–0x18EC12`, `0x059F31–0x059F57`, `0x062219–0x06222C`, `0x087E90–0x087E9D`.

A nonempty-address route through `0x06FC50` stores byte `1` into client `+0x398` at `0x06FCA7`, before socket creation, name/address resolution, connection and subsequent handshake work. Therefore nonzero mode is not, by itself, proof of an already established connection or a successful handshake. The audited failure exits include direct mode-zero stores at `0x06FE47`, `0x06FEE9`, `0x07018C`, `0x070745` and `0x070931`, following their respective cleanup work. Not every exceptional or early-receive exit has been proved to perform the same cleanup; no exhaustive failure-state guarantee is made.

In the successful replacement route, `0x070408` writes the then-current creature pointer from client `+0x8006D0` into client `+0x39C`, updating world `+0xB8` after the replacement’s data assignment. This publication changes pointer identity; it does not compare a faction or designate every actor whose stored link happens to match that creature.

The sender-worker tail at `0x06A869` resets client `+0x398` to zero on its observed termination route after closing/clearing the socket. Explicit disconnect `0x0719F0`, admitted when client byte `+0x800585` is nonzero, also clears that running byte. With a nonzero socket it closes/clears the socket and resets the mode at `0x071A5B`; after waiting for nonnull worker handles, its guarded world portion resets the mode again at `0x071AAD`. No direct null assignment to client `+0x39C` appears in that scoped disconnect body. This absence is not a promise about arbitrary nested callbacks, destruction, or pointer validity during every exceptional transition. Evidence: original `00469c10.c`, `0046fc50.c`, `004719f0.c`; image/listing at the cited sites.

## Remaining bounds

This audit proves concrete producers for every constituent of the `0x1A00` exclusion mask, a concrete pre-creation `0x2000` producer, default/reset/copy behavior, selected-field preservation, and client mode/designation transitions. It does not prove that these are the only writers. The full generator admission, appearance producer `0x03F7C0`, descriptor modifier `0x1C7730`, all reset callers, indirect aliases and all snapshot-publication paths remain dependencies. The first gameplay-specific producer of `+0x124` bit `0x20` remains open.

The raw discriminator and kind values used by the readers do not establish universal faction labels. Null and stale pointers remain caller obligations where no internal guard is shown. Malformed streams, impossible/corrupt container lengths, allocation failures, floating-point exceptional values, concurrent visibility outside the cited operations, complete fatal processing and full actor/descriptor destruction are outside the closed relations. No behavior of a separate server executable is inferred from client zero/nonzero branches. All earlier held artifacts remain outside this artifact’s evidence and unchanged.
