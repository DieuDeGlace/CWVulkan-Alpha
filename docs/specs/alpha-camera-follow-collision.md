# Alpha client camera follow and collision caller

Status: FINAL / STABLE / HELD. This is an independent original-source behavioral contract for the input callbacks, smoothing, and late follow/collision caller that supply the main client's subsequent view construction. The complete late caller is bounded at RVA 0x09C2E6–0x09CBE3. Its geometry-query results remain explicit inputs where the reached query implementation was not fully audited. This does not claim complete camera, device, user-interface, terrain-loading, or collision coverage.

## Image and evidence

## Objects, retained state, and numerical domain

`C` denotes the client receiver of RVA 0x088EE0. `W` is its embedded world at C+0x2E4. `A0` denotes the creature pointer read from C+0x8006D0 in the late caller; its position is the three signed 64-bit members beginning at A0+0x10. This caller dereferences that pointer without a local null admission test. This contract does not derive the pointer's upstream selection, reset, or lifetime rules. `M` denotes the separate object pointer at C+0x800710 used by the mouse callback.

## Placement in input and frame processing

The client vtable at VA 0x006FFDC8 contains mouse callback RVA 0x07EA00 at byte slot +0x18, wheel callback 0x07EF40 at +0x24, update 0x088EE0 at +0x28, and renderer 0x0AC260 at +0x2C. Original outer routine 0x0C8AE0 processes window messages before its optional sampled-mouse call through +0x18, and makes that sampled-mouse call before invoking 0x0C85F0. The latter enters its update/render sequence only when the two pointers at VA 0x0076B1B4 and VA 0x0076B1C8 are nonnull. It calls `timeGetTime`, initializes the previous-time DWORD at VA 0x0076B234 to the current result when that stored DWORD is zero, and passes the 32-bit current-minus-previous difference to the update. It performs resize reconciliation after the update, stores the sampled current time to that previous-time DWORD, then invokes the render callback. This previous-time storage differs from the mouse callback's storage below. A dispatched wheel message can run in the earlier message-processing phase. These are caller relations, not an exhaustive inventory of every callback invocation. Sources: image vtable; `S/004c8ae0.c`, `S/004c85f0.c`, `S/004c83f0.c`.

Within update 0x088EE0, the world calls at 0x08CF2E and 0x08CF49 precede current-angle/distance/scale smoothing at 0x0965A2–0x09662C. The later action/input region around 0x09B58E–0x09C02F also precedes the late anchor/eye route beginning at 0x09C2E6. On paths that execute both world calls and this route, the follow/collision work uses state after those world calls. It is not inserted between the world-duration pieces. This audit does not close all earlier frame admission, pause, device, or action branches; neither does it assert that the world calls run on every update. The smoothing count N is the signed 32-bit update argument retained at frame entry, rather than each world piece's duration. Sources: `F` at 0x088F31–0x088F34, 0x08CEF4–0x08CF49, 0x0965A2–0x09662C, 0x09C2E6 onward.

## Mouse admission and angle targets

RVA 0x07EA00 accepts two binary32 values, called u and v here. Its initial call to 0x263B50 is a no-op in this image: it must not be credited with publishing M's coordinate history. Before angle admission, bit 0 of the shared full 32-bit member at VA 0x0076B094 controls one-time initialization of the previous-time DWORD at VA 0x0076B090 with imported `WINMM.dll!timeGetTime`; the initialization flag is set by a full 32-bit write. There is then another time query, a 32-bit current-minus-previous subtraction, and publication of the new previous time. That difference is consumed as signed by the weight helper described below, with binary32 coefficient bits 0x3C23D70A. A shared float at VA 0x0076B04C is blended toward M+0xD8; its new-minus-old value feeds earlier widget-layout branches. The timer and shared float are not per-client members. Sources: `S/0047ea00.c`, `S/00663b50.c`, `A` at 0x07EA00 onward; original PE import table.

A widget property in this contract means the full 32-bit selected value obtained from the widget's pointed object at +0x3C, its full 32-bit index at +0x68, and its array pointer at +0x94, with four-byte array entries; zero versus nonzero is the tested relation. RVA 0x07FA10 supplies that test. It does not admit a null widget itself. Before the general mouse predicate, callback 0x07EA00 gives precedence to nonzero property of C+0x800888, then C+0x80088C, each requiring bit 0 of M's byte +0xF4. Either admitted branch performs separate widget/layout work and returns before the main angle-target writes. The identities and transitive effects of those layouts are not closed here. Sources: `S/0047fa10.c`, `S/0047ea00.c`; `A` at 0x07EA8F–0x07ECC3.

The subsequent client virtual predicate at byte slot +4 is RVA 0x07F1D0. Its low result byte is zero only when every condition in the following table holds. A nonzero condition fails immediately according to the original short-circuit order; the table groups the tested storage without assigning menu or gameplay names. Upper return bytes do not define a Boolean value. Source: `S/0047f1d0.c`, `A` at 0x07F1D0–0x07F3AA.

For predicate result zero, callback 0x07EA00 calls 0x250AE0 on M and ignores its result for angle admission. It rounds signed C+0x18C to binary32, multiplies by binary32 bits 0x3BA3D70A, then multiplies that product by v for the first-angle delta. C+0x194 equal zero adds this delta to target +0x1B0; any nonzero value subtracts it. After storing, a result strictly above 180 is replaced by binary32 180, and a result strictly below zero by positive zero. Equal 0, negative zero, and equal 180 are not replaced by these tests. Target +0x1B8 decreases by the corresponding sensitivity product multiplied by u. There is no local yaw wrap/clamp and no write to target +0x1B4. These are separate binary32 operations, with the sensitivity multiplication before the input multiplication. Source: `A` at 0x07EE7F–0x07EF2C.

For nonzero predicate result, the callback first supplies u,v to M through 0x252C10, then calls 0x250AE0. Only a full 32-bit zero return from the latter, together with nonzero client byte +4, admits writes to the same two main angle targets. The v substitute is the binary32 difference M+0xD8 minus M+0xE0; the u substitute is M+0xD4 minus M+0xDC. Each difference is multiplied by the separately rounded sensitivity-times-0x3BA3D70A product. Direction choice and pitch clamping are as above. The M coordinate producers and the transitive callback effects of 0x252C10 remain dependencies. Helper 0x250AE0 returns the full 32-bit value stored at M+0xC8 when nonzero, otherwise the return of 0x236560 called on the pointer stored at M+0xB4 with coordinates at M+0xD4 and an argument zero; the latter relation is not closed as a focus or ownership predicate. Sources: `A` at 0x07ECDD–0x07EDE4, `S/00650ae0.c`.

Still within the nonzero-predicate branch, a separate admission using client byte +0xA and nonzero widget property C+0x8008DC reaches the different pointed object C+0x8008F4. It adds one half of the horizontal M difference to that object's float +0x16C and subtracts one half of the vertical difference from its float +0x164. Those are not writes to the main client's angle members. No health, class, creature-action, or elapsed-duration gate is inserted into the established main-angle arithmetic by this callback. This statement does not remove the widget/pointer gates or establish their upstream producers. Source: `A` at 0x07EDE4–0x07EE7C.

## Wheel and retained targets

The window procedure 0x0C83F0 handles message value 0x020A by reading the signed high 16 bits of its parameter and reducing negative, positive, or zero to callback argument −1, +1, or 0 respectively. Magnitude beyond its sign is lost on that route. The wheel callback itself, 0x07EF40, accepts a full signed 32-bit value, so its direct-call relation is wider than the message route. Source: `S/004c83f0.c`, `S/0047ef40.c`.

With client byte +0x8006E4 zero, the callback doubles its full 32-bit argument with 32-bit wrap, interprets the doubled value as signed, converts it to binary32, and subtracts that value from target distance +0x1C0. It stores the result, replaces a strictly negative result by positive zero, then replaces a result strictly above 14 by 14. Equality at either bound is retained. It does not first clamp the incoming argument and does not directly change D. With the mode byte nonzero, a negative argument multiplies target scale +0x1C8 by binary32 bits 0x3F666666; a nonnegative argument, including zero, divides by that same value. The stored result is bounded first above by 10 and then below by binary32 bits 0x3C23D70A, both with strict comparisons. Thus zero input still takes the division path in this second branch and can change the target scale. The coefficient is approximately 0.9, not an exact decimal rational. Sources: `A` at 0x07EF40–0x07EFF6; image constants at VA 0x006FD31C, 0x006FCE34, 0x00745E74 and 0x006FCDA0.

## Per-update smoothing

The common weight helper 0x0AC150 accepts signed N and a binary32 coefficient. Nonpositive N produces zero weight. For positive N it obtains an N-fold approach-to-one weight beginning at zero, using the coefficient widened to binary64. Within each approach, subtraction of the current weight from binary64 one precedes multiplication by the coefficient and addition of the old weight; those are separate binary64 operations. Only the final result is narrowed to binary32. This precision relation does not authorize substituting a reassociated power formula. The binary32 vector helper 0x057460 and scalar helper 0x0ABA20 each use binary32 one-minus-weight, separate old-times-complement and target-times-weight products, then their binary32 sum. They do not choose a shortest angular arc. Sources: `S/004ac150.c`, `S/00457460.c`, `S/004aba20.c`; `A` at their respective RVAs.

At 0x0965A2 the signed smoothing option C+0x190 is rounded to binary32 and multiplied by coefficient bits 0x3C23D70A. This becomes the exponent supplied with base bits 0x3BA3D70A to helper 0x011D10. That helper widens both supplied floats to binary64, calls the imported power routine, and narrows its result to binary32. Its result is the angle interpolation coefficient, not the elapsed count. The update first blends all three current angles toward the three targets using N and this coefficient, then D toward C+0x1C0 using N and coefficient bits 0x3B83126F, then scale C+0x1C4 toward C+0x1C8 with the same N and coefficient. The latter coefficient is approximately 0.004. There is no post-blend angle wrap or distance clamp at these three call sites. Source: `F` at 0x0965A2–0x09662C; `S/00411d10.c`.

## Late follow anchor

The late route starts at 0x09C2E6 by initializing a temporary rotation matrix to identity. It applies helpers 0x024610, 0x0244F0, and 0x0243D0 using current angle components 2, 1, and 0 respectively, in that order. These helpers multiply their binary32 degree input by binary32 factor bits 0x3C8EFA35, widen the resulting angle to binary64, call cosine before sine, and narrow the results to binary32 before matrix arithmetic. The later backward-offset direction B is the output of 0x088E50 for this matrix and binary32 input vector (0,0,1). That helper forms each output component from three binary32 products, the first two added before the third. It adds no translation and the caller does not normalize B. The matrix helper signs and full matrix state remain identified original helper dependencies rather than an alternate reassociated Euler formula in this contract. Sources: `F` at 0x09C2E6–0x09C362 and 0x09C787–0x09C7BD; `S/004243d0.c`, `S/004244f0.c`, `S/00424610.c`, `S/00488e50.c`.

Before choosing the anchor route, the update subtracts A0's fixed position from retained F0, converts that difference to a binary32 vector, and obtains its squared length through 0x024860. The helper separately squares three binary32 components and adds the first two before the third; no square root participates in this comparison. A value strictly above binary32 2500 replaces the entire fixed anchor with A0's position. Equality does not snap. This check precedes the widget decisions and ordinary following, so an admitted snap does not skip those later operations. Source: `F` at 0x09C367–0x09C3C4; `S/00424860.c`.

The properties of C+0x800874, +0x800888, +0x800894, and +0x80088C are queried in that order, stopping on the first nonzero property. Any such result selects the alternative anchor described below. If all are zero, a local binary32 value initially zero is blended toward one with N and coefficient bits 0x3CCCCCCD, approximately 0.025. Call its resulting weight r. The first anchor component is updated, then the second: for each, A0's raw component minus its corresponding retained anchor component is multiplied by the quantized fixed representation of r, signed-divided by 65,536 toward zero, and added back to that retained raw anchor component. The quantization is binary32 r-times-65,536 followed by signed 64-bit truncation. The multiplication retains its low 64 bits before signed division. This is a fixed quantized-delta relation, not a float blend of two absolute positions. Sources: `F` at 0x09C3C4–0x09C4FA; `S/00468ca0.c`; raw arithmetic helpers 0x012200, 0x02C9B0, 0x28DA90, 0x28D9E0 in `A`.

Only after those two components are stored does the ordinary route select its vertical target. It queries properties C+0x800880, then C+0x800890. Either nonzero property uses A0's position component 2 minus the converted binary32 value at A0+0x1180. If both properties are zero, the following table applies to the action byte at A0+0x68. Each binary32 quantity below is separately converted to fixed before the raw additions/subtraction; the half-component product is first rounded to binary32. The order is position minus converted +0x1180, then the converted half-component, then the converted constant when present. No meaning is assigned to the raw binary32 vector at A0+0x80. Source: `F` at 0x09C4FF–0x09C6BB; helpers 0x012220, 0x0122E0.

| Action byte | Ordinary-route vertical target additions after subtracting A0+0x1180 |
| --- | --- |
| 0x53 or 0x54 | One half of binary32 component 0 of the vector beginning at A0+0x80; no final constant. |
| 0x6A or 0x6B | One half of that vector's component 2, then binary32 1.5. |
| Every other byte | One half of component 2, then binary32 0.5. |

The selected raw vertical target and retained F0 component 2 are blended by 0x0573D0 using N and coefficient bits 0x3BA3D70A, approximately 0.005. This helper rounds the old signed 64-bit raw value to binary32, multiplies it by binary32 one-minus-weight, then truncates that product to signed 64 bits. It separately rounds the target raw value to binary32, multiplies by the binary32 weight, and truncates that product to signed 64 bits. The two raw integer results are added with 64-bit wrap. There is no division by 65,536 in this blend. Even zero weight does not guarantee retention of all low raw-coordinate bits at large magnitudes, because the old raw integer passes through binary32. Sources: `F` at 0x09C619; `A` at 0x0573D0–0x057455.

For the alternative route, helper 0x087FE0 on W returns the address W+0x8000F0, a three-binary32 vector. Its converted fixed value replaces all three components of F0. Anchor components 0 and 1 are then signed-divided by 65,536 toward zero through 0x02F570, with each quotient's low 32 bits used for column lookup 0x0347A0 on W and optional-context argument zero. There is no negative-coordinate pre-adjustment on this particular conversion. The lookup rejects either signed coordinate below zero or at least 0x01000000; for admitted coordinates it requests a chunk using the coordinates divided by 256 and, if nonnull, chooses its 32-byte column from the low eight coordinate bits. Chunk acquisition at 0x034D10 remains an unclosed dependency. If the column is nonnull, getter 0x0348B0 reads its full 32-bit +0x10 and getter 0x034B70 reads its full 32-bit +0x1C, in that order; their 32-bit wrapped sum, interpreted as signed, is converted to fixed and replaces anchor component 2. A null column leaves that component as converted from W+0x8000F0. In either case fixed integer 50 is then added to the vertical component. This route does not perform the ordinary x/y or vertical smoothing. The producer and semantic identity of W+0x8000F0 are not established here. Sources: `F` at 0x09C6C0–0x09C76A; `S/00487fe0.c`, `S/0042f570.c`, `S/004347a0.c`, `S/004348b0.c`, `S/00434b70.c`.

## Eight corner queries and distance retention

After either anchor route, the update copies F0 to E and subtracts the fixed conversion of B multiplied componentwise by binary32 D. Multiplication by D precedes the float-to-fixed conversion of each component. This first eye E is the origin for all eight corner samples, even when a preceding sample has reduced the local allowed distance. The local allowed distance begins as the same D. Source: `F` at 0x09C76F–0x09C81F; scalar-vector helper 0x051510 and fixed helpers 0x02C460, 0x02C9D0.

The exact sample offsets, in coordinate units and in visitation order, are (−0.25,−0.25,−0.25), (−0.25,−0.25,+0.25), (−0.25,+0.25,−0.25), (−0.25,+0.25,+0.25), (+0.25,−0.25,−0.25), (+0.25,−0.25,+0.25), (+0.25,+0.25,−0.25), (+0.25,+0.25,+0.25). Each component is exactly raw −16,384 or +16,384. The native construction converts binary64 half-offset components to fixed and applies a further fixed multiplier of 0.5; omitting that second factor would produce the wrong sample extent. Sample coordinate Q is the initial E plus the corresponding raw offset. Sources: `F` at 0x09C823–0x09C932; `S/00459c00.c`, `S/0043b610.c`, `S/0042c6e0.c`; helper 0x02C900.

Each Q is first submitted to 0x02F860 on W with optional-context argument zero. The resulting voxel record is classified through 0x03B480: only its byte +3 low five bits matter to this predicate, which is true exactly when that five-bit value is neither 0 nor 2. If false, the sample makes no ray call. If true, the update calls 0x1A35D0 with W, fixed start Q, binary32 direction B, maximum distance D, and two option arguments both equal to 1. The caller narrows the query's returned value to binary32, subtracts it from D in binary32, and replaces the local allowed distance only when the previous allowed distance is strictly greater than that candidate. Equal candidates retain the earlier value. The original D is still the maximum supplied to later samples; the current allowed distance is not substituted into those calls. No local nonnegative-return admission or post-subtraction clamp is inserted in this sample route. Sources: `F` at 0x09C937–0x09C9E0; `S/0043b480.c`.

All eight samples progress through their voxel tests; there is no caller early exit merely because a previous sample was classified or shortened the distance to zero. Once the samples finish, the caller stores the allowed distance back to D at C+0x1BC. It recomputes E from F0 minus the fixed conversion of B times this new D, and copies D's exact four bytes to C+0x1CC. It does not change the target distance at C+0x1C0. Thus a shortened current distance can begin approaching the retained target again at the next update's earlier scalar smoothing, and can be shortened again at that update's later query phase. This is a relation of the two reached phases, not a complete inventory of every writer to the distance members. Sources: `F` at 0x09C9E0–0x09CA7A, 0x0965EC–0x096609.

Because the ray implementation is not fully closed here, a sample return must not be assumed to lie within [0,D] or to encode a particular no-hit sentinel. For ordinary finite returns, a negative return does not by itself reduce the initially allowed D; D-minus-return can round back to D. A return greater than D can produce a negative candidate that this caller does not clamp. The contract preserves that caller arithmetic without claiming those return values are ordinarily produced by 0x1A35D0.

## Final center correction and view handoff

The caller next submits the recomputed center E to the same voxel lookup and classification. A false classification retains E. A true classification computes E minus A0's fixed position, converts that raw difference to binary32, and checks its binary32 squared length strictly above zero. Zero, negative, or unordered squared length does not reach the next ray call. For an admitted value, helper 0x0240F0 normalizes the difference. It forms the three binary32 squares and first-two-then-third sum, widens this rounded sum to binary64 for imported square root, narrows the root to binary32, forms binary32 one divided by that root, and multiplies each original component by the reciprocal in binary32. It has no independent zero guard. Source: `F` at 0x09CA80–0x09CB4B; `S/004240f0.c`, `S/00424860.c`.

This final ray call starts at A0's fixed position, uses that normalized E-minus-position direction, maximum distance binary32 100, and option arguments 1 and 1. Its returned value is narrowed to binary32. Negative or unordered results retain the preceding E; zero is admitted. For an admitted result, E becomes A0's fixed position plus the fixed conversion of the normalized direction multiplied by that result. F0, target distance, D, and its C+0x1CC copy are not rewritten by this final correction. Consequently D is not necessarily the distance of the final E from A0 or F0. At 0x09CBE3 the update proceeds into construction using the client matrix at +0x1EC; this contract stops at that handoff and does not restate later shake/view-matrix arithmetic. Source: `F` at 0x09CB50–0x09CBE3.

## Voxel selection boundary and missing records

The direct fixed-coordinate voxel adapter 0x02F860 has a different negative rule from the alternative-anchor column conversion. For each negative signed raw coordinate it first subtracts raw 65,536, then signed-divides by 65,536 toward zero and retains the quotient's low 32 bits. Nonnegative coordinates are divided without that subtraction. Thus an exactly negative integral coordinate is mapped one integer below its plain signed quotient; replacing the adapter with a conventional floor changes those equality cases. Its reached integer lookup is 0x02F7E0. Sources: `S/0042f860.c`, `A` at 0x02F860 onward.

Helper 0x02F7E0 calls column lookup 0x0347A0 with the integer coordinates and supplied optional context. A null column returns the static record at VA 0x0076AFC4. A signed z below the column's full 32-bit +0x10 also returns that record. A z at or beyond the 32-bit sum of column +0x10 and +0x1C returns the record at VA 0x0076AFBC when z is at most zero, otherwise VA 0x0076AFC0. For an in-range z it obtains a record through 0x02F730 using z minus the column base. If that record's low-five-bit classification is zero, z is at most zero, and byte +3 bit 0x40 is clear, it substitutes VA 0x0076AFBC; otherwise it returns the record. Record access allocation/lifetime and the initial contents of all three static records remain unclosed. In particular, missing or unloaded columns must not be declared transparent or blocking from the returned address alone. Sources: `S/0042f7e0.c`, `S/004347a0.c`; `A` at 0x02F7E0–0x02F856 and 0x03B480.

## Imports, side effects, and limits

The original PE import table identifies `MSVCR110.dll!_libm_sse2_pow_precise`, `MSVCR110.dll!_libm_sse2_sqrt_precise`, `MSVCR110.dll!_libm_sse2_cos_precise`, and `MSVCR110.dll!_libm_sse2_sin_precise`. Their imported scalar results, runtime math accuracy, x87/SSE control state, exceptional input behavior, and transcendental implementation remain dependencies. The contract's explicit binary32 stores and conversion boundaries must not be erased by assuming exact real arithmetic or combining operations. Timer API identity is `WINMM.dll!timeGetTime`; wrap and signed treatment at the mouse call site are stated above, without a wider timer-lifetime guarantee.

No direct random-number or random-seed call occurs in the audited mouse/wheel callbacks, interpolation helpers, raw conversion helpers, or late follow/collision caller range. That does not establish absence in unclosed widget dispatch, device callbacks, chunk acquisition, ray geometry, or other frame work. No random-draw count for those nested dependencies is asserted.

This contract closes the late caller's state writes, corner visitation, query arguments, comparison boundaries, and retained-target recovery relation. It leaves the complete 0x1A35D0 geometry/material/traversal behavior, query return bounds and side effects, unloaded-data record initialization, complete 0x034D10 acquisition semantics, upstream M coordinate publication, option/UI producers, C+0x8006D0 selection and lifetime, initial/reset camera values, and W+0x8000F0 production unresolved. Earlier frame focus-selection work, including other calls to 0x1A35D0, is not equated with these late correction calls. There is no claim that these are the sole writers to every named member or that the caller is safe under null, corrupt, overflowing, or concurrent unsupported object state. Earlier HELD artifacts remain unchanged.
