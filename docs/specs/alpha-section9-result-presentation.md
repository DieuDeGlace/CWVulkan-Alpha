# Section 9 addressed item results in Cube World Alpha

**Source author status — FINAL / STABLE / HELD**

## Evidence and packet identity

The original 32-bit client Cube.exe is 3,885,568 bytes, SHA-256 84A7A132A84D4282338E7EA45A1940D32066D64E39CBAFED8F2418D5A6DC30BF. The dedicated Server.exe is 1,718,784 bytes, SHA-256 1FFBCBCE251E1506A63C9CE18AB0009D5553FCBB9E6202BE2BC3A7D870D34FB1. Both have preferred image base 0x400000. Addresses below are RVAs in the named image. The evidence is the owner's original binaries, their disassembly and the corresponding native function listings.

Section 9 means the ninth section, counting from one, in the dedicated server's type-4 world update. The server writes a 32-bit count followed by that many 0x120-byte records in list order. The first eight bytes are the addressed creature ID. The 0x118-byte item starts at record offset 8. The client reader uses the same sizes and appends a copy of each complete ordinary record to its list. This describes a well-formed update. Server RVAs 0x024D22–0x024FAC and 0x021BF0. Client RVAs 0x06CE8C, 0x058500–0x058631 and 0x051CC0.

## Dedicated audience

During normal dedicated update distribution, every non-null entry of the connection-pointer array gets the entire addressed-item list appended to its pending section. The source list is at update offset 0x40. The destination list is at connection offset 0x58. The append traverses the list in order. This copy has no test of the record's creature ID, receiving connection's creature ID, position, item category or distance. Other sections in the same connection loop do perform distance checks. Server RVAs 0x14A0AA–0x14A0D0, 0x02730E–0x02734B, 0x0273B1–0x027682, 0x02773D–0x02776B, 0x021090 and 0x027F75–0x027F93.

Each connection's sender takes its pending update, then serializes the section into its own type-4 packet and sends the encoded length and payload on that connection's socket. The addressed ID survives transmission to the other peers. Distribution into the pending queue establishes the intended audience. It cannot guarantee delivery, frame timing or that the receiving client has the addressed creature. Server RVAs 0x024911, 0x023400, 0x024D22, 0x024F52 and 0x024FDD–0x025011.

## Client processing and interface gates

In client update RVA 0x088EE0, a first pass traverses the incoming list at client offset 0x800670. Each record looks up its ID in the primary world at client offset 0x2E4. Only a successfully resolved actor identical to the local actor pointer at client offset 0x8006D0, with item category other than 25, enters the inventory credit routine. The inventory starts at actor offset 0x11DC. The supplied value minus one selects the automatic inventory group. The credit routine can update a currency count or an item stack. The client then recalculates the inventory widget's scroll range and scroll control, in that order, through the widget at client offset 0x800954. This finishes for all incoming records before their late presentation. Client RVAs 0x08F719–0x08F801, 0x02F000, 0x06EBE0, 0x0C6350 and 0x0C64C0.

The client appends the incoming range in order to the frame's presentation list. For each entry in that list, it resolves the eight-byte ID again using the primary world's actor table. A failed lookup immediately advances to the next record. A resolved local actor triggers the crafting-list refresh before any category-specific effect. That refresh groups and sorts recipe entries, updates six groups numbered 0 through 5, then calls the same two scroll-widget routines on the separate widget at client offset 0x800958. The resolved foreign actor bypasses this refresh. These are per-record calls. The scroll-range routine requires a bound collection, and scroll-control placement also checks the child, range and stored per-group offsets. Client RVAs 0x08F801–0x08F8D5, 0x057C20, 0x054740, 0x02F000–0x02F027, 0x0A14C0–0x0A1885, 0x0A19D0, 0x0C6350 and 0x0C64C0.

## Generic receipt text

Every resolved result except category 25 enters the same receipt formatter. The local actor gets the white prefix “You receive ”. A foreign actor gets its own null-terminated name from actor offset 0x1168 followed by the white text “ receives ”. The client widens that name byte by byte. An empty name contributes no characters before the suffix. Actor resolution and pointer equality govern these choices. There is no additional distance, chat-focus or inventory-open check at this dispatch. Client RVAs 0x08FA81–0x08FA8D, 0x080FB0–0x08114F, 0x2089C0 and 0x024DA0.

The body and closing punctuation are separate submissions to the same text widget at client offset 0x800A14. Category 12 prints the signed short at item offset 0x10 in decimal, a space and the singular localized material name selected by item byte 0x0D, in white. For categories 0, 13, 20, 21, 23, 24 and category 11 except subtype 14, the ordinary formatter prints that signed decimal quantity, the literal “ X ” and the item's display name. Other ordinary categories, including category 11 subtype 14, print the display name followed by “ +” and the integer returned by the native power calculation. The closing period and newline are white. Category 25 is also a quantity category inside the shared formatter, but the section-9 dispatch sends it down its own branch. Client RVAs 0x0811F6–0x08144D, 0x0C76A0 and 0x080E00.

The formatter gets the item name from the primary world's display-name routine. Item type, subtype and localization participate. For example, the stock registration for category 13 subtype 0 supplies the key PlatinumCoin. The receipt path does not use the recipient name as an item label. Category 13's body has normalized RGB (0.5, 0.1, 1), which becomes (127, 25, 255) in the text widget. Category 21 uses gray (0.5, 0.5, 0.5). For remaining ordinary non-currency cases, quality byte 0x0C selects white, green, blue-violet, purple or yellow for values 0 through 4 respectively, and red otherwise. The text helper multiplies normalized channels by 255 and truncates. The generic formatter issues no sound request. Client RVAs 0x081328–0x0813D9, 0x0C7D20, 0x03AB30, 0x198A50, 0x19FBF0 and 0x1905E8–0x190608.

## Platinum and mana cubes

Category 13 has two distinct local credits. In the first pass the inventory credits the signed quantity to the platinum counter at inventory offset 0x12C. In the late pass the client compares both words of the addressed ID with the local actor's ID at actor offsets 8 and 0x0C. On equality it adds ten times the signed 16-bit quantity to experience at actor offset 0x194, then processes level thresholds. It proceeds to the generic receipt for either local or foreign recipients. A resolved foreign category-13 result therefore displays the named receipt without giving the observing actor the platinum or experience. Client RVAs 0x06EBE0, 0x08F78A–0x08F7C3, 0x08F8D5–0x08F91C, 0x047B00 and 0x08FA81–0x08FA8D.

Category 25 uses a different gate. Once the addressed actor resolves, the branch increments the observing client's local actor counter at 0x1164 by one, writes state byte 0x6D at actor offset 0x68 and clears the four-byte field at 0x6C. Even a resolved foreign address takes this path. Item quantity has no effect on the increment. The client submits “You receive a mana cube.” followed by a newline in RGB (100, 150, 255), then requests sound ID 30, missioncomplete.wav. The supplied position is the client's own reference position at offset 0x140 and both supplied sound factors are 1. The sound helper uses the configured effects volume. Client RVAs 0x08F91C–0x08F9C3, 0x084350, 0x084D54 and 0x085E69.

When the updated local counter is divisible by four, the client dispatches the named interface operation “manacubes” with value zero through the interface object at client offset 0x8007D8, then submits “You gain one skill point.” followed by a newline in RGB (150, 128, 255). The interface routine walks children and forwards the name to available components. The extra line and interface call occur after the ordinary mana-cube sound. Other counter values proceed directly to the next result. Client RVAs 0x08F9C3–0x08FA8D, 0x236810 and 0x264C10.

## Limits

These call paths establish submissions, local state changes and their order for the ordinary update. They do not establish the final rasterized arrangement, audible sample under all device settings, every translated item spelling, the exact visual effect of the “manacubes” interface state, or delivery after a socket failure. The initial inventory and late presentation passes have separate recipient lookups. An ID in a delivered record alone does not establish either lookup's outcome.
