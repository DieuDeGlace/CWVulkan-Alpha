# Fatal-context field producers in the Alpha client

This independent contract covers creature offsets +0x1B0, +0x1B4, +0x1B8 and +0x11C8 in the supported original `binary/Cube.exe`, SHA-256 `84a7a132a84d4282338e7ea45a1940d32066d64e39cbafed8f2418d5a6dc30bf`. All addresses below are RVAs relative to image base 0x00400000. Evidence paths are relative to the original-evidence root, `Documents/disassembled alpha cube world`. Original decompilation was used for navigation and checked against original instruction listings or the supported image. No reconstruction, replacement implementation, runtime material or earlier contract supplies evidence here.

The scope is the production and retention of these inputs. Fatal application is mentioned only to identify which stored value it consumes. The contract does not repeat the full fatal-effects procedure or establish a complete actor lifecycle.

## Field identities and initialization

For a creature C, +0x1B0 and +0x1B4 are separate signed 32-bit horizontal spatial identifiers. +0x1B8 is a signed 32-bit ordinal into one spatial object's pointer collection. The three occupy a 12-byte group. Their ordinary spawn producer supplies a spatial object's stored coordinate pair and the ordinal of the selected backing descriptor. They are not the current fixed-point position at C+0x10, +0x18 and +0x20, and the third word is not a vertical coordinate. The distinction is established by the separate copies at RVA 0x210005–0x210020 and 0x2100BA–0x2100FA. The signed bounds tests in fatal use independently establish the signed interpretation of the group. [Evidence: `decompiled/client/assembly.txt`, RVA 0x210005–0x210020, 0x2100BA–0x2100FA, 0x196B65–0x196C49; `decompiled/client/functions/00411e30.c`, RVA 0x011E30.]

C+0x11C8 is an eight-byte linked identifier, with its low 32-bit word at +0x11C8 and high word at +0x11CC. It is used as a creature-map lookup key. It is not a pointer. Producers commonly obtain it from another creature's own eight-byte identifier at +0x08/+0x0C, or from the exact key selected for a newly created creature. Those origins do not make a map entry key and the pointed creature's own identifier interchangeable in arbitrary input states. [Evidence: `decompiled/client/assembly.txt`, RVA 0x1EE9C5–0x1EEA19, 0x20DE48–0x20DE76, 0x20E7CC–0x20E830; `decompiled/client/functions/0042f000.c`, RVA 0x02F000; `decompiled/client/functions/00477d90.c`, RVA 0x077D90.]

The creature constructor at RVA 0x03B690 first copies its supplied eight-byte identifier to C+0x08/+0x0C. It initializes the state beginning at C+0x10 through RVA 0x03C100. Within that state initializer, relative offsets +0x1A0/+0x1A4 become 0xFFFFFFFF and +0x1A8 becomes zero. Thus the creature-relative defaults are +0x1B0 = −1, +0x1B4 = −1 and +0x1B8 = 0. Later in the creature constructor, the linked identifier is explicitly cleared, low word first and high word second. These are written defaults, not an assumption about allocator contents. [Evidence: `decompiled/client/functions/0043b690.c`, `0043c100.c`; `decompiled/client/assembly.txt`, RVA 0x03B6BA–0x03B6D1, 0x03B7BE–0x03B7C8, 0x03C2AB–0x03C2C5.]

The reset boundary RVA 0x046330 calls the state reset at RVA 0x0465C0 with C+0x10. That reset restores the same −1, −1, 0 group. The outer reset then explicitly clears +0x11C8/+0x11CC. It preserves the own identifier at +0x08/+0x0C in the inspected sequence. Invoking this reset on an existing creature can therefore discard its previous backing descriptor association even while the same creature object and own identifier remain. Relevant actual callers include RVA 0x04BE7F, 0x20E5EF, 0x20E839 and 0x20EADF; this is a callable reset, not an automatic promise that every actor is reset on every invocation. [Evidence: `decompiled/client/functions/00446330.c`, `004465c0.c`; `decompiled/client/assembly.txt`, RVA 0x04633A–0x04633D, 0x04639B–0x0463A5, 0x046701–0x046715 and the cited caller addresses.]

Appearance, item and collection initialization are constructor dependencies. Their internal draws and failure behavior are not closed here. None is a basis for replacing the explicit defaults above with an all-zero creature state.

## Spatial and descriptor origin of the three-word group

The spatial lookup at RVA 0x034D10 accepts two signed 32-bit coordinates. It rejects either negative value or either value at least 65536. Each coordinate is divided by 64 to select a larger table region, and its remainder modulo 64 selects a pointer within that region. Region selection uses the first coordinate as the more significant component: the region-pointer table begins at world+0xBC with 1024 entries per first-coordinate step. Within a region, the pointer table at +0x10018 has 64 entries per first-coordinate remainder step. A missing region or spatial pointer produces no object. These are spatial identifiers in this lookup's coordinate system; no inferred environment name is required. [Evidence: `decompiled/client/functions/00434d10.c`, `00434a90.c`; `decompiled/client/assembly.txt`, RVA 0x034D10–0x034D87.]

The original spatial producer at RVA 0x1E4850 accepts that same bounded coordinate pair. After constructing the spatial object through RVA 0x2240F0, it writes the first input to object+0x60 and the second to object+0x64. The values are retained as two 32-bit integers. The producer later publishes that object into the region pointer slot indexed by the two input remainders modulo 64. The matching region and publication index are visible in the original arithmetic; the object's +0x60 pair is not inferred merely because another type has the same offsets. [Evidence: `decompiled/client/assembly.txt`, RVA 0x1E4889–0x1E48BC, 0x1E4930–0x1E49D2, 0x1E6B63–0x1E6B96, 0x1EE04E–0x1EE05A; `decompiled/client/functions/006240f0.c`, RVA 0x2240F0.]

At the ordinary descriptor-based creation boundary in world routine RVA 0x20C510, a selected spatial object contributes its pointer collection beginning at +0x18. The loop starts at ordinal zero and advances in collection order. Each selected pointer denotes a backing descriptor D. D+0x48/+0x4C supplies the creature identifier: the routine checks for an existing non-null creature under that key, constructs a creature with the same eight bytes when admitted, and stores its pointer under that same key. This proves key/own-ID agreement for this creation route at publication; it is not a universal invariant for later corrupted, received or separately changed records. [Evidence: `decompiled/client/assembly.txt`, RVA 0x20FB48–0x20FC02, 0x20FFB4–0x21000C, 0x210433–0x210453.]

The new creature's current position is copied from D+0x10 as three 64-bit components. The creature's position-related group beginning at +0x1C0 also receives D+0x10. These copies occur before the fatal-context group is assigned. The fatal-context group receives, in order, the selected spatial object's +0x60 word, its +0x64 word, and the current descriptor ordinal. RVA 0x02C500 constructs the temporary three-word value, and RVA 0x011E30 copies it to C+0x1B0. There is no float conversion, coordinate division, clamp or random draw in this three-word assignment. [Evidence: `decompiled/client/assembly.txt`, RVA 0x210005–0x210020, 0x21009C–0x2100A6, 0x2100BA–0x2100FA; `decompiled/client/functions/0042c500.c`, `00411e30.c`; supported `binary/Cube.exe`, RVA 0x02C5B0–0x02C5DB.]

The surrounding creation path has further admission and descriptor-generation work, including time bounds, a stored delay/clock check, nearby-creature checks and conditional calls that can seed or consume the CRT random stream. Those do not make the three-word value a fresh measurement of the creature's position. The group records which spatial object and which descriptor were used for this creation. This audit does not close the complete production of D, every admission condition or every nested random draw. [Evidence: `decompiled/client/assembly.txt`, RVA 0x20FBC1–0x20FC61, 0x20FCFE–0x20FD4A, 0x20FFB4–0x2100FA.]

The candidate spatial objects in this invocation are collected separately around actors whose byte +0x60 is zero. For each horizontal component of their current 64-bit fixed position, the inspected route performs signed division by 65536, uses the low 32-bit result, and divides that signed 32-bit value by 256 with truncation toward zero. It queries the surrounding three-by-three integer-coordinate neighborhood and retains non-null spatial pointers. This closes a numeric connection between current position and the candidate spatial coordinate system. It does not write the selected actor's existing association group. In particular, the two-stage integer conversion, including the 32-bit boundary, must not be replaced by an inferred floating-point coordinate or assumed floor operation for negative inputs. [Evidence: `decompiled/client/assembly.txt`, RVA 0x20CA3D–0x20CAF1; `decompiled/client/functions/0042f570.c`, RVA 0x02F570.]

In fatal object work, the first two stored words are passed directly to RVA 0x034D10. One use scans that spatial object's separate contiguous record collection at +0x0C, whose records are 0x188 bytes apart, for a record with selector 5, a +0x178 word equal to C+0x1B8, and a nonzero byte at +0x30. The scan's own ordinal is a distinct value: it is that record ordinal which is supplied with the copied object record to the later output. Another use treats C+0x1B8 as an ordinal in the pointer collection at spatial object+0x18, checks it against zero and the current collection length, and addresses the selected backing descriptor. Thus a match in the contiguous selector-5 collection and an index in the descriptor pointer collection are separate identities joined by the stored integer. The producer of every selector-5 record's +0x178 association is not closed by this contract. [Evidence: `decompiled/client/assembly.txt`, RVA 0x196193–0x196219, 0x196B65–0x196C49.]

The original fatal consumers re-fetch current spatial and collection pointers. They do not prove that a retained ordinal still denotes its original descriptor after collection reordering, replacement or unloading. The last backing-descriptor access checks the spatial pointer and ordinal bounds but does not separately null-check the indexed descriptor pointer. Constructor defaults fail the negative-coordinate spatial gate. No global validity guarantee follows from the default index zero. [Evidence: `decompiled/client/functions/00434d10.c`; `decompiled/client/assembly.txt`, RVA 0x196B65–0x196C49.]

## Copies, reception and retention

The state-copy boundaries at RVAs 0x04B040 and 0x066050 copy all three words from relative state offsets +0x1A0/+0x1A4/+0x1A8. They do not derive them from the first three 64-bit position components and do not validate spatial bounds or ordinal identity. Their state bases are C+0x10 when used on creatures. The creature's linked identifier at +0x11C8 lies outside this copied state region. [Evidence: `decompiled/client/functions/0044b040.c`, `00466050.c`; `decompiled/client/assembly.txt`, RVA 0x04B2A6–0x04B2C4, 0x0662B5–0x0662D3; constructor/state base at RVA 0x03B6CB.]

The client kind-0 receive path reads an eight-byte map key and looks up the corresponding creature. If no non-null creature is found, it constructs and inserts one using that key. It copies the existing or newly initialized creature state into a temporary state, then decodes the incoming masked fields into that temporary state. The group at state+0x1A0 is one 12-byte codec field. An absent mask bit leaves the temporary group's prior value unchanged. For a newly constructed actor this prior value is −1, −1, 0; for an existing actor it is the existing group. The receive path subsequently copies the temporary state into the actor unless it is the designated actor pointer at client+0x8006D0. The copy transmits the supplied integers without reconstructing their descriptor provenance. [Evidence: supported `binary/Cube.exe`, RVA 0x06BBB0–0x06BC82, 0x06BCC3–0x06BE04; `decompiled/client/functions/004ccfa0.c`, `004cc540.c`, `0044b040.c`, `00466050.c`.]

This establishes valid-input retention and copy behavior, not a full malformed-packet contract. The buffer reader has its own short-buffer behavior, and receive scheduling, producer trust and replacement of surrounding state are outside this scope. The handshake route also calls the state-copy boundary after resolving or constructing its designated actor; it can therefore supply a group independently of ordinary descriptor spawning. Neither the state copy nor the inspected kind-0 field codec transfers C+0x11C8. A newly received actor has the constructor's zero link until some separate proven producer changes it. Existing actors do not have their link cleared merely because this state group is copied. [Evidence: `decompiled/client/functions/0046fc50.c`, RVA 0x06FC50, especially the constructor call at RVA 0x070304 and the following state copy; `decompiled/client/functions/004ccfa0.c`, `004cc540.c`; supported `binary/Cube.exe`, RVA 0x06BC52–0x06BE04.]

The audited movement, descriptor creation and state-copy boundaries provide no unconditional per-movement recomputation of +0x1B0/+0x1B4/+0x1B8. Independent position copies, including restoration of a linked actor's position at RVA 0x20F51A–0x20F52D and position initialization of a separately constructed actor at RVA 0x215A5F–0x215A66, do not copy this association group. Such constructed actors begin with constructor defaults unless a later explicit state copy or assignment changes them. This is a statement about the inspected routes, not proof that no other aliasing writer can exist. [Evidence: `decompiled/client/assembly.txt`, the cited ranges and RVA 0x2158F7–0x21595B; constructor and reset evidence above.]

## Concrete linked-identifier producers

The world uses +0x11C8 as the forward member of a relationship whose reverse identifier is stored at the linked actor's +0x198/+0x19C. The following producers establish that relationship numerically without requiring an inferred gameplay name.

* With world byte +0xB4 nonzero, world routine RVA 0x20C510 traverses the creature map. For each non-null actor whose byte +0x60 equals 5, it looks up that actor's +0x198/+0x19C. If the lookup resolves a non-null actor, it copies the kind-5 actor's own +0x08/+0x0C identifier into the resolved actor's +0x11C8/+0x11CC, low word first. There is no health test or equality check between the kind-5 actor's own identifier and its map entry key in this write sequence. It overwrites a prior forward link. Missing reverse lookups leave other links untouched in this pass. The nonzero-world-byte branch then skips the zero-byte relationship-maintenance phases described below. [Evidence: `decompiled/client/assembly.txt`, RVA 0x20DDEB–0x20DE11, 0x20DE30–0x20DE76, 0x20DE90–0x20DEB6.]

* With world byte +0xB4 zero, a later pass acts on the previously collected actors whose byte +0x60 was zero. This pass is skipped when the collection at world+0x94 is empty. For each selected actor A whose item category byte at +0x1020 is 0x13, a nonzero forward link that resolves to a non-null creature is initially retained. Otherwise the two link words are cleared and the map is scanned for a non-null kind-5 actor whose reverse identifier equals A's own identifier. The first matching actor's own identifier is copied into A's forward link. This recovery matches reverse ID to own ID; it does not compare against A's map entry key. [Evidence: `decompiled/client/assembly.txt`, RVA 0x20CA3D–0x20CA50, 0x20E419–0x20E580.]

* If A still has a zero link, the inspected branch can create a new linked actor unless A's byte at +0x124 has bit 0x10 set or an earlier refresh of an existing linked actor already occurred. Selection starts from eight-byte zero, scans map entries with non-null creature pointers, retains the least key below the current candidate under signed high-word/unsigned low-word ordering, and subtracts one with 64-bit carry. The resulting eight bytes are written to A+0x11C8 before allocation and construction. They then supply both the new creature's own identifier and its insertion key. The new actor is reset, receives A's own ID in its reverse identifier and byte +0x60 = 5, and is configured from A's current fields. The raw decrement is not a checked exhaustion or wraparound protocol. Publication and failure boundaries therefore matter: the forward ID is written before the allocation and insertion complete. [Evidence: `decompiled/client/assembly.txt`, RVA 0x20E6DF–0x20E88D.]

* Helper RVA 0x1EE7A0 accepts an eight-byte identifier I and a creature pointer L. It builds behavior state before the relationship write. If I resolves in the world's creature map to a non-null actor A, it puts I in L's reverse identifier and copies L's own identifier to A's forward link, low word then high word. If the map lookup fails or resolves null, that final forward-link write is absent. The helper does not derive the forward identifier from L's map entry. Calls from the world creation and refresh paths supply the previously selected A own identifier. The helper's earlier allocation, behavior and numeric dependencies remain bounded dependencies here. [Evidence: `decompiled/client/functions/005ee7a0.c`; `decompiled/client/assembly.txt`, RVA 0x1EE99A–0x1EEA19, 0x20E6A1–0x20E6B8, 0x20E8E8–0x20E8FC.]

* The enclosing client-frame routine also has a concrete assignment at RVA 0x094BAF/0x094BB8. After a hit-related record names the designated actor as its target, effect byte +0x45 equals 6, and that actor's item category is 0x14, it resolves the record's source key. The source actor's resident list must contain a selector-7 record whose scalar is ordered at least 1 and whose embedded identifier equals the designated actor's own identifier. On the admitted branch, the source actor's own identifier is copied into the designated actor's forward link, and the item category is changed to 0x13. Thus this assignment can originate outside the world-maintenance producer. The inspected comparisons and pointer origins establish the assignment; a complete protocol or symbolic interpretation of the resident record is outside scope. [Evidence: `decompiled/client/assembly.txt`, RVA 0x094A79–0x094B35, 0x094B7A–0x094BD4.]

## Link clearing, freshness and remaining limits

In the zero-world-byte maintenance path, an actor in the selected collection whose item category is not 0x13 has its current forward key looked up. If the resolved creature has a resident selector-7 record, the inspected branch retains the relationship. Otherwise A's forward link is cleared low word then high word; a resolved linked creature's health is then set to zero. A missing lookup still permits clearing. A separate pass over kind-5 actors checks their reverse identifier: when it resolves but that actor's forward link differs from the kind-5 actor's own identifier, the kind-5 actor is reset, given zero health, changed to byte +0x60 = 3, and has its reverse identifier cleared. That reset also resets its own fatal-context group and its own forward link. The mismatched owner's forward link is not repaired by this particular reset sequence. [Evidence: `decompiled/client/assembly.txt`, RVA 0x20E906–0x20E9C5, 0x20EAAF–0x20EB0B; reset RVAs 0x046330 and 0x0465C0.]

Existing links can survive while a linked actor is reset and rebuilt from current owner item/level inputs. The reset is called on the linked pointer, not on the owner holding the forward link; the configuration helper subsequently republishes the forward ID if its lookup succeeds. The trigger includes a changed +0x1138 value or changed item comparison against the retained +0x1D48 item. The complete item equality policy is not needed to establish the reset target and is not independently specified here. This route can restore −1, −1, 0 to an actor that previously had nondefault fatal-context coordinates. [Evidence: `decompiled/client/assembly.txt`, RVA 0x20E586–0x20E6DA; `decompiled/client/functions/00446330.c`, `004465c0.c`, `005ee7a0.c`.]

Fatal application and credit consumption lookup the retained link and mutate the resolved actor, but the inspected sequences do not clear the owner's forward ID merely because they zero the linked actor's health. A nonzero ID is therefore not proof of a living linked actor. Conversely, the credit consumer's lookup can be attempted for the zero value: zero is treated as an absent-link sentinel by particular producers and tests, not erased from the map's possible eight-byte key space. [Evidence: `decompiled/client/assembly.txt`, RVA 0x196279–0x1962E6, 0x1A0C58–0x1A0CAE, 0x1A0CF7–0x1A0D30; `decompiled/client/functions/0042f000.c`, `00477d90.c`.]

Ordering is local to each routine. In world RVA 0x20C510, supplied queued hits are applied at RVA 0x20CD9B before the link refresh/maintenance work and before descriptor spawning. The main actor traversal begins at RVA 0x210499 after those phases. A queued fatal hit can consequently observe the retained association and link from before the current invocation's later producer phases. This ordering does not prove any particular network-thread/frame schedule, a coherent all-actor snapshot, or continued validity if another actor or callback changes the referenced data. [Evidence: `decompiled/client/assembly.txt`, RVA 0x20CD1F–0x20CD9B, 0x20DDEB–0x20DEB6, 0x20E419–0x20EB15, 0x20F942–0x210499.]

The assignments themselves are ordinary 32-bit stores or three-word copies. The visible low/high store order is not an atomic 64-bit publication guarantee. The kind-0 receive path explicitly brackets map/state accesses with synchronization calls at RVAs 0x06BBDC, 0x06BC6F, 0x06BCBE and 0x06BE0C, but their system-wide exclusion against all readers and producers is not established here. Likewise, no transitive lock guarantee is inferred for the world producer or frame assignment. Direct selection and copying of the scoped identifiers consume no random draw; constructor, behavior, item and spatial-generation dependencies can consume or seed randomness before those assignments, and their complete draw order remains outside this contract.

The concrete closure is therefore: written constructor/reset defaults; an ordinary spawn association consisting of stored spatial coordinates plus a descriptor ordinal; byte-preserving state reception/copy routes; the identified forward/reverse relationship producers, clearing and rebuild boundaries; and their local read/write order. Unclosed boundaries include complete descriptor and selector-5 association generation, collection lifetime under mutation/unloading, every possible aliasing or virtual writer, malformed reception, allocation failure recovery, nested generation/RNG behavior, transport scheduling and whole-frame synchronization. No server equivalence or inferred gameplay role is claimed.
