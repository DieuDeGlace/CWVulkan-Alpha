# Alpha server hit-record routing

Status: FINAL / STABLE / HELD. Re-certified 2026-11-22. This is a bounded, original-only behavioral contract for reception of packet kind 7, server hit routing, and inclusion of the resulting hit records in outgoing aggregates. It does not establish any client behavior or client/server equivalence.

The supported image is `binary/Server.exe`, SHA-256 `1ffbcbce251e1506a63c9ce18ab0009d5553fcbb9e6202be2bc3a7d870d34fb1`, under the original evidence root `disassembled alpha cube world`. All addresses below are RVAs in that image; its preferred image base is `0x00400000`. Citations are relative to that evidence root. The original executable, the original server function exports, the full server instruction listing, and the per-function server assembly export were inspected for this contract. No other contract or replacement implementation supplies its facts.

## Record and sender identities

The incoming packet has a four-byte packet-kind value of 7 followed by a 72-byte (`0x48`) hit record. Nothing is read between that discriminator and the record. Within the record, the source ID occupies eight bytes at `+0x00` and the target ID eight bytes at `+0x08`. The creature-map lookups compare both 32-bit halves of each ID, the high half as a signed value first and the low half as an unsigned value second. The amount is a binary32 value at `+0x10`. The routing contract does not treat any other record property as connection identity. [Evidence: `decompiled/server/functions/00426020.c`, RVA `0x026020`, packet-7 branch `0x026461–0x0264DB`; `decompiled/server/functions/004cea80.c`, RVA `0x0CEA80`; `decompiled/server/functions/00530600.c`, RVA `0x130600`; `binary/Server.exe`, the same ranges.]

Each connection's receive worker is started with a context that holds the world, the manager's connection vector, the connection's slot index, the connection's 64-bit player ID, and the address of the manager's shared hit list at manager `+0x34` (whose 32-bit count is at manager `+0x38`). Packet-7 receipt uses the slot index only to obtain the socket and uses the shared-list address to enqueue the record. It does not read the player ID to validate, replace, or supplement either embedded ID. The queued value carries no added sending-player or slot field. [Evidence: `decompiled/server/functions/004254a0.c`, RVA `0x0254A0`, receive-worker context construction around `0x025D9D–0x025EA0`; `decompiled/server/functions/00422e80.c`, RVA `0x022E80`, manager construction; `decompiled/server/functions/00426020.c`, RVA `0x026020`, especially `0x02646C–0x0264C4`.]

Consequently, this path has no requirement that the source equal the sending player, that the target differ from the sending player, or that source and target differ. This is a statement about the inspected native checks; it is not an assertion about who generated a packet or about another endpoint's admission policy.

## Receipt and the shared input queue

The packet-7 branch first initializes selected properties of a temporary hit record. It then requests the remaining portion of the 72-byte body until positive receive results have filled it. Each positive result advances the destination and reduces the remaining count. A receive result of `-1` sets the worker's stop condition and leaves without appending this hit. Any other nonpositive result, including zero, leaves the body loop and reaches the append path even when bytes remain. There is no second complete-body-length check before the append. [Evidence: `decompiled/server/functions/00426020.c`, RVA `0x026461–0x0264DB`; `binary/Server.exe`, RVA `0x026490–0x0264DB`.]

The initializer clears the byte at `+0x14`, the eleven four-byte properties at `+0x18` through `+0x40`, the two bytes at `+0x44` and `+0x45`, and the byte at `+0x46`. It does not initialize the two IDs, the amount, or bytes `+0x15–+0x17` and `+0x47`. A prematurely ended body therefore cannot be described as a fully received or wholly zero-filled hit; whatever the temporary storage already held supplies any unfilled, uninitialized bytes. [Evidence: `decompiled/server/functions/00422a90.c`, RVA `0x022A90`.]

On the append path, the worker enters the world lock (the critical section at world `+0x8000C0`), appends one copied hit to the tail of the manager's shared hit list, and leaves that lock. This branch has no target lookup, source lookup, ID equality test, amount validation, role check, ownership check, or duplicate search. The append increments the list's 32-bit count and links a new node at the tail. Its exceptional limit at a count of `0x03333332` entries is a capacity check, not hit deduplication. [Evidence: `binary/Server.exe`, RVA `0x0264AC–0x0264C4`; `decompiled/server/functions/004d3df0.c`, RVA `0x0D3DF0`; `decompiled/server/functions/004d5c60.c`, RVA `0x0D5C60`; `decompiled/server/functions/00428400.c`, RVA `0x028400`.]

Each main-loop iteration constructs a fresh input aggregate and then drains the shared hit queue into that aggregate's hit list at aggregate `+0x00`. The whole drain runs under the world lock: it copies all queued hits in forward list order, resets the shared list to empty, sets its count at manager `+0x38` to zero, and frees the old nodes. This occurs before world processing and before network distribution. A receive append after the drain releases the lock belongs to a later drain. [Evidence: `decompiled/server/functions/00428230.c`, RVA `0x028230`; `decompiled/server/functions/00420ef0.c`, RVA `0x020EF0`; `binary/Server.exe`, main loop around `0x14A05A–0x14A0AE`, in the function at RVA `0x149C50`.]

After the drains, the main loop enters the world lock, constructs a distinct fresh output aggregate, calls world update with a time-difference value, the output aggregate, and the input aggregate, and then distributes the output aggregate to connections, all before leaving the world lock. It then sleeps 20 milliseconds and destroys both aggregates. Input inclusion alone is not an unconditional output echo. [Evidence: `binary/Server.exe`, RVA `0x14A081–0x14A26C`; `decompiled/server/functions/00549c50.c`, RVA `0x149C50`.]

World update skips hit handling when the input aggregate is absent or its hit list is empty. Otherwise, if the world mode byte at `+0xB4` is nonzero, it first clears the output hit list (`0x132B05–0x132B0B`). It then visits the input hit list from its first record to its end, calling the router once per record at `0x132B5B` and advancing to the next record after each call. It processes the input buff list at aggregate `+0x58` afterward. The world constructor stores the mode byte from a construction argument, and the standalone server main passes zero. [Evidence: `decompiled/server/assembly-functions/005322d0.asm`, RVA `0x132ADF–0x132BA4`; `decompiled/server/functions/00426f60.c`, RVA `0x026F60`; `decompiled/server/functions/004c8570.c`, RVA `0x0C8570`; `binary/Server.exe`, world construction at `0x149CB7–0x149CBD`.]

## Target admission and the relay decision

The router at RVA `0x0CEA80` operates on the world and receives three arguments: the hit record (the value stored in the input list node), the output aggregate, and an auxiliary collection owned by world update. It receives no sending-connection identity. Its first lookup uses the embedded target ID in the world's creature map at world `+0x04`. A missing entry or a null creature pointer returns without putting this hit in the output hit list and without looking up the source. The lookup is exact across the full eight-byte key; this routing code has no separate prohibition on an all-zero ID. [Evidence: `binary/Server.exe`, RVA `0x0CEACB–0x0CEB07`; `decompiled/server/functions/00530600.c`, RVA `0x130600`; `decompiled/server/assembly-functions/005322d0.asm`, call setup `0x132B40–0x132B5B`.]

Next, the router performs an ordered scalar comparison of binary32 zero against target health at creature `+0x16C` and returns when the carry flag is clear. Health values ordered at or below zero, including either signed zero and negative infinity, return. Positive finite health and positive infinity continue. An unordered comparison caused by a NaN health sets the carry flag and continues, provided floating-point execution completes. No finite-value normalization or maximum-health query precedes this admission. The machine-code branch is authoritative here rather than any simplified positive-health reading of the decompiled output. Unmasked floating-point exceptions and ambient floating-point controls remain execution limits. [Evidence: `binary/Server.exe`, RVA `0x0CEB0D–0x0CEB17`.]

After target admission, the exact direct-relay condition is that the four-byte world field at `+0xB8` is null and the target's one-byte numeric role at creature `+0x60` is zero. When both hold, the router appends a property copy of the hit to the output aggregate's hit list at `+0x00` and returns. This happens before the source lookup and before any amount, category, protection, knockback, resource, health, threat, or death processing. The source ID can therefore be unresolved, and source and target can be equal, without preventing this relay. [Evidence: `binary/Server.exe`, RVA `0x0CEB1D–0x0CEB38`; append helper RVA `0x028400`.]

The world constructor initializes the designated-creature pointer at `+0xB8` to null, and the standalone server main constructs the world with the mode byte at `+0xB4` zero. These establish the initial standalone configuration. They do not establish that either field can never change over the world's lifetime; the routing rule above remains conditional on the field values at the time of each call. [Evidence: `decompiled/server/functions/004c8570.c`, RVA `0x0C8570`; `binary/Server.exe`, RVA `0x149CB7–0x149CBD`.]

The identity outcomes are therefore:

| Relationship or target state | Established server routing outcome |
| --- | --- |
| Embedded target equals the sending connection's player ID | No rejection on that equality. The ordinary map, pointer, health, world-field, and target-role rules decide the route. |
| Embedded target differs from the sending player | No requirement to redirect it to the sender. The embedded target is looked up as supplied. |
| Embedded source equals embedded target | No self-hit rejection in receipt or the relay decision. A relay-eligible target produces the ordinary output hit. |
| Target passes admission, has role zero, and world `+0xB8` is null | One copied hit is appended to output, with no source lookup or local hit resolution by this router. |
| Target passes admission but the direct-relay condition fails | The source lookup and local hit-resolution path follow. The hit is not automatically appended for relay. |
| Target is missing, null, or has health ordered at or below zero | The router returns before either relay or local resolution. |

## Local NPC application and its limits

On the nonrelay path, the router looks up the embedded source ID in the same map. A missing entry yields a null source; a present entry can also hold a null pointer. Neither is an immediate general rejection. If the two embedded IDs are equal and that entry exists, both lookups resolve the same creature. The router does not replace either ID, construct a second creature, or apply a special self-hit suppression at this point. [Evidence: `binary/Server.exe`, RVA `0x0CEB3D–0x0CEB5E`.]

This branch is the route into local NPC hit application in the initial standalone configuration. Entry does not promise that health decreases. Among the subsequent gates, when target flag word `+0x7E` has bit `0x2000` set, the target's threat map at `+0x13A4` must contain an entry with a positive value whose key resolves to a nonnull role-0 creature; otherwise the router returns. A record category byte `+0x45` equal to 3 then returns. After knockback handling, category 1 takes the resource branch at target `+0x170` and returns, and category 4 calls the target helper at RVA `0x008230` with the output aggregate and returns. The health branch then requires world mode byte `+0xB4` zero or the target pointer equal to world `+0xB8`. Within it, a positive amount with category 5 subtracts from resident state entries of type 6 in the list at target `+0x1178` and can emit buff records into output aggregate `+0x58`. These are local-effect gates after the earlier routing decision. [Evidence: `binary/Server.exe`, RVA `0x0CED07–0x0CEFE7`; `decompiled/server/functions/004cea80.c`.]

For an ordinary positive-amount health subtraction (any category other than 5 that reached this point), the target must pass the low-byte eligibility result of the helper at RVA `0x009620`. If a nonnull source exists, it must pass the same helper; a null source does not block this subtraction on its own. The helper accepts roles 0, 1, 3 and 5, and role 6 except when the four-byte creature type at `+0x64` is `0x8C`, `0x8D` or `0x8E`. Other numeric roles fail. The admitted subtraction stores target health minus the supplied binary32 amount to target health. Negative amounts take a separate healing path that stores target health minus the negative amount. This contract does not close the arithmetic, protection, healing, threat, death, reward, or random dependencies of the whole local resolver. [Evidence: `decompiled/server/functions/00409620.c`, RVA `0x009620`; `binary/Server.exe`, RVA `0x0CEFEC–0x0CF04F`.]

Some local side effects precede those later gates. A positive amount reduces target state at `+0x1190` (floored at zero), and if the target action byte at `+0x68` is `0x54` it clears that byte and sets target `+0x12C` to 3000. A present source with a nonnegative amount records each creature's ID in the other's last-hit ID at `+0x11D0` and updates threat associations. The local branch can also produce other output categories and death-related state changes. It contains no general append of the received hit to the output hit list after local resolution; its only direct append of the received hit is the earlier role-0 relay branch. The router makes no direct stores to the received record's source, target, amount, or other properties through the record pointer. This does not certify purity of every downstream helper or callback. [Evidence: `binary/Server.exe`, RVA `0x0CEB5E–0x0CED07`, relay append at `0x0CEB33`, and record-pointer uses through `0x0CF153` and at `0x0CF6CB–0x0CF888`; `decompiled/server/calls.csv`, calls from RVA `0x0CEA80`.]

## Copies, recipients, and outgoing serialization

Every hit-list append and range copy here allocates an `0x50`-byte node, eight link bytes followed by 72 value bytes, and fills the value with the property copier at RVA `0x022A00`. The copier copies all eight bytes of each ID, the four amount bytes, byte `+0x14`, each four-byte property at `+0x18` through `+0x40`, and bytes `+0x44`, `+0x45`, and `+0x46`. These are plain width-preserving copies with no amount arithmetic, identifier substitution, or flag normalization. The copier does not write bytes `+0x15–+0x17` or `+0x47`, and allocation sets only the node links. Property preservation is established; a byte-for-byte copy of all 72 incoming bytes is not. [Evidence: `decompiled/server/functions/004202b0.c`, RVA `0x0202B0`; `decompiled/server/functions/004268b0.c`, RVA `0x0268B0`; `decompiled/server/functions/00422a00.c`, RVA `0x022A00`; `binary/Server.exe`, RVA `0x022A00–0x022A85`.]

The distributor enters the world lock and visits the manager's connection vector (manager `+0x28` to `+0x2C`) in increasing slot order. For every nonnull connection it first copies one other aggregate list (aggregate `+0x18` into connection `+0x30`) and then appends the entire output hit list to the tail of that connection's pending hit list at connection `+0x18`, preserving list order. Both copies precede the per-recipient creature lookup and distance gates used for other aggregate categories. The hit-list copy has no per-hit source or target comparison, source-connection exclusion, target-connection exclusion, target-role test, proximity filter, ownership filter, or duplicate search. Accordingly, a still-present sending connection receives the relay too; receiving a copy is not restricted to the target's connection. A null slot is skipped. [Evidence: `binary/Server.exe`, distributor at RVA `0x0272D0`, lock entry `0x027306–0x027309`, slot test `0x027340–0x027345`, hit-list copy `0x02736A–0x027392`, recipient lookup `0x027397–0x0273CB`; `decompiled/server/functions/00420ef0.c`, RVA `0x020EF0`.]

A connection's send worker, while holding the world lock, snapshots that connection's pending aggregate into a separate temporary aggregate. The snapshot copies the hit list through RVAs `0x023400`, `0x0221A0`, and `0x020EF0`. Still under the world lock it empties and frees the connection's pending lists, including the hit list, and sets the hit count at connection `+0x1C` to zero. It releases the world lock at `0x024C7B`, before the related network sends. Hits added after the snapshot remain pending for a later snapshot. The temporary aggregate lasts through the current serialization and send attempt and is then destroyed. The pending hit queue is not retained until acknowledgement or successful transmission. [Evidence: `binary/Server.exe`, lock entry `0x0248DD`, snapshot call `0x024911`, hit-list clearing `0x024963–0x024997`, lock release `0x024C7B`, in the function at RVA `0x023DD0`; `decompiled/server/functions/00423400.c`, RVA `0x023400`; `decompiled/server/functions/004221a0.c`, RVA `0x0221A0`.]

In the same attempt, the worker first sends a packet of kind 5 and then the four-byte packet kind 4. The kind-4 body is built from the snapshot. Its hit section is the second section written, after the section built from aggregate `+0x18`. The hit section is a four-byte count followed by the 72 raw value bytes of each node in forward list order. It adds no sender ID, does not replace the embedded source with a header ID, and does not select records by destination connection. The raw bytes include the four bytes the property copier omits, whose values are not established. After building the body, the worker runs the buffer-processing helper at RVA `0x012C70` (through RVA `0x012D00`, which calls ordinal 11 imported from `ZLIB1.DLL`), sends a four-byte resulting length, and then sends the resulting body. This contract does not specify that imported transformation's internals. [Evidence: `binary/Server.exe`, RVA `0x024C80–0x024D7D` and `0x024FAC–0x025019`; `decompiled/server/functions/00421b80.c`, RVA `0x021B80`; `decompiled/server/functions/00412c70.c`, RVA `0x012C70`; `decompiled/server/functions/00412d00.c`, RVA `0x012D00`; `decompiled/server/external_functions.csv`.]

## Ordering, repeated records, and remaining limits

No duplicate suppression is present in the inspected receive append, shared-queue drain, input iteration, direct-relay append, connection fan-out, snapshot, or hit serializer. Two successfully enqueued equal records are two list entries. Each routing call inspects then-current world state independently. A local first hit can change or kill the target so that a later equal record fails target-health admission; that is state-dependent processing, not a stored duplicate detector. The direct-relay branch itself does not change target health. [Evidence: reception RVA `0x026020`; append RVA `0x028400`; drain RVA `0x028230`; world input iteration RVA `0x132ADF–0x132B90`; router RVA `0x0CEA80`; distributor RVA `0x0272D0`; serializer RVA `0x021B80`, in the original files cited above.]

One worker's completed body appends follow its receive-loop order. Appends from different workers are ordered by their acquisition of the world lock; this evidence does not establish a deterministic cross-connection arrival order. The shared drain, input traversal, relay appends, connection-list appends, snapshot copies, and serialization each preserve forward order. A connection can accumulate output from several main-loop iterations before its next snapshot. These hit-list operations add no sequence number, acknowledgement identity, resend queue, or content-based coalescing. The main loop destroys its input and output aggregates after distribution rather than keeping them for retries. [Evidence: `decompiled/server/functions/00426020.c`; `decompiled/server/functions/00428230.c`; `decompiled/server/functions/00420ef0.c`; `decompiled/server/assembly-functions/005322d0.asm`; `binary/Server.exe`, RVA `0x0272D0`, `0x023DD0`, and `0x149C50`.]

The send worker checks the kind-4 header, length, and body send results for `-1`; the inspected sends do not loop to finish a positive short write and do not restore the already-cleared pending hit list after failure. [Evidence: `binary/Server.exe`, RVA `0x024D22–0x024D2A` and `0x024FDD–0x025019`.]

## Unresolved

- Socket transport success, complete peer delivery, disconnect races, allocation and length exceptions, and recipient-side application are not established. Receipt of a relay by the sending connection does not establish what that endpoint does with a self-sourced or self-targeted record. No behavior of the client image is inferred.
- The contents of the kind-5 packet that precedes kind 4, the sections of the kind-4 body other than the hit section, and the internals of the `ZLIB1.DLL` ordinal-11 transformation are not specified here.
- The values of bytes `+0x15–+0x17` and `+0x47` in relayed and serialized hits, and of any bytes left unfilled by a short packet-7 body, are not established.
- Whether world `+0xB4` or `+0xB8` can change during the standalone server's lifetime is not established.
- The whole local hit resolver (arithmetic, protection, healing, threat, death, reward, random draws, and every downstream helper and callback) is not closed.
- The role of the auxiliary collection passed to the router, and the purpose of the separate connection critical section at connection `+0x98` released during the send worker's snapshot, are not established.

The source/target admission and routing conclusions are closed for this server image and the inspected entry path; the items above remain open.
