# Alpha server hit-record routing

Status: FINAL / STABLE / HELD. This is a bounded, original-only behavioral contract for reception of packet kind 7, server hit routing, and inclusion of the resulting hit records in outgoing aggregates. It does not establish any client behavior or client/server equivalence.

The supported image is `binary/Server.exe`, SHA-256 `1ffbcbce251e1506a63c9ce18ab0009d5553fcbb9e6202be2bc3a7d870d34fb1`, under the original evidence root `disassembled alpha cube world`. All addresses below are RVAs in that image; its preferred image base is `0x00400000`. Citations are relative to that evidence root. The original executable, original server function exports, and original server assembly export were inspected independently for this contract. No other contract or replacement implementation supplies its facts.

## Record and sender identities

The incoming packet has a four-byte packet-kind value of 7 followed by a 72-byte, `0x48`-byte hit record. There is no separate source or target ID between that discriminator and the record. Within the record, the source ID occupies eight bytes at `+0x00` and the target ID eight bytes at `+0x08`. The routing lookups consume both 32-bit halves of each ID. The amount is read as binary32 at `+0x10`; the routing contract does not reinterpret the other record properties as connection identity. [Evidence: `decompiled/server/functions/00426020.c`, RVA `0x026020`, packet-7 branch `0x026461–0x0264DB`; `decompiled/server/functions/004cea80.c`, RVA `0x0CEA80`; `decompiled/server/functions/00530600.c`, RVA `0x130600`; `binary/Server.exe`, the same ranges.]

The receive worker has a sending-connection index and an associated 64-bit player ID available in its context. Connection setup also gives it the address of the manager's shared hit list, at manager `+0x34`. Packet-7 receipt uses the connection index to obtain the socket and the shared-list address to enqueue the record. It does not read the associated player ID to validate, replace, or supplement either embedded ID. The queued value carries no additional sending-player or connection-index field. [Evidence: `decompiled/server/functions/004254a0.c`, RVA `0x0254A0`, receive-worker context construction around `0x025D9D–0x025EA0`; `decompiled/server/functions/00426020.c`, RVA `0x026020`, especially `0x02646C–0x0264C4`.]

Consequently, this path has no requirement that the source equal the sending player, that the target differ from the sending player, or that source and target differ. This is a statement about the inspected native checks; it is not an assertion about who generated a packet or about another endpoint's admission policy.

## Receipt and the shared input queue

The packet-7 branch first initializes selected properties of a temporary hit record. It then requests the remaining portion of the 72-byte body until positive receive results have filled it. Each positive result advances the destination and reduces the remaining count. A receive result of `-1` takes the failure path without appending this hit. A result of zero leaves the body loop and reaches the append path even when bytes remain. There is no second complete-body-length check before the append. [Evidence: `decompiled/server/functions/00426020.c`, RVA `0x026461–0x0264DB`; `binary/Server.exe`, RVA `0x026490–0x0264DB`.]

The initializer clears the byte at `+0x14`, the eleven four-byte properties beginning at `+0x18` through `+0x40`, the two bytes at `+0x44`, and the byte at `+0x46`. It does not initialize the two IDs, the amount, or the four omitted-copy bytes described below. A prematurely ended body therefore cannot be described as a fully received or wholly zero-filled hit. The surviving temporary storage supplies any unfilled, uninitialized properties. [Evidence: `decompiled/server/functions/00422a90.c`, RVA `0x022A90`.]

On the append path, the worker enters the world lock, appends one copied hit to the tail of the manager's shared hit list, and leaves that lock. There is no target lookup, source lookup, ID equality test, amount validation, role check, ownership check, or duplicate search in this branch. The append routine increments the list's 32-bit count and links a new node. Its exceptional length limit of `0x03333332` entries is a capacity check, not hit deduplication. [Evidence: `decompiled/server/functions/00426020.c`, RVA `0x0264AC–0x0264C4`; `decompiled/server/functions/00428400.c`, RVA `0x028400`.]

The main server loop constructs a fresh input aggregate, then transfers the shared hit queue into that aggregate's hit list at aggregate `+0x00`. This transfer copies all queued hits in forward list order. Under the world lock it then resets the shared list to empty, sets its count at manager `+0x38` to zero, and frees its old nodes. This occurs before world processing and before eventual network transmission. A new receive append after that transfer belongs to a later drain. [Evidence: `decompiled/server/functions/00428230.c`, RVA `0x028230`; `decompiled/server/functions/00420ef0.c`, RVA `0x020EF0`; `decompiled/server/functions/00549c50.c`, RVA `0x149C50`, main loop around `0x14A05A–0x14A0AE`.]

The same main loop constructs a distinct fresh output aggregate, supplies both aggregates to world update, and later distributes that output aggregate to connections. Input inclusion alone is not an unconditional output echo. World update visits the input hit list from its first record to its end, calling the router once per record at RVA `0x132B5B`; it advances to the next input record after that call. It processes the input buff list afterward. If the world mode byte at `+0xB4` is nonzero and the input hit list is nonempty, it first clears the output hit list at `0x132B05–0x132B0B`. The standalone server's construction initializes that byte to zero. [Evidence: `decompiled/server/assembly-functions/005322d0.asm`, RVA `0x132ADF–0x132BA4`; `decompiled/server/functions/00426f60.c`, RVA `0x026F60`; `decompiled/server/functions/004c8570.c`, RVA `0x0C8570`; `decompiled/server/functions/00549c50.c`, RVA `0x149C50`.]

## Target admission and the relay decision

The router at RVA `0x0CEA80` receives the world, the hit record, the output aggregate, and an auxiliary collection. It receives no sending-connection identity. Its first identity lookup uses the embedded target ID in the world's creature map at world `+0x04`. A missing entry or a null creature pointer returns without putting this hit in the output hit list and without looking up the source. The lookup is exact across the full eight-byte key; there is no independent prohibition on an all-zero ID in this routing code. [Evidence: `decompiled/server/functions/004cea80.c`, RVA `0x0CEACB–0x0CEB07`; `decompiled/server/functions/00530600.c`, RVA `0x130600`; `binary/Server.exe`, RVA `0x0CEACB–0x0CEB07`.]

Next, the router compares binary32 zero against target health at creature `+0x16C`, using a scalar SSE ordered comparison and the native unsigned-above-or-equal branch. Ordered health values at or below zero, including either signed zero and negative infinity, return. Positive finite health and positive infinity continue. An unordered comparison caused by NaN continues if floating-point execution completes. No finite-value normalization or maximum-health query precedes this admission. This branch detail takes precedence over the simplified positive-health condition in the decompiled prose. Unmasked floating-point exceptions and ambient floating-point controls remain execution limits. [Evidence: `binary/Server.exe`, RVA `0x0CEB0D–0x0CEB17`; `decompiled/server/functions/004cea80.c`, RVA `0x0CEA80`.]

After target admission, the exact direct-relay condition is that the four-byte world field at `+0xB8` is null and the target's one-byte numeric role at `+0x60` is zero. When both hold, the router appends the original hit's copied properties to the output aggregate's hit list at `+0x00`, then returns. This occurs before the source lookup and before amount, category, protection, knockback, resource, health-change, threat, or death processing. The source ID can therefore be unresolved, and source and target can be equal, without preventing this relay branch. [Evidence: `binary/Server.exe`, RVA `0x0CEB1D–0x0CEB38`; `decompiled/server/functions/004cea80.c`, RVA `0x0CEA80`; append helper RVA `0x028400`.]

The world constructor initializes the designated-creature pointer at `+0xB8` to null. The standalone server main constructs this world with the mode byte at `+0xB4` zero as well. These establish the initial standalone configuration. They do not establish that either field can never change over the world's lifetime; the routing rule above remains conditional on the field values at the call. [Evidence: `decompiled/server/functions/004c8570.c`, RVA `0x0C8570`; `decompiled/server/functions/00549c50.c`, RVA `0x149C50`, world construction.]

The identity outcomes are therefore:

| Relationship or target state | Established server routing outcome |
| --- | --- |
| Embedded target equals the sending connection's player ID | No rejection on that equality. The ordinary map, pointer, health, world-field, and target-role rules decide the route. |
| Embedded target differs from the sending player | No requirement to redirect it to the sender. The embedded target is looked up as supplied. |
| Embedded source equals embedded target | No self-hit rejection in receipt or the relay decision. A relay-eligible target produces the ordinary output hit. |
| Target passes admission, has role zero, and world `+0xB8` is null | One copied hit is appended to output, with no source lookup or local hit resolution by this router. |
| Target passes admission but the direct-relay condition fails | The source lookup and local hit-resolution path follow. The original hit is not automatically appended for relay. |
| Target is missing, null, or has ordered health at or below zero | The router returns before either relay or local resolution. |

## Local NPC application and its limits

On the nonrelay path, the router looks up the embedded source ID. A missing entry produces a null source pointer; a present entry can also contain a null pointer. Neither is an immediate general rejection. If the two embedded IDs are equal, the two map lookups resolve the same creature pointer when that entry exists. The router does not replace one ID, construct a second creature, or introduce a special self-hit suppression at this boundary. [Evidence: `binary/Server.exe`, RVA `0x0CEB3D–0x0CEB5E`; `decompiled/server/functions/004cea80.c`, RVA `0x0CEA80`.]

This branch is the route into local NPC hit application in the initial standalone configuration. Entry does not promise that health decreases. Among the subsequent gates, target flag word `+0x7E` bit `0x2000` requires an eligible positive threat-map association with a resolvable role-0 creature before the main effect block. Record category byte `+0x45` equal to 3 exits that block. Category 1 uses the resource branch, category 4 calls its separate target helper, and positive category 5 affects resident type-6 state and can emit buff records. The health branch also requires world mode byte `+0xB4` zero or target-pointer equality with world `+0xB8`. These are local-effect gates after the earlier routing decision. [Evidence: `decompiled/server/functions/004cea80.c`; `binary/Server.exe`, RVA `0x0CED07–0x0CEF2F`.]

For an ordinary positive-amount health subtraction, the target must pass the low-byte eligibility result at RVA `0x009620`. If a nonnull source exists, it must pass the same helper; a null source does not block this subtraction on its own. The helper accepts roles 0, 1, 3 and 5, and role 6 except when the four-byte creature type at `+0x64` is `0x8C`, `0x8D` or `0x8E`. Other numeric roles fail. The admitted subtraction reads the supplied binary32 amount and stores the result to target health. Negative amounts use a separate healing path. This contract does not close the arithmetic, protection, healing, threat, death, reward, or random dependencies of the whole local resolver. [Evidence: `decompiled/server/functions/00409620.c`, RVA `0x009620`; `binary/Server.exe`, RVA `0x0CEFEC–0x0CF054`; `decompiled/server/functions/004cea80.c`.]

Some local side effects precede those later gates: positive amounts can change target state at `+0x1190` and interrupt action value `0x54` at target `+0x68`; a present source and nonnegative amount can update last-target IDs and threat associations. The local branch can also produce other output categories and death-related state changes. It contains no general append of the received hit to the output hit list after local resolution. Its direct received-hit append is the earlier role-0 relay branch only. There are no direct stores rewriting the received record's source, target, amount, or properties in the inspected router. This does not certify purity of every downstream helper or callback. [Evidence: `decompiled/server/functions/004cea80.c`, RVA `0x0CEA80`, including `0x0CEB5E–0x0CED07`; `decompiled/server/calls.csv`, calls from RVA `0x0CEA80`; `binary/Server.exe`, relay append at `0x0CEB33`.]

## Copies, recipients, and outgoing serialization

All hit-list append and range-copy operations here allocate a node with eight link bytes and 72 value bytes, then use the property copier at RVA `0x022A00`. It copies all eight bytes of each ID, the four amount bytes, byte `+0x14`, each four-byte property at `+0x18` through `+0x40`, and bytes `+0x44`, `+0x45`, and `+0x46`. These are plain width-preserving copies, without amount arithmetic, identifier substitution, or flag normalization. The copier does not write record bytes `+0x15–+0x17` or `+0x47`. Allocation initializes the node links rather than zeroing the record storage. Thus property preservation is established, but a byte-for-byte copy of all 72 incoming bytes is not. [Evidence: `decompiled/server/functions/004202b0.c`, RVA `0x0202B0`; `decompiled/server/functions/004268b0.c`, RVA `0x0268B0`; `decompiled/server/functions/00422a00.c`, RVA `0x022A00`; `binary/Server.exe`, RVA `0x022A00–0x022A83`.]

The distributor visits the manager's connection vector in increasing slot order. For every nonnull connection, it appends the entire output hit list to that connection's pending hit list at connection `+0x18`, preserving list order. This hit-list copy precedes the per-recipient creature lookup and distance gates used for other aggregate categories. There is no per-hit source or target comparison, source-connection exclusion, target-connection exclusion, target-role test, proximity filter, ownership filter, or duplicate search in the hit-list copy. Accordingly, a still-present sending connection receives the relay too; receiving a copy is not restricted to the target's connection. A null connection slot is skipped. [Evidence: `decompiled/server/functions/004272d0.c`, RVA `0x0272D0`; `binary/Server.exe`, hit-list copy at `0x02736A–0x027392`, followed by recipient lookup at `0x027397–0x0273CB`; `decompiled/server/functions/00420ef0.c`, RVA `0x020EF0`.]

A connection's send worker snapshots its pending aggregate into a separate temporary aggregate while holding the world lock. The snapshot copies the hit list through RVAs `0x023400`, `0x0221A0`, and `0x020EF0`. It then empties and frees the connection's pending hit list and sets connection `+0x1C` to zero before releasing the world lock and before the relevant network sends. Hits added after this snapshot remain pending for a later snapshot. The temporary aggregate survives through the current serialization/send attempt and is subsequently destroyed. The original pending hit queue is not retained until acknowledgement or successful transmission. [Evidence: `decompiled/server/functions/00423dd0.c`, RVA `0x023DD0`; `binary/Server.exe`, snapshot call `0x024911` and hit-list clearing `0x024963–0x024997`; `decompiled/server/functions/00423400.c`, RVA `0x023400`; `decompiled/server/functions/004221a0.c`, RVA `0x0221A0`.]

The server transmits this aggregate under packet kind 4. Before aggregate buffer processing, the hit-list serializer writes a four-byte count, then copies 72 raw bytes from each node's value in forward list order. It does not add a sender ID, replace the embedded source with a header ID, or select records by the destination connection. The raw serialization includes the four bytes omitted by the property copier, whose values are not established. After aggregate construction, the worker calls the native buffer-processing helper at RVA `0x012C70`, sends a four-byte resulting length, then sends the resulting body. The exported preprocessing helper reaches an imported ordinal function; this contract does not specify that external transformation's internals. [Evidence: `decompiled/server/functions/00423dd0.c`, RVA `0x023DD0`, packet-kind-4 construction and sends; `decompiled/server/functions/00421b80.c`, RVA `0x021B80`; `decompiled/server/functions/00412c70.c`, RVA `0x012C70`; `decompiled/server/functions/00412d00.c`, RVA `0x012D00`.]

## Ordering, repeated records, and remaining limits

No duplicate suppression is present in the inspected receive append, shared-queue drain, input iteration, direct-relay append, connection fan-out, snapshot, or hit serializer. Two successfully enqueued equal records are two list entries. Repeated routing calls inspect then-current world state independently. A local first hit can change or kill the target so that a later equal record fails the target-health admission; that is state-dependent processing, not a stored duplicate detector. The direct-relay branch itself does not change target health. [Evidence: reception RVA `0x026020`; append RVA `0x028400`; drain RVA `0x028230`; world input iteration RVA `0x132ADF–0x132B90`; router RVA `0x0CEA80`; distributor RVA `0x0272D0`; serializer RVA `0x021B80`, in the original files cited above.]

One worker's completed body appends follow its receive-loop order. Appends from different workers are ordered by their acquisition of the world lock; this evidence does not establish a deterministic cross-connection arrival order. The shared drain, input traversal, relay appends, connection-list appends, snapshot copies, and serialization preserve the forward order at each stage. A connection can accumulate output from multiple world iterations before its next snapshot. No sequence number, acknowledgement identity, resend queue, or content-based coalescing is added by these hit-list operations. The main loop destroys its input and output aggregates after distribution rather than retaining them for later retries. [Evidence: `decompiled/server/functions/00426020.c`; `decompiled/server/functions/00428230.c`; `decompiled/server/functions/00420ef0.c`; `decompiled/server/assembly-functions/005322d0.asm`; `decompiled/server/functions/004272d0.c`; `decompiled/server/functions/00423dd0.c`; `decompiled/server/functions/00549c50.c`.]

The send worker checks the aggregate header, length, and body send results for `-1`; the inspected sends do not loop to finish a positive short write or restore the already-cleared pending hit list after failure. Socket transport success, complete peer delivery, external buffer processing, disconnect races, allocation/length exceptions, and recipient-side application remain outside this contract. In particular, receipt of a relay by the sending connection does not establish what that endpoint does with a self-sourced or self-targeted record. No behavior of the client image is inferred here. [Evidence: `decompiled/server/functions/00423dd0.c`, RVA `0x023DD0`, packet-kind-4 failure paths and cleanup; `decompiled/server/functions/00428400.c`; `decompiled/server/functions/004268b0.c`.]

The source/target admission and routing conclusions are closed for this server image and the inspected entry path. The whole local hit resolver, lifetime invariants of world `+0xB4` and `+0xB8`, external library behavior, and end-to-end delivery or application are explicitly unclosed.
