# Alpha creature behavior target-selection boundary

Status: FINAL / STABLE / HELD. This is a bounded source-only contract; later action execution and navigation are outside its scope.

The supported image is `disassembled alpha cube world/binary/Cube.exe`, SHA-256 `84a7a132a84d4282338e7ea45a1940d32066d64e39cbafed8f2418d5a6dc30bf`, preferred image base `0x400000`. Evidence citations below are relative to `disassembled alpha cube world`. The principal evidence is `decompiled/client/assembly.txt`, update RVA `0x02CB20`, from entry through the no-target exit at `0x02D2A9`, together with its reached publication helper `0x1A0970`. Original helper listings were checked against the supported image; 3,918 instruction entries across the prefix and individually scoped helpers matched its bytes. No reconstruction, runtime observation, or other project contract supplies facts here.

**Inputs and identity.** The receiver of `0x02CB20` is a behavior object. Its four stack arguments, in order, are a creature pointer, world pointer, 32-bit step amount, and output-aggregate pointer. This document calls the supplied creature the subject. The prefix uses that current argument; it does not recover a replacement subject from the behavior object's identifiers. Normal returns remove 16 argument bytes, with the Boolean result in the low result byte. A nonnull selected target instead reaches `0x02D2AE`, where this contract stops; that boundary is not itself a function return. Subject, world, aggregate and container validity are caller prerequisites, not checked here. The surrounding virtual caller's admission and the interpretation or unit of the supplied step are not established by this audit. (`assembly.txt`, RVAs `0x02CB20–0x02CB71`, `0x02D2A0–0x02D2AE`, `0x02EEBE–0x02EEE3`.)

The behavior fields used here are signed-tested 32-bit counters at `+0x04/+0x10`, a 32-bit field reset at `+0x0C`, and a binary32 scalar at `+0x08`. The reset alone does not establish signedness for `+0x0C`. Their broader meanings and initialization are not inferred from this prefix. Subject and candidate identity fields are full 64-bit stored identifiers at `+0x08`; position components are signed 64-bit quantities at `+0x10`, `+0x18`, and `+0x20`. The actor fields relevant to decisions are discriminator byte `+0x60`, full 32-bit kind `+0x64`, action byte `+0x68`, signed 32-bit action clock `+0x6C`, unsigned 16-bit word `+0x7E`, 16-bit flags `+0x124`, full 32-bit value `+0x128`, binary32 health `+0x16C`, full 32-bit numeric field `+0x190`, and full 64-bit link key `+0x198`. These are numeric identities and offsets, not inferred faction, ownership, action-name or duration labels.

The world's actor container is at world `+0x04`. It maps signed 64-bit keys to 32-bit actor pointers. Actor `+0x13A4` and `+0x13AC` are separate containers of signed 64-bit keys and binary32 values. Their traversal order is ascending signed key: the high word is compared as signed, then the low word as unsigned. A map key and the pointed actor's stored identifier are not compared for consistency here. Exact lookup `0x077D90` returns the matching node or the container sentinel and does not insert. It accepts key zero. Slot helper `0x068AD0` returns an existing value or inserts the exact key with a positive-zero default value. None of these rules makes a null mapped actor pointer usable. (`assembly.txt`, RVAs `0x077D90–0x077E03`, `0x068AD0–0x068B6C`; original files `decompiled/client/functions/00477d90.c`, `00468ad0.c`.)

**Earlier admission and inventory precedence.** Every ordinary entry first clears mask `0x0004` in the subject's 16-bit `+0x124` word. Next, an action other than `0x53`, `0x52`, `0x54`, or `0x4F` is replaced by byte zero when its signed clock is strictly greater than 10,000. Equality does not clear it, and the clock itself is retained. After those mutations, any nonzero full 32-bit `+0x128` causes a true return. Otherwise action `0x50` with clock strictly below 3,000 also returns true. Equality at 3,000 proceeds. Neither return reduces the behavior counters, updates mask `0x0040`, or performs target lookup. The earlier action clear can therefore occur even on an immediate true return. (`assembly.txt`, RVAs `0x02CB71–0x02CBCC`.)

On continued entry, health is sampled before one call to subject stat helper `0x044DB0`. Its x87 result is stored as binary32; that value is multiplied by binary32 0.25. Only health strictly below that product reaches helper `0x03D1A0`. The subject's signed action clock must then be strictly greater than that helper's signed 32-bit result. Equality at either boundary does not admit inventory use. The complete stat/action tables behind these two helpers remain dependencies, rather than being replaced by a fixed health ceiling or action duration in this contract. Their call identities, result conversions and comparison order are established. (`assembly.txt`, RVAs `0x02CBCC–0x02CC06`, helper entries `0x044DB0`, `0x03D1A0`; `decompiled/client/functions/00444db0.c`, `0043d1a0.c`.)

Eligible inventory scanning visits the outer vector bounded by subject `+0x11DC/+0x11E0` in increasing address order. Its elements occupy 12 bytes and contain an inner begin/end pair. Inner records occupy `0x11C` bytes: a 32-bit count followed by an item payload of `0x118` bytes. The first record whose count is nonzero and whose first two payload bytes both equal 1 is used. The count test is not a positive-count test. No later eligible record is considered after that first match. Empty vectors or exhaustion continue to target lookup.

Item use writes subject action `0x50`, then the full action clock zero, then copies the selected item's semantic fields to subject `+0x1E8` through `0x02C5E0`. Relative to the item, that copy includes bytes `+0/+1`, 32-bit fields `+4/+8`, bytes `+0x0C/+0x0D/+0x0E`, word `+0x10`, all 32 eight-byte records beginning `+0x14`, and the 32-bit tail at `+0x114`. It does not initialize the omitted padding between those fields. The source count is then decremented with 32-bit wrap. If the resulting signed value is at most zero, the count and only the first two source payload bytes are set to zero. Other source payload bytes remain. Thus negative counts pass the initial admission; ordinary negative decrements are clamped, while decrementing `INT32_MIN` wraps to positive `INT32_MAX` and escapes that clamp. (`assembly.txt`, RVAs `0x02CC06–0x02CCBB`, helper `0x02C5E0–0x02C672`.)

Only after the copy and count changes are there two random calls, at `0x02CCC1` and `0x02CCE8`. Each returned signed integer is converted to binary32, multiplied by 4.0, divided by 32,767.0, then reduced by 2.0, with scalar single-precision operations at those boundaries. The first result is retained while the second draw occurs. The subject's `+0x40` component receives the first result, `+0x48` receives positive zero, and `+0x44` receives the second result, in that write order. This is not normalized. The function then returns true without target selection or counter reduction. The two calls use the same original import, `MSVCR110.dll!rand`, IAT RVA `0x2FC468`; no seed call occurs on this route. (`assembly.txt`, RVAs `0x02CCBB–0x02CD20`; original import table and constants in `binary/Cube.exe`.)

**Preliminary target choices.** Failure to use an inventory record invokes `0x044BF0` on the subject. This scans subject `+0x13A4`, begins with value positive zero and selected key zero, and excludes key zero from consideration. A nonzero key replaces the choice when its value is greater than or equal to the current best. For ordinary finite values, negative entries cannot win; zero entries can. Equal maximum values select the last visited key, hence the greatest signed key. The helper returns that full 64-bit map key, not a stored actor identifier. An empty map or no eligible value returns zero. (`assembly.txt`, RVAs `0x044BF0–0x044CA0`; `decompiled/client/functions/00444bf0.c`.)

The caller performs a world lookup of the returned key even when it is zero. Missing keys and null mapped pointers produce no preliminary target. If world key zero maps to a nonnull actor, it can become the preliminary target even though the key-selection helper returned its zero default. There is no retry with a lower-ranked map entry if the chosen key is absent or null. This route does not test target health, self-pointer equality, discriminator, distance, relationship, visibility, or stored-ID consistency. (`assembly.txt`, RVAs `0x02CC42–0x02CC88`, `0x02CD25–0x02CD28`.)

Subject discriminator 5 adds a separate linked-actor lookup using the subject's entire `+0x198` key, including zero. A missing or null link preserves the preceding preliminary choice. A nonnull linked actor discards it immediately. If that linked actor's action byte equals `0x6A`, the function returns false at `0x02D2A7` without reducing either behavior counter, clearing behavior `+0x0C`, or updating subject mask `0x0040`. Earlier entry mutations remain.

Otherwise the linked actor's `+0x13AC` container is traversed in ascending signed-key order. A value must be strictly greater than the current best, initially positive zero. For such an entry, its map key is looked up in the world. Only a found nonnull pointer admits the entry; the native path then repeats the same world lookup to obtain the selected pointer and retains the entry's value. Under stable containers, this selects the first valid key with the greatest positive value, with the lowest signed key winning equal positive values. Zero and negative values never qualify. An absent/null entry does not raise the best value and therefore cannot suppress a later valid lower-valued entry. Key zero is not excluded. No health, self, type, distance, relationship or visibility test is added. Empty or unsuccessful linked selection leaves no preliminary target; the discarded earlier choice is not restored. The two lookups are distinct native operations, not one cached query. Concurrent mutation between them is outside the stable-input relation and can invalidate its pointer assumptions. (`assembly.txt`, RVAs `0x02CD28–0x02CE36`.)

**No-preliminary-target special case and counters.** A null preliminary pointer causes a fresh health sample and a second `0x044DB0` call. After binary32 result storage and multiplication by 0.5, health strictly below that product together with subject discriminator 3 starts a different immediate action: byte `+0x68` becomes `0x50`, clock `+0x6C` becomes zero, word `+0x1E8` becomes `0x0401`, word `+0x1F8` receives the low 16 bits of subject `+0x190`, and components `+0x40/+0x44/+0x48` become positive zero in that order. This only overwrites those item fields; it is not a full item copy. It returns true without a draw, counter reduction or mask-`0x0040` update. A nonnull preliminary target avoids this second stat query. Equality at the half-value boundary does not start this action. (`assembly.txt`, RVAs `0x02CE36–0x02CEE7`.)

All other continued routes, including null preliminary targets that fail that special case, reduce behavior `+0x04` by the supplied 32-bit step. The subtraction wraps to 32 bits; a negative signed result is then replaced by zero. Zero or negative input steps are not rejected: zero leaves a nonnegative counter unchanged, while a negative step ordinarily increases it, subject to wrap and the final signed clamp. This counter does not itself gate the world scan in the audited prefix.

The subject's resident list at `+0x1178` is next scanned in forward list order until its sentinel or the first node whose payload type byte is 8. Presence is remembered without checking a duration, removing a node, or changing a record. A nonnull preliminary target bypasses the fallback world scan regardless of this presence. (`assembly.txt`, RVAs `0x02CE3A–0x02CE76`, `0x02CEEC–0x02CF01`.)

**Fallback scan admission and distance.** The fallback scan requires a null preliminary pointer. Subject discriminator 5 with any nonzero full link key suppresses it, even if that link failed world lookup. Behavior `+0x10` strictly greater than zero also suppresses it; zero and negative values permit it. This test precedes that counter's later reduction, so becoming zero later in this invocation does not reopen the scan. Its initial binary32 distance limit is behavior `+0x08` multiplied by itself. A negative finite scalar therefore gives the same initial limit as its positive counterpart; a zero limit admits no ordinary nonnegative score. (`assembly.txt`, RVAs `0x02CF01–0x02CF3C`.)

The world container is traversed in ascending signed-key order through its live nodes, without a copied candidate vector or fixed candidate count. Each entry supplies its mapped pointer. Null pointers, pointer equality with the subject, ordinary finite health at most zero, and discriminator byte 5 are rejected before distance calculation. There is no key-zero or stored-ID-zero exclusion. Distinct pointers with the same stored identifier are not rejected as self. Conversely, an alias of the subject pointer is rejected regardless of its map key. A selected pointer from either preliminary-map route did not undergo these fallback-only checks.

Candidate-minus-subject position differences are formed as three wrapped 64-bit differences and treated as signed integers by x87 loads. Each is stored as binary32, then separately multiplied in binary32 by exactly `2^-16` (constant bits `0x37800000`). Each scaled component is squared in binary32. The squared distance adds Y squared to X squared first, then adds Z squared, with binary32 rounding after each addition. It is not an integer distance comparison or a double-precision norm. (`assembly.txt`, RVAs `0x02CF42–0x02D087`; constant RVA `0x2FCD94`.)

Candidate binary32 `+0x1190` strictly greater than zero modifies that distance. The candidate's full 32-bit `+0x190` minus the subject's corresponding field wraps to 32 bits and is interpreted as signed. It is converted first to binary32 and then widened to binary64 as the exponent of the original precise power call with binary64 base 1.5. The power result is rounded to binary32, multiplied by candidate `+0x1190`, and subtracted from binary32 1.0. That factor is lower-clamped to the stored binary32 0.1 (`0x3DCCCCCD`), squared in binary32, and used to divide the squared distance in binary32. Equality at the lower clamp retains the factor. Nonpositive finite `+0x1190` bypasses this entire power/factor adjustment. This adjustment occurs before the resident-type-8 rejection, so its power call is still reached for otherwise eligible candidates when type 8 will reject them. (`assembly.txt`, RVAs `0x02D072–0x02D0F3`; binary constants RVAs `0x2FD328`, `0x345DC0`, `0x2FCB7C`.)

With no resident type 8, a candidate's adjusted score must be strictly below the current limit. Equality loses. Further admission tests occur before that limit is narrowed; a closer rejected candidate does not hide a farther acceptable one. Every accepted candidate becomes the current choice and its score becomes the new limit. Thus the final choice is a minimum admissible score strictly inside the initial limit, with the first visited candidate winning equal scores. This tie rule differs from both preliminary-map rules. The scan continues after finding a choice. (`assembly.txt`, RVAs `0x02D0EE–0x02D20F`.)

**Relationship, visibility and kind predicates.** For a score that passes the strict limit, relationship helper `0x196CA0` is called with subject first and candidate second. A false result can be bypassed only when the subject discriminator is 5, the subject's full link key is zero, candidate action byte is `0x52`, candidate byte `+0x1020` is `0x14`, and candidate byte `+0x1021`, zero-extended to 32 bits, equals the subject's full 32-bit kind `+0x64`. A subject kind outside 0–255 cannot satisfy the last equality. These are raw predicates, with no inferred action or equipment name.

Next, visibility helper `0x19EE90` receives the world, the subject position address, candidate position address, full 32-bit literal 1, and binary32 200.0. Its false result rejects the candidate. Only after a true visibility result does classifier `0x044680` inspect the subject, not the candidate. A false classifier result admits the candidate. A true classifier result requires the same three candidate predicates on `+0x68/+0x1020/+0x1021`; this second check does not additionally require subject discriminator 5 or zero link. Neither predicate sequence mutates the candidate. (`assembly.txt`, RVAs `0x02D102–0x02D1A7`.)

Classifier `0x044680` returns false when any bit in actor word `+0x7E` mask `0x1A00` is set. Otherwise its true-result full-32-bit kind set is: `0x13, 0x14, 0x16, 0x17, 0x19, 0x1A, 0x1B, 0x1E, 0x1F, 0x20, 0x21, 0x22, 0x23, 0x35, 0x37, 0x38, 0x39, 0x3A, 0x43, 0x44, 0x4A, 0x57, 0x59, 0x5C, 0x5D, 0x62, 0x64, 0x6A, 0x6B, 0x91, 0x92, 0x93`. Every other kind returns false. The helper has no writes, nested calls or draws. (`assembly.txt`, RVAs `0x044680–0x044759`; `decompiled/client/functions/00444680.c`.)

Relationship `0x196CA0` is ordered. A first actor with discriminator 5 and second with discriminator 0 returns false before subsequent rules; either discriminator 6 also returns false. After those exclusions, exactly one discriminator 1 gives true. Two discriminator-1 actors are classified first-actor then second-actor; a mismatch gives true. If equal, the native path repeats those two classifier calls in the same order and again admits a mismatch. Remaining cases return true if either actor's low byte at `+0x124` has mask `0x20`; otherwise false. There is no identity or owner lookup, pointer-self rejection, world-mode test, random call or state write inside this helper. It requires usable actor pointers. (`assembly.txt`, RVAs `0x196CA0–0x196D2A`; `decompiled/client/functions/00596ca0.c`.)

Visibility uses the same signed-difference, binary32 scaling and Y/X/Z squared-sum relation as above, without the `+0x1190` adjustment. A squared distance strictly below binary32 `0.0001` (`0x38D1B717`) immediately succeeds. Otherwise a squared distance strictly above binary32 200.0 squared fails; equality remains eligible. It widens the single-precision squared distance for the original precise square-root import, rounds the result back to binary32 length, and divides each scaled component by that length in binary32. Ray helper `0x1A35D0` then receives the original start position, that direction, length, byte-zero option and the caller's option 1. The ray result is rounded from x87 to binary32. Visibility succeeds when it is at least binary32 length minus stored binary32 0.01 (`0x3C23D70A`); equality succeeds. (`assembly.txt`, RVAs `0x19EE90–0x19F065`; constants RVAs `0x345D90`, `0x2FCDA0`; `decompiled/client/functions/0059ee90.c`.)

The ray helper's complete voxel traversal, missing-cell policy, stopping geometry and exceptional coordinate conversions remain an explicit dependency. Its directly reached original native helpers are spatial lookup `0x034D10` through `0x034A90`, column access `0x02F730`, signed division `0x28D9E0`, scalar-to-integer conversion `0x28D946`, and the runtime security check. Those inspected native routes contain no random/seed call or gameplay callback. Column access may initialize or overwrite its shared default-cell storage; it is not necessarily a globally write-free query. This does not establish a collision or line-of-sight algorithm beyond the caller relation just stated. (`assembly.txt`, helper `0x1A35D0`; individually identified originals `decompiled/client/functions/005a35d0.c`, `00434d10.c`, `00434a90.c`, `0042f730.c`, `0068d946.c`.)

**Selected-target publication.** Only a newly chosen fallback-scan target reaches `0x02D213–0x02D232`. The subject's `+0x13A4` slot under the target's stored 64-bit identifier is obtained or inserted and overwritten with binary32 1.0. This key comes from the actor, not from the world-map node that supplied its pointer. Helper `0x1A0970` is then called on the world with the selected target first, subject second and current output aggregate third. Preliminary-map targets bypass this new store and helper call. (`assembly.txt`, RVAs `0x02D20F–0x02D237`.)

The helper first reads the subject's value under that same target stored identifier, then appends one relationship record to aggregate `+0x50`. Here its semantic fields are subject stored ID at record `+0`, target stored ID at `+8`, and binary32 1.0 at `+0x10`. Both IDs occupy all 64 bits. The copied payload occupies 24 bytes, but the producer initializes only these first 20 semantic bytes; the last four bytes are opaque padding, not a zero field. Allocation and the payload copy precede list-count increase and final linkage. No transport send or later receiver application is performed by this helper. (`assembly.txt`, RVAs `0x1A0970–0x1A0A0A`, copying helper `0x051D00`, append helper `0x086150`.)

After that first append, `0x1A0970` scans the live world actor container in ascending signed-key order. It excludes null pointers and pointers equal to either the selected target or subject. For each remaining actor, it calls `0x196CA0` with that actor first and selected target second. Only a true result reaches position arithmetic. The resulting squared distance is from that actor to the subject, with the same binary32 scaling and Y-squared-plus-X-squared-then-Z-squared relation. It must be strictly below binary32 64.0, not 64.0 squared. Equality fails. No health or extra discriminator gate is added.

For each such actor, its `+0x13A4` slot keyed by the selected target's stored identifier is obtained or default-inserted. Only a value equal to zero is overwritten by binary32 0.5; both signs of zero qualify. That change precedes another 24-byte append carrying that actor's stored ID, target stored ID and the newly read value 0.5. The original performs another slot lookup for the store and another for the record's value read; these are retained operations, not a single assumed cached pointer. Existing nonzero values, including negatives, receive no overwrite or event. An unordered value does not pass the zero test. The first subject record always precedes these additional records, whose order follows successful actors in the world scan. There is no key-zero, stored-ID-zero, duplicate-stored-ID, or self-ID exclusion. Different pointers with equal stored IDs may therefore address the same numeric keys and generate repeated ID pairs. Pointer exclusions remain effective even when IDs differ. (`assembly.txt`, RVAs `0x1A0A0A–0x1A0BE0`; `decompiled/client/functions/005a0970.c`.)

These are map changes and output-list publication under the passed world/aggregate, with no direct test of world mode byte `+0xB4` or designated pointer `+0xB8` in the prefix or this helper. No client/server ownership equivalence is inferred. Container allocation failure, maximum-length exceptions, allocator hooks and asynchronous mutation are outside the normal successful-publication relation. In particular, the native count-limit failure can occur after allocation and payload copying; this contract does not promise transactional rollback of the prior map store.

**Readiness, terminal counter changes and scope boundary.** A nonnull preliminary target or newly published fallback target next reaches the same readiness test. Action byte zero is ready immediately. For every other action, the original queries `0x044270`, `0x03CAA0`, then `0x047310` on the subject, each with full signed 32-bit argument −1. Those helpers resolve the negative argument using the current unsigned action byte. The first signed 32-bit result is halved with truncation toward zero before combining it with the second and third signed results, with 32-bit wrapping additions. Readiness requires the subject's signed clock strictly greater than this threshold. Equality fails. Complete action-dependent query tables and stat-derived values remain explicit dependencies; the call count, order, negative-argument resolution, integer half and boundary comparison are established. A null final pointer does not run those readiness queries and is treated as not ready, even if its action is zero. (`assembly.txt`, RVAs `0x02D237–0x02D26E`, helper entries `0x044270`, `0x03CAA0`, `0x047310`.)

Readiness sets mask `0x0040` in the subject's 16-bit `+0x124` word; not ready clears only that mask. Behavior `+0x10` is then reduced by the supplied step, with the same 32-bit wrap followed by signed-negative clamp to zero used for `+0x04`. With no final target, behavior `+0x0C` is set to zero and the function returns false through `0x02D2A9`. The linked-actor action-`0x6A` false exit described earlier bypasses all these terminal changes. With a nonnull target, this prefix does not reset `+0x0C`, and proceeds to `0x02D2AE` even if readiness was false. The later code decides action execution and navigation; no success return, attack, movement, additional map lifetime, or future counter behavior is inferred at this handoff. (`assembly.txt`, RVAs `0x02D26E–0x02D2AE`.)

**Randomness and remaining numeric limits.** Within the audited prefix the only direct random draws are the two inventory-use calls, after its item/count mutations and before its component writes. The alternative discriminator-3 immediate action draws none. Primary-map selection, link override, fallback traversal, relationship/classifier checks, selected-target map writes and relationship publication contain no direct random or seed call. The inspected native stat dependencies lead through `0x047700`, `0x044CB0`, `0x0478B0`, item queries `0x0C70B0/0x0C7C00` and numeric helpers `0x045F60/0x045FF0`, whose scoped native calls are arithmetic/power queries rather than random producers. The stat, visibility and map/list helper boundaries inspected here add no identified native gameplay random or seed call. Native insertion bookkeeping, rotations, successor traversal and payload copying likewise do not add one. Allocation, exception, runtime-library internals and externally replaced hooks are not covered by that statement. No seed is installed or restored by this prefix. The imported seed API is separately `MSVCR110.dll!srand` at IAT RVA `0x2FC4B4`; merely sharing that DLL does not establish a global or cross-thread stream contract.

All ordinary floating-point selection relations above assume finite inputs and usable original data structures, with no concurrent structural mutation. Each stated binary32 operation retains its native conversion/rounding boundary; the prefix does not install an x87 control word or MXCSR rounding mode. The power import is `_libm_sse2_pow_precise`, reached through `0x28D8D4`; the square-root import is `MSVCR110.dll!_libm_sse2_sqrt_precise`, reached through `0x28D9C8`. Their full algorithms and exceptional-state behavior are not reconstructed. Overflowing power, nonfinite actor fields, denormal handling, floating-point traps, invalid pointers, malformed/cyclic containers, aliasing with mutable container storage, and asynchronous changes between repeated queries remain outside the ordinary numeric relation. In particular, this contract's finite positive-health wording must not be promoted into a claim that every unordered value is rejected at the same gate.

The established output is therefore a bounded selection/state/publication relation for the current subject and world inputs. Full movement, later actions, caller scheduling, complete stat tables, voxel visibility geometry, producer lifetime of the input maps and resident records, transport delivery, and a server counterpart remain unclosed. Earlier artifacts were neither consulted nor changed.
