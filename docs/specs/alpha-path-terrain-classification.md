## Supplied coordinate, center, and bounds

The classification begins only after the routine has selected and removed one pending coordinate and found that its three signed 32-bit components differ from the converted destination. Denote that selected coordinate by x, y, and z, in stored component order. The world receiver and actor pointer are supplied to the enclosing step. Classification reads actor binary32 sizes at `+0x80/+0x84/+0x88`, the resident-pointer exclusion set at `+0x1468`, and the three-word comparison value at `+0x1478`. It does not substitute actor current-position storage for the selected coordinate. [Evidence: `binary/Cube.exe`, RVAs `0x1AAB98–0x1AAC05`, `0x1AB659–0x1AB6B7`, `0x1ABA1F–0x1ABA56`; `decompiled/client/functions/005aaab0.c`.]

Each selected component is sign-extended and multiplied by raw `65536` through a complete 64-bit shift. The center's first and second components receive signed 64-bit `32768`. The third receives the signed 64-bit truncation of actor height promoted from binary32 to binary64, multiplied by binary64 `0.5`, then binary64 `65536`, with a separate binary64 rounding boundary at each multiplication. Height conversion occurs first; the horizontal constant is converted afterward and used on both horizontal axes. The resulting center is private storage, not an actor-position write. [Evidence: `binary/Cube.exe`, RVAs `0x1AABF7–0x1AAC83`; constants RVAs `0x345DE8`, `0x2FD588`, `0x302A88`; `decompiled/client/functions/0042c800.c`.]

Next the routine converts a binary32 offset triplet zero, zero, `0.01`; each component is multiplied by binary32 `65536`, stored as binary32, and passed through signed 64-bit conversion RVA `0x28D946`, in first/second/third order. The third raw result is exactly 655 in the ordinary finite domain. The binary32 `0.01` has bits `0x3C23D70A`, and its scaled value is exactly `655.3599853515625`. [Evidence: `binary/Cube.exe`, RVAs `0x1AAC88–0x1AACA7`, `0x02C460–0x02C49D`; `decompiled/client/functions/0042c460.c`.]

The lower raw corner is center minus converted actor half-sizes plus that offset triplet. For each corner calculation, all three half-sizes are first formed by binary32 multiplication by `0.5`, in first/second/third order. The converter then processes them in that same axis order, multiplying each by binary32 `65536`, storing binary32, and truncating to signed 64 bits. The upper raw corner is center plus independently converted actor half-sizes, without the `0.01` offset. The actor sizes are reread for the upper calculation. Stable inputs make the two sets of half-sizes equal; the native reads do not establish an atomic snapshot. [Evidence: `binary/Cube.exe`, RVAs `0x1AACAC–0x1AAD69`, `0x1AAD6E–0x1AAE05`.]

Both corners are converted to three signed 32-bit grid components by RVA `0x02F040`. That helper processes third, second, then first component, using signed 64-bit division by `65536`, retaining the low 32-bit quotient, and subtracting one more for every negative raw component. Exactly integral negative coordinates receive that subtraction too. The lower grid bounds are each decreased by one and the upper bounds each increased by one. In the following definitions, low/high always mean these expanded integer bounds, not the unexpanded actor box. Inverted bounds simply suppress the affected native loops; there is no normalization or size clamp. [Evidence: `binary/Cube.exe`, RVAs `0x02F040–0x02F0FE`, `0x1AAE05–0x1AAE51`; `decompiled/client/functions/0042f040.c`.]

The exact constants used here are binary32 half `0x3F000000`, binary32 raw scale `0x47800000`, binary64 half `0x3FE0000000000000`, binary64 raw scale `0x40F0000000000000`, and binary64 horizontal offset `0x40E0000000000000`. Integer/float conversion helper RVA `0x28D946` truncates ordinary finite representable x87 inputs toward zero. Signed division helper RVA `0x28D9E0` truncates ordinary signed division toward zero. No square-root, power, random-number, or terrain-generator call occurs in these center/bound calculations. Floating-point control and exceptional conversions remain ambient limits. [Evidence: `binary/Cube.exe`, RVAs `0x28D946–0x28D9BA`, `0x28D9E0–0x28DA87`, constants RVAs `0x345DA0/0x2FCE7C/0x345DE8/0x2FD588/0x302A88`.]

## Single cell sample and terrain traversal

After preparing the expanded bounds and clearing the low byte of every classification flag, the routine performs one cell query at the constructed center. The third raw component is reduced by the signed 64-bit conversion of binary64 `-65.536`, bits `0xC050624DD2F1A9FC` at RVA `0x31DBB0`. That conversion is -65, so the ordinary sampled raw position is center x, center y, center z plus 65. The last lookup hint is zero. The call is RVA `0x02F860` at `0x1AAF75`. It retains exactly bit 1 of returned cell byte `+3` as a separate Boolean called W below. No type-name interpretation of W is established. [Evidence: `binary/Cube.exe`, RVAs `0x1AAE5A–0x1AAF87`; `decompiled/client/functions/0042f860.c`.]

RVA `0x02F860` converts the supplied raw coordinates in third/second/first order. Before signed division by `65536`, it decreases each negative raw coordinate by another raw `65536`; the retained grid quotient is 32 bits. With the supplied zero hint it reaches resident chunk/column lookup through RVAs `0x02F7E0/0x0347A0/0x034D10/0x034A90`. A valid horizontal grid coordinate is within `0..0xFFFFFF`. Chunk coordinates are within `0..0xFFFF`, and region coordinates within `0..0x3FF`. World `+0xBC` is indexed with first region coordinate major in a 1024-by-1024 table; region `+0x10018` uses first chunk remainder major in a 64-by-64 table. Column storage at chunk `+0xA8` uses second cell remainder times 256 plus first remainder, with a 32-byte column stride. These routes return resident storage or a sentinel; no load or generation request is made. [Evidence: `decompiled/client/functions/0042f860.c`, `0042f7e0.c`, `004347a0.c`, `00434d10.c`, `00434a90.c`; corresponding native entry points.]

The subsequent terrain scan visits the expanded bounds inclusively, first component outermost, second next, third innermost, increasing each by one. It queries a cell only when at least one component lies on its expanded bound: wholly strict-interior cells are skipped. It does not terminate when a flag is set, and a previously set flag does not suppress later queries. Every queried blocking cell is tested against all applicable flag conditions below. Conditions are independent; coincident bounds can satisfy more than one of them. [Evidence: `binary/Cube.exe`, RVAs `0x1AAF91–0x1AB044`, `0x1AB0CF–0x1AB588`.]

Terrain lookup in that scan uses the resident tables directly or through RVA `0x034D10`. A column provides signed 32-bit base z at `+0x10`, entry pointer at `+0x18`, and signed 32-bit count at `+0x1C`. An in-span z reaches RVA `0x02F730` with relative index. Missing/out-of-range horizontal data, a missing computed column, or z below its base selects the missing sentinel. Above the stored span, positive z selects the upper sentinel and nonpositive z the lower sentinel. A stored type-zero cell at nonpositive z with byte `+3` bit `0x40` clear is also replaced by the lower sentinel. [Evidence: `binary/Cube.exe`, RVAs `0x1AAFF8–0x1AB0CF`; `decompiled/client/functions/0042f730.c`.]

The terrain scan uses lower/upper/missing sentinels at RVAs `0x36DDA4/0x36DDA8/0x36DDAC`. Their dedicated initializers write, respectively, four-byte values `FF FF FF 82`, `FF FF FF 00`, and `C8 C8 C8 01`. The single sample uses separate but correspondingly initialized sentinels at `0x36AFBC/0x36AFC0/0x36AFC4`. After those initializers, lower has type 2 and bit 1 set, upper has type 0 and bit 1 clear, and missing has type 1 and bit 1 clear. Classification uses only the low five bits of byte `+3`: zero and two do not contribute terrain flags; every other type does. W instead retains bit 1 regardless of the five-bit type. Initializer scheduling and other possible writers of shared sentinels are outside this audit. [Evidence: `binary/Cube.exe`, RVAs `0x2FAB60–0x2FABE7`, `0x2F9720–0x2F97A7`, `0x1AAF7A–0x1AAF81`, `0x1AB0CF–0x1AB0ED`.]

## Resident spatial entries and per-record order

After completing the terrain scan, the routine divides the expanded low and high horizontal grid bounds by eight with signed truncation toward zero. It visits every coarse pair in those inclusive ranges, first coordinate outermost, second inner. A coarse coordinate must be within `0..0x1FFFFF`. Chunk lookup receives each coarse coordinate divided by 32; object buckets at chunk `+0xAC` use second remainder times 32 plus first remainder, with an eight-byte bucket stride. Entries are followed in stored next-pointer order until the bucket sentinel. There is no sorting or deduplication across buckets. Missing chunk/bucket routes add no record flags. [Evidence: `binary/Cube.exe`, RVAs `0x1AAE2B–0x1AAE8D`, `0x1AB588–0x1AB659`, `0x1AC39B–0x1AC3DF`.]

Each entry supplies a spatial-record pointer at entry `+8` and a separate three-word tag at entry `+0x0C/+0x10/+0x14`. Before reading geometry, the record pointer is looked up in actor `+0x1468` using unsigned 32-bit comparison and exact pointer equality. A present pointer skips the entire record, including R0. No actor ID or coordinate equality is substituted for this pointer membership. The set is read here, without insertion, removal, refresh, or ownership transfer. [Evidence: `binary/Cube.exe`, RVAs `0x1AB659–0x1AB6B4`.]

An admitted record supplies signed 64-bit coordinates at `+8/+0x10/+0x18`, a signed 32-bit orientation operand at `+0x20`, and binary32 sizes at `+0x24/+0x28/+0x2C`. Odd orientation, including negative odd orientation, swaps the local first and second sizes; even orientation retains their order. All record half-sizes use binary32 size times `0.5`, then times `65536`, then signed 64-bit truncation. Record full height uses binary32 height times `65536`, then signed 64-bit truncation. Actor half-sizes are converted through the same binary32 sequence, with actor fields reread at the reached conversion points. No minimum or nonnegative clamp is applied. [Evidence: `binary/Cube.exe`, RVAs `0x1AB6B4–0x1AB7FC`, `0x1AB802–0x1AB9AA`, `0x1ABAD5–0x1AC393`.]

For each record, the following order is fixed: test the center shifted by raw minus `65536` on the third axis for R0; apply the height/terrain-flag admission below; apply selector exclusions; compare the entry's three-word tag with actor `+0x1478`; then test centers shifted on minus x, plus x, minus y, and plus y, by raw `65536` each, for R-x/R+x/R-y/R+y. The unshifted coordinates on all other axes remain the originally constructed center. These five probes are not a series of movements of that center. [Evidence: `binary/Cube.exe`, RVAs `0x1AB7AC–0x1ABA5B`, `0x1ABA5B–0x1ABCB9`, `0x1ABCB9–0x1ABF13`, `0x1ABF13–0x1AC15C`, `0x1AC15C–0x1AC399`.]

Each probe uses the following exact axis-aligned relations. On x and y, record coordinate minus converted record half-size must be less than or equal to probe coordinate plus converted actor half-size. Probe coordinate minus converted actor half-size must be strictly less than record coordinate plus converted record half-size. On z, record base must be less than or equal to probe z plus converted actor half-height, and probe z minus converted actor half-height must be strictly below record base plus converted full record height. Tests are ordered x, y, then z, and later-axis conversions are conditional on earlier overlap. RVA `0x194690` supplies signed 64-bit greater-or-equal and RVA `0x194660` signed 64-bit strictly-less, using signed high words followed by unsigned low-word comparison. These comparison helpers consume no geometry, random state, or callbacks beyond their supplied words. [Evidence: `binary/Cube.exe`, RVAs `0x1AB7AC–0x1AB9AA`, `0x1ABA5B–0x1AC393`, `0x194660–0x1946AF`; `decompiled/client/functions/00594660.c`, `00594690.c`.]

The initial x record/actor conversions and x bounds are retained for later probes. R0 conditionally converts y record/actor halves, then actor half-height, then full record height. Each subsequent horizontal probe conditionally repeats its y and z conversions in that order after its x comparisons. Repeated queries/conversions are not suppressed merely because the corresponding accumulated flag is already true. A passing probe only sets its local flag true; it does not change resident record state or actor position. [Evidence: `binary/Cube.exe`, RVAs `0x1AB6FE–0x1AB9AA`, `0x1ABA5B–0x1AC393`.]

## Admission between R0 and the four horizontal probes

R0 is tested before any selector, height-threshold, record-byte, or entry-tag exclusion. Thus an otherwise excluded selector or matching tag can still set R0 when its pointer was not in actor `+0x1468`. There is no selector exclusion on R0 and no read of record byte `+0x30` in this step's record path. [Evidence: `binary/Cube.exe`, RVAs `0x1AB6B4–0x1ABA56`.]

The height gate compares binary32 `3.0`, bits `0x40400000` at RVA `0x2FCD70`, with record full-height operand `+0x2C`. Only when 3 is ordered strictly greater than record height and all five flags U, Q-x, Q+x, Q-y, and Q+y are clear does the record skip its four horizontal probes. Equality, an ordered greater/equal record height, or any of those five flags admits the next gate. Under masked invalid-operation handling, an unordered COMISS result takes the native JBE admission branch too. The decompile's apparent unordered rejection is not the native branch. Later exceptional conversions and unmasked traps are not closed by that one comparison result. [Evidence: `binary/Cube.exe`, RVAs `0x1AB9B1–0x1AB9F0`.]

Next selectors exactly 1, 2, 8, 7, and 6 skip the horizontal probes. Selector 9 is not among these exclusions, and the gate does not require byte `+0x30` for selectors 3 or 5. Surviving entries compare three raw 32-bit words with actor `+0x1478/+0x147C/+0x1480`, in that order, stopping at the first difference. Equality of all three skips the horizontal probes. There is no validity, sign, zero, or range check on this comparison: an equal malformed triplet is still equal. These gates do not undo an already set R0. [Evidence: `binary/Cube.exe`, RVAs `0x1AB9F0–0x1ABA56`.]

## Mutation, random state, and limits

The center, corners, converted bounds, sample bit, and classification flags are private stack state. Classification itself writes no actor position, resident spatial record, actor triplet `+0x1478`, or exclusion-set member. It contains no random draw, seed access, allocation, generation request, record/model callback, or lock. Neighbor publication later mutates the search containers and update flags; upstream triplet selection can explicitly draw randomness as identified above. Resident terrain and object contents still depend on unclosed producers and their seed histories.

The cell accessor RVA `0x02F730` has defensive out-of-range branches that write shared fallback cells and initialization bits. With stable valid column count/base arithmetic, the preceding span checks supply an in-range index and those writes are not reached. Integer overflow, concurrent span replacement, or malformed storage does not inherit a general purity or normalized-result guarantee. Its direct valid-index route returns the resident four-byte entry. [Evidence: `binary/Cube.exe`, RVAs `0x02F730–0x02F7DB`, `0x1AB085–0x1AB0AD`.]

The closed ordinary domain requires valid stable actor/world/container pointers, finite representable conversion operands, nonoverflowing signed bounds and coordinate arithmetic, representable 32-bit grid quotients, and terminating resident lists. The native code adds no general validation for those assumptions. Actor sizes and record data can be reread between probes; the constructed center itself remains based on its earlier height read. There is no established snapshot, reference pin, or protection against record-vector replacement, bucket mutation, or pointer reuse. Exceptional floating-point conversions, unmasked traps, malformed dimensions/counts, imported runtime/allocator internals, upstream timing, and server behavior remain unresolved. No standard movement, shortest-route, environmental-type, or whole-frame guarantee follows from these arithmetic and admission rules.
