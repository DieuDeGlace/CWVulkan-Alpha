# Alpha actor word +0x124, mask 0x0020

Status: FINAL / STABLE / HELD after complete author readback.

This bounded original-source contract concerns the 16-bit resident word at actor `+0x124`, especially its mask `0x0020`. It establishes construction/reset writes, the generic bit-changing interface and its identified direct callers, whole-word copying and received-state publication, and selected direct readers. A native local decision that first turns this bit on from a clear actor has **not** been established. Whole-word reception can nevertheless publish either bit value supplied by its input. These are different findings.

The supported client is `binary/Cube.exe`, image base `0x00400000`, SHA-256 `84a7a132a84d4282338e7ea45a1940d32066d64e39cbafed8f2418d5a6dc30bf`. Evidence paths below are relative to `disassembled alpha cube world`; bare function filenames are under `decompiled/client/functions`. Original image instructions, `decompiled/client/assembly.txt` and the individually identified original function files are the evidence. No reconstruction, previous contract or runtime observation supplies a fact here.

## Identity and widths

C denotes an actor pointer. Its embedded data object B begins at C `+0x10`. Accordingly, B's word `+0x114` and C's word `+0x124` are the same two bytes. This displacement is established by the actor constructor's call at `0x03B6D1`, reset calls at `0x04633D` and `0x047134`, and ordinary data-copy callers. An instruction using `+0x114` must be interpreted with its actual receiver; it is not automatically a different field. [Evidence: `0043b690.c`, `00446330.c`, `00447110.c`; corresponding native call sites.]

The scoped readers test mask `0x20` in the low byte at C `+0x124`. The resident storage and the bounded reset/copy interface are 16-bit. Bits in C `+0x125` do not satisfy this test. Neither a sign interpretation of the whole word nor a conversion to a numeric magnitude is used by these readers. Bytes C `+0x126/+0x127` are not replaced by the verified word stores.

C's separate full 32-bit member `+0x5C` is not this word. For example, the original performs distinct stores to C `+0x124` and C `+0x5C` at `0x0258C1/0x0258CE` and `0x207090/0x207097`. B `+0x5C`, in turn, is C `+0x6C`, not C `+0x5C`. A mask value of `0x20` in a packet presence mask or another object is likewise not evidence that the actor's scoped bit changed.

Another excluded apparent match is the full-width store with displacement `+0x124` at `0x20E67A`: the original has already advanced its actor-derived pointer by `0x78`, so the actual destination is actor `+0x19C`. It is not an overwide write to the scoped word. [Evidence: native RVAs `0x20E669–0x20E680`.]

## Generic bit changes and the missing positive local admission

Original helper `0x02F160` receives a data-object receiver, a mask occupying a four-byte stack argument, and a Boolean option occupying the next four-byte stack argument. Only the mask's low 16 bits and the option's low byte affect this operation. A nonzero low option byte sets the selected word bits; a zero low byte clears them. Other resident word bits are preserved. For an actual actor receiver B and mask `0x0020`, this interface can selectively set or clear the scoped bit. It performs no role, kind, health, identifier, old-value or ownership test, has no nested call, and draws or seeds no random state. Its ordinary return does not define a separate useful result. [Evidence: `0042f160.c`; native RVAs `0x02F160–0x02F187`.]

Capability is not proof of an original caller that requests mask `0x0020`. A binary-level search of the supported image's `.text` found 27 direct relative calls to this exact entry. The call-site arguments were checked against original instructions, including `0x09BC31`, which is outside the recovered frame listing's complete function coverage. The identified masks are `0x0001`, `0x0004`, `0x0008`, `0x0010`, `0x0040`, `0x0080`, `0x0200` and `0x0400`; none is `0x0020` or includes that bit.

The other inspected literal-displacement word modifiers provide no selective `0x0020` producer. The sites `0x02CB79–0x02E15A`, `0x03ADDF/0x03ADEE`, `0x07E8EC`, `0x0A6E41`, `0x0C82B2–0x0C82DE`, `0x0DBF3C`, `0x18D60A`, `0x1A90DE/0x1A90ED`, `0x2194BA–0x2195A3` and `0x21F01F/0x21F034` change masks among `0x0001`, `0x0004`, `0x0010`, `0x0040` and `0x0200`; the resulting bit operation preserves `0x0020`. In particular, an AND mask that clears `0x0010` or `0x0040` does not clear `0x0020`. An equal displacement alone still does not prove an actor alias, and these observations do not substitute for an exhaustive alias-sensitive proof over all native code.

No independent timer, automatic expiry, action-name rule, ownership/faction rule or input toggle for `0x0020` is established by these call sites. A local selective transition from clear to set remains unresolved. The absence of a matching direct call does not exclude computed/indirect calls, different aliases, full-object copies or external state supplied to a decoder.

## Copying and received-state publication

The ordinary data assignment routine `0x04B040` copies the entire source word at data `+0x114` to the destination at the same displacement. Native `0x04B0F3–0x04B101` reads and writes exactly two bytes. The corresponding copy-construction routine `0x066050` performs the same word copy at `0x066102–0x066110`. Neither filters `0x0020`, combines it with the old destination word, consults actor `+0x5C`, or clears it based on role/health. A source word `0x0020` can therefore produce that word in a destination data object, while source zero can clear an already set destination. The upstream production of the source word is a separate dependency. [Evidence: `0044b040.c`, `00466050.c`; cited original instructions.]

Two original data decoders use the same data-relative word `+0x114`: the in-memory decoder `0x0CCFA0` reaches two-byte helper `0x0CBED0`; the socket decoder `0x0CD3E0` reaches two-byte helper `0x0CBF40`. On a present field and an ordinary complete input, each replaces those two bytes with the incoming raw word. On an absent field, it leaves those bytes unchanged. The mask selecting whether this field is present is a separate packet structure; it does not become the resident word. Neither reached word helper strips `0x0020`. Full packet validation and short/partial/error cases are not generalized into a successful overwrite here. [Evidence: `004ccfa0.c`, `004cd3e0.c`, `004cbed0.c`, `004cbf40.c`; native sites `0x0CD0E2–0x0CD0F7`, `0x0CD5EE–0x0CD603`, `0x0CBF1F–0x0CBF2E`, `0x0CBF6E–0x0CBFB0`.]

There is concrete resident publication, not only a detached decoder:

- In the receiver region `0x06BC52–0x06BE04`, a resident actor's B is first copied into a temporary data object. The world-related release helper is called before memory decoding at `0x06BC82`; the acquisition helper is called again before publication. The pointer comparison at `0x06BCC5` excludes an actor pointer equal to client `+0x8006D0`. Other reached valid actors receive the temporary B through `0x04B040` at `0x06BDFF`. Both locally inspected interpolation alternatives rejoin at that copy. Consequently, omission of the word preserves its snapshot value in the temporary, while a present incoming word can replace the resident actor's scoped bit. Earlier packet/identifier admission and the complete ownership of the temporary are not closed here.
- In the receiver's socket-data route, current resident B values are first copied into a temporary keyed collection at `0x06C310–0x06C331`. The decoder call at `0x06C41C` targets an entry of that collection. The later resident lookup/publication region `0x06C620–0x06C96C` likewise excludes a pointer equal to client `+0x8006D0` at `0x06C69A`; the reached other actor receives its temporary B through the word-preserving assignment at `0x06C96C`. The interpolation choices inspected here do not add a `0x0020` filter. Full message-kind dispatch, entry-removal rules, lookup-helper semantics and exceptional allocation paths remain outside this bounded publication relation.

These paths establish that an externally supplied raw data word can set or clear the bit for an admitted noncontrolled resident actor. They do not establish which native upstream peer first decided to set it. They also do not establish a received overwrite of the controlled actor through these two publication sites: the exact-pointer exclusions are explicit. They are not comparisons of stored identifiers.

The difference builder `0x0CDAA0` reaches the two-byte comparison/selection helper `0x0CB670` for data `+0x114`. The helper selects two raw source bytes when its low-byte force option is nonzero or the two words differ; equality without force omits that field. It updates packet bookkeeping, not the resident actor word. Thus raw copying and packet inclusion must not be treated as a locally derived mode rule. [Evidence: `004cdaa0.c`, `004cb670.c`; native call site `0x0CDC70–0x0CDC8F`.]

## Independently established reader effects

The two relation helpers below consume valid actor pointers and read the scoped bit without changing it. A refers to the first stack argument and B to the second; this B is an actor, not the data-object alias used above.

At `0x196CA0`, the early false cases are A's role byte `+0x60` equal to 5 with B's role equal to 0, A's role equal to 6, or B's role equal to 6. The following role-1 checks can return true before reaching the scoped word: one actor having role 1 and the other not having it, or unequal low-byte classification results from helper `0x044680` when both have role 1. If neither earlier result decides, A's `0x0020` bit is tested first; if set, the result is true without reading B's bit. Otherwise B's bit determines true versus false. There is no pointer-self rejection in this helper. The bit can therefore produce true for a valid same-pointer pair that reaches these final tests, but it cannot override the earlier role-6 false cases. [Evidence: `00596ca0.c`; complete native routine `0x196CA0–0x196D2C`.]

At `0x1988A0`, pointer equality returns false before any actor-field read. For distinct valid actors, either role byte equal to 6 returns true before the remaining checks. The role-1 comparisons then use the same classification-helper relationship, followed by the same first-actor-then-second-actor bit tests. Thus the same resident bit does not make a same-pointer pair true here. Stored identifiers are not used for that self test. The classification helper reads raw actor state including word `+0x7E` and full kind `+0x64`; assigning faction/ownership names or closing its complete classification table is outside this contract. Neither relation helper writes `+0x124`, calls a random/seed API, or consumes the bit. [Evidence: `005988a0.c`, `00444680.c`; complete native routine `0x1988A0–0x19892E`.]

Within each of two reached candidate scans in input-related helper `0x0A6B50`, a nonnull actor passes the classification gate when role byte `+0x60` is 1 **or** its low-byte `0x20` test at `+0x124` succeeds. This gate precedes the health comparison and later projection/distance/visibility work. For ordinary finite health, the following comparison admits only `+0x16C` strictly greater than zero. The bit alone does not guarantee final selection, and no word mutation occurs at these read sites. Unordered health is not rejected by the same ordered comparison branch; complete exceptional-state selection is not inferred. [Evidence: `004a6b50.c`; native RVAs `0x0A82A9–0x0A82D4` and `0x0A87B3–0x0A87DE`.]

## Lifetime, synchronization and exhaustiveness limits

The established lifetime is reset/copy based: initial data construction clears the bit; the listed whole-word resets clear it again; the verified unrelated-mask modifiers preserve it; raw data assignment or admitted received publication can replace it. The read predicates above do not consume or expire it. No stronger duration, ordinary local activation event, gameplay name or server-origin rule follows from these observations.

The short generic bit helper has no lock acquisition, interlocked operation or synchronization prefix. This does not prove its callers are unguarded. The receiver's visible world-related acquisition/release helpers are `0x201CB0/0x201E90`: they call imported `EnterCriticalSection/LeaveCriticalSection` on their receiver `+0x8000C0`. With the observed receiver at client `+0x2E4`, that identifies the critical section at client `+0x8003A4`. The locally inspected memory publication is performed after reacquisition and before release, while decoding is between the earlier release and reacquisition. Broader thread ownership, recursive acquisition state, all caller critical sections and races remain unaudited. No concurrency guarantee is supplied for an arbitrary reader racing a reset or whole-word copy. [Evidence: `00601cb0.c`, `00601e90.c`; native RVAs `0x201CB0–0x201CBD`, `0x201E90–0x201E9D` and the receiver sites above; original PE imports.]

The direct-call inventory and literal-displacement search were checked against the original image as well as the recovered listing. Upstream initialization of copied/loaded source objects, saved-character loading, all upstream packet producers, complete receiver dispatch, a server counterpart and all later behavior reached through relation results remain unclosed except for the specific boundaries stated above.
