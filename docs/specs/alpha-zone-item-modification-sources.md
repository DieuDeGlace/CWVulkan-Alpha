# Which single-player updates mark a zone's item list for saving

FINAL / STABLE / HELD

This supplement covers the original 32-bit Windows Alpha client, Cube.exe, 3,885,568 bytes, SHA-256 `84a7a132a84d4282338e7ea45a1940d32066d64e39cbafed8f2418d5a6dc30bf`. Addresses are RVAs from base `0x00400000`. The interaction dispatch and its pickup, drop and object branches were read directly from the executable, including blocks absent from the exported instruction listing.

## What sets the flag

The world update at `0x20C510` starts a fresh set of resident zone pointers at `0x20CD05`. The set uses pointer identity and admits each pointer once. At the end of the pass the client visits the set, sets each zone's byte `+0x75` to 1, then emits one snapshot containing the zone coordinates and the current resident item list, including an empty list. That loop performs no database write. The nearby-zone scan also collects pointers, but puts them in a different set for ticking. Visiting a zone does not add it to the item snapshot set. Evidence includes `0x18E7D0`, `0x19F070`, `0x20CACE–0x20CAF1`, `0x22113C–0x2211EE` and `0x0DC820`.

## Producers verified in the original image

| Path | Effect on the item snapshot set |
| --- | --- |
| Pickup, interaction 5 | In mode zero the client looks up the requested zone, checks the item index, tests the actor's eligibility, then checks distance. It inserts the zone pointer at `0x210833`, records the pickup and erases the selected resident item at `0x210940`. Picking up the last item therefore queues a snapshot with an empty list if no later action adds another item. The failure exits before insertion leave the zone unmarked by this request. |
| Drop at actor position, interaction 6 | In mode zero the client passes the requested item, actor position and the same set to the placement routine at `0x2119CC–0x211A03`. The helper appends to the destination zone at `0x19B140` and then inserts that zone pointer at `0x19B163`. A missing destination zone exits before either operation. |
| Drops from an object or defeated actor | In mode zero a type-10 object with state byte 2 can release items through `0x210DF0–0x210F65`. Each successful placement marks its actual destination through the same helper. The hit-processing route at `0x195A60` passes the set on the defeated-actor branch at `0x19622E` to the loot selector at `0x19B180`. Only loot branches that reach successful placement add a zone. Damage, an object interaction or selecting a possible drop does not alone establish membership. |

The interaction numbers come from the byte dispatch at `0x210535–0x210546` and its jump table at `0x222C20`. For pickup the index must be nonnegative and below the current item count. Category 25 additionally requires its embedded four-byte field at `+0x04` to match the actor value at `+0x1164`. Actor values above 100 use 100 plus their remainder modulo 100. Other categories pass that eligibility check. The squared three-axis distance has an inclusive limit of 16 in block units, with 65,536 fixed-position units per block. An otherwise eligible item exactly four blocks away on one axis qualifies. The pickup handler itself tests neither item countdown, the saved day nor the origin byte. Higher-level selection of a pickup request is outside this finding. Evidence includes `0x03E550`, `0x024860`, `0x02C4A0` and `0x210746–0x210833`.

## Updates with separate effects

- **Item timers.** For each visited item, a positive resident `+0x140` counts down by the update delta and clamps a negative result to zero. A positive `+0x13C` counts down next. When it reaches or passes zero it is set to zero and, in mode zero, emits a positional event of type 58 for category 12 or 59 otherwise. Neither countdown marks the zone, erases the item or updates its saved day. The subsequent erase loop has a separately initialized collection. These countdown branches supply it no entries. A timer change can still appear in a snapshot or row when another cause marks the zone. Evidence includes `0x20CEE2–0x20CF53` and `0x20D1C9–0x20D369`.
- **Object state.** The ordinary mode-zero toggle in interaction 3 changes the state at object `+0x30` for types 1, 2, 3, 9 and 10, and emits an object update. The matching output pass resolves the coordinates and sets zone byte `+0x76`. The toggle and object-update pass do not set `+0x75`. A type-10 interaction can also place loot as described above. A different operation that appends to zone collection `+0x3C` sends the zone through a separate set and snapshot with no `+0x75` store. Evidence includes `0x1A58E0`, `0x210FD4–0x211029`, `0x21195F–0x2119B5` and `0x2211F0–0x22134B`.
- **Terrain edits.** The terrain action can queue a 20-byte modification carrying the current world day at `0x211755–0x2117A6`. The end-of-pass terrain consumer resolves each record's zone from its block coordinates and appends the modification to resident `+0x68` if that zone exists. This consumer neither inserts into the item set nor sets the item flag. On unload a nonempty modification list independently qualifies the zone for a row write. With `+0x75` clear, that row records item count zero even when resident items exist. Evidence includes `0x22134B–0x2213E6`, `0x1A4890`, `0x1A5050` and `0x04E340`.

## Persistence boundary

Single-player unload consults the flag already on the zone. It does not infer an item change from elapsed timers, an object event, the separate `+0x76` flag or an object overlay. With a nonempty save name, a valid zone, `+0x75` clear and no terrain modifications, the ordinary writer skips the row. With `+0x75` set it writes all current resident items. The saved-row decoder has its own verified flag store at `0x04D0BF` when the admitted and resident lists differ. For the zone's existing pointer collection at `+0x18`, the saved-row decoder restores object fields `+0x38` and `+0x3C` on a matching count. It likewise restores the `+0x30` state byte in the `+0x0C` collection on a matching count. Neither overlay sets the item flag at `0x04D305–0x04D42B`. If the row qualifies for a separate reason, the writer includes both overlays.

These findings identify direct membership for the traced interaction and loot handlers. They do not enumerate all upstream causes of requests, membership supplied to shared helpers by other callers, every mutation of resident static-object fields, or concurrent causes in the same pass. A failed pickup leaves an existing flag intact. A successful pickup and drop in the same zone and pass produce one item snapshot containing the final list.
