# Alpha descriptor activation refresh and its indexed context

Status: FINAL / STABLE / HELD after complete author readback.

This original-source-only contract covers the bounded descriptor activation route in client world routine RVA `0x20C510`, particularly context acquisition at `0x20FB48–0x20FB94` and refresh at `0x20FCFE–0x20FD4A`. It identifies the context's actual storage and lookup inputs, selected concrete producers/copies/resets of its four relevant fields, refresh admission and ordering, the full-width descriptor-role exception, and related descriptor/actor flag effects through this activation's ordinary continuation. Numeric naming is retained where a gameplay interpretation has not been established.

The supported original image is `binary/Cube.exe`, image base `0x00400000`, SHA-256 `84a7a132a84d4282338e7ea45a1940d32066d64e39cbafed8f2418d5a6dc30bf`. Evidence paths below are relative to `disassembled alpha cube world`; function filenames without a directory prefix are under `decompiled/client/functions`. Native RVAs refer to that image; original instruction bytes were compared with `decompiled/client/assembly.txt` for the scoped lookup, record construction/producer, activation and copy regions. Individually identified original function files provide additional anchors. No earlier contract, reconstruction, replacement implementation or runtime observation was used as evidence.

## Which object supplies the context

Below, **W** is the world receiver, **P** is the reached cell object whose descriptor-pointer collection begins at `+0x18`, **D** is an individual descriptor pointer from that collection, **M** is a parent object returned from W's indexed pointer table, and **C** is the context record embedded in M. P and C are different objects. C is acquired once for the reached P before its descriptor loop, after the preceding work on P's separate `+0x24` collection. The pointer is cached locally and reused for the descriptor entries; it is not independently acquired from each D's position. [Evidence: native RVAs `0x20FB2D–0x20FBBB`.]

The acquisition reads the full signed 32-bit component at P `+0x64` first and divides it by 8 with truncation toward zero. It then reads P `+0x60` and performs the same signed division. The resulting ordered X/Y argument pair is passed to `0x087DA0` on W. There is no fixed-point division by 65,536, floating conversion, position subtraction or negative extra decrement in this acquisition. P's stored integer pair is the query input; D's raw 64-bit position at `+0x10/+0x18/+0x20`, D's other stored indices, and the not-yet-created actor's cached coordinates do not supply this lookup key. [Evidence: native RVAs `0x20FB48–0x20FB87`; component accessor `0x028970`.]

Getter `0x087DA0` accepts each divided argument only in the signed interval `[0,8192)`. With valid inputs, it multiplies each by 8 and divides by 64 with signed truncation toward zero, in Y-then-X computation order. Because the admitted values are nonnegative and bounded, these latter results equal ordinary integer division of the divided arguments by 8, without overflow. It calls parent lookup `0x034A90` on W with that X/Y pair. That helper admits parent indices `[0,1024)` and reads the pointer at W `+0xBC`, indexed with X as the outer component and Y as the inner component of a 1024-by-1024 table. A null parent gives a null C. Neither lookup allocates, loads nor generates an absent parent.

For a nonnull M, C is an embedded record at M `+0x14018`, advanced by `0x68` bytes for each record index. The record index is eight times the divided X argument's remainder by 8, plus the divided Y argument's remainder by 8. Thus there are 64 such records in X-major/Y-minor storage order. The getter returns the record address itself, not a pointer loaded from a per-record slot. Parent constructor `0x1C3AC0`, whose native vtable identity is RVA `0x31DCCC`, initializes exactly 64 records at that base using constructor `0x1C3BB0`, advancing by `0x68` each time. These observations establish storage identity without importing a semantic region/quest label. [Evidence: `decompiled/client/functions/00487da0.c`, `005c3ac0.c`, `005c3bb0.c`; native RVAs `0x087DA0–0x087E22`, `0x034A90–0x034AC3`, `0x1C3B0F–0x1C3B2B`.]

The first signed division is material at exceptional ordinary integer inputs: P components -1 through -7 divide to zero and can reach the zero-index record, whereas -8 divides to -1 and is rejected. P component 65,535 divides to 8,191 and is admitted by the getter; 65,536 divides to 8,192 and is rejected. This describes the native conversion boundary, not a claim that P's construction normally produces negative coordinates. P's coordinate producers, the earlier local cell-set membership and the complete world distribution remain outside this acquisition closure.

## Relevant context fields and concrete producer boundaries

| C-relative storage | Width and established use here |
| --- | --- |
| `+0x30` | Full 32-bit value; copied without conversion into the later wrapping seed sum. |
| `+0x34` | Full 32-bit selector compared with exact value 5, without low-byte narrowing. |
| `+0x3C` | Full 32-bit value copied to D `+0x34`, except for exact full-width role 6; its low 16 bits are also used by the nested record refresh. |
| `+0x40` | Byte copied to D `+0x58`, with the same role exception; also read separately for nested record-byte construction. |

Record constructor `0x1C3BB0` stores zero 32-bit values at C `+0x30`, `+0x34` and `+0x3C`, and zeroes the 16-bit word beginning at `+0x40`, including the relevant byte. The requested stores occur in that order, with other record-field stores interleaved. The constructor itself is a leaf containing no random or seed call. Fresh C therefore fails the exact-5 refresh test until another producer changes its selector. [Evidence: native RVAs `0x1C3C03–0x1C3C1F`.]

A concrete native state producer is the common commit stage of `0x1D8750`. Its record address uses the same parent-table and `0x68`-record indexing relation, with its own supplied integer X/Y inputs. At the reached preparation stage it first sets C `+0x34` to zero and clears separate members `+0x41`, `+0x44` and `+0x48`. If full C `+0x18` equals 10, it leaves that preparation stage without reaching the later common commit; this does not reset the other three requested fields. For other values, its temporary selector candidates are `[1]` when `+0x18` is zero, `[9,3,4]` when it is 1, and `[5]` for the other reached nonzero values, including 14. A direct `rand` call selects by unsigned remainder over this temporary collection, including a draw when its size is one. These are producer input/output relations, not inferred meanings of C `+0x18`. [Evidence: `decompiled/client/functions/005d8750.c`; native RVAs `0x1D8AEA–0x1D8C9D`.]

After that selection, this producer scans W's actor map. It admits nonnull mapped actor pointers with discriminator byte `+0x60` equal to zero, without an additional direct health or identifier test in this scan. For the value later stored at C `+0x3C`, a signed 32-bit accumulator starts at zero and reads each admitted actor's full signed `+0x190`. It replaces the accumulator when the accumulator is zero or is signed-less than that newly read value. With ordinary positive values this supplies their maximum; no admitted values leave zero. The zero-sentinel replacement rule is retained for mixed zero/negative values rather than silently replacing it with a mathematical maximum over every signed input. Exact actor-map traversal and the complete preceding cleanup/generation work of this routine remain separate dependencies. [Evidence: native RVAs `0x1D8CC4–0x1D8D94`.]

When execution reaches the common commit at `0x1D9319`, the requested writes are ordered: obtain a fresh imported `rand` result and store its full 32 bits at C `+0x30`; copy the low byte of existing C `+0x28` to C `+0x40`; copy the captured accumulator to C `+0x3C`; then store the selected full 32-bit selector at C `+0x34`. Additional type-dependent work and draws can occur between initial selector selection and this common commit. This document does not promise that all calls reach the commit or supply a total draw count for that intervening work. C `+0x28`'s complete upstream production is also unclosed. The routine subsequently gathers the context payload into an output record; the field stores precede that publication, rather than being delayed until a receiver applies the record. [Evidence: native RVAs `0x1D9319–0x1D938A`.]

Another concrete replacement boundary is the client-frame consumer of pending entries at client `+0x800690`. It reads the entry's full 32-bit X/Y coordinates at `+0/+4` and passes them directly to `0x087DA0` on the embedded world, without the division by 8 used for P above. If C is nonnull, helper `0x068620` copies the payload beginning at entry `+0x10` into C `+0x2C`. Consequently entry `+0x14` replaces C `+0x30` as 32 bits, entry `+0x18` replaces C `+0x34` as 32 bits, entry `+0x20` replaces C `+0x3C` as 32 bits, and entry byte `+0x24` replaces C byte `+0x40`. The helper copies the five successive 32-bit payload fields first, then its two bytes, then its remaining 32-bit fields. There is no clamp, exact-5 admission or random call in this copy. A missing C skips the copy; the pending entry is still removed on the inspected continuation. Complete queue producers, transport, short-record handling and receiver authority are not inferred here. [Evidence: native RVAs `0x08FDC3–0x08FEC7`, helper `0x068620–0x06866B`; original file `00468620.c`.]

A reached reset loop inside `0x06FC50` visits existing parent pointers through `0x034A90` and their 64 context records. It zeroes these same requested fields: C `+0x30`, then `+0x34`, then `+0x3C`, then the 16-bit word at `+0x40`, with other payload members interleaved. This is a further explicit zero producer; the complete connection/startup admission to that loop is not reconstructed here. The constructor, common commit, pending-entry copy and this reset are concrete audited producer families, not an exhaustive proof excluding every alias-based or generator writer. In particular, `+0x30` is not guaranteed always to retain a fresh random result, and `+0x34` need not remain 5. [Evidence: `decompiled/client/functions/0046fc50.c`; native RVAs `0x070410–0x07053D`, specifically `0x070440–0x070462`.]

## Admission to this activation and refresh

The descriptor phase reached at `0x20F942` requires W byte `+0xB4` to be zero and the 32-bit count at W `+0xA4` to be nonzero. It iterates a previously assembled local set of P pointers; this document does not supply that set's full construction rules. P's context query occurs before the signed count check of P's descriptor collection. The collection is visited by increasing index, and its current count is queried again at the loop continuation. No snapshot of every descriptor or context value is established by that iteration. [Evidence: native RVAs `0x20F942–0x20F9BA`, `0x20FB48–0x20FBBB`, `0x210433–0x210453`; count predicate `0x077220`.]

For each D, equal full 32-bit bounds at D `+0x40/+0x44` bypass both world-value queries. Otherwise the routine reads W `+0x80015C` through `0x071910` and rejects a signed result below D `+0x40`; only if that passes does it query the same world member again and reject a result above D `+0x44`. Equality at either bound is admitted. The two queries are not merged into one assumed value.

Next, the full 64-bit identifier at D `+0x48` is looked up in W's actor map through `0x02F000`. A nonnull mapped actor skips this D. A missing entry or null mapped pointer admits the remaining checks; no separate zero-identifier exception appears in this lookup. Negative signed D `+0x38` is then clamped to zero. For positive D `+0x38` only, equality of full D `+0x3C` with W `+0x800160` skips this D; zero, including a just-clamped negative value, bypasses that equality test. The scoped sequence does not reduce `+0x38` by the update amount. [Evidence: native RVAs `0x20FBC1–0x20FC29`; original helper `0x02F000`.]

A preceding local actor-pointer collection must contain an entry within D's distance admission. For each reached entry, its actor position at `+0x10` minus D's position at `+0x10` is formed as three signed 64-bit fixed-point components with 64-bit wrap. `0x02C4A0` converts X/Y/Z separately through signed-integer-to-binary32 stores and then binary32 multiplication by `2^-16`. `0x024860` squares each component in binary32, adds X-square and Y-square, then Z-square, and returns the rounded binary32 result through x87; the caller stores it as binary32 again. D's binary32 `+8` is squared in binary32. A strict radius-square greater than the distance measure admits the first qualifying entry; equality does not admit it. If no entry qualifies, the descriptor is skipped. The collection's complete membership and broader actor eligibility remain unclosed; no visibility or relationship test is invented for this distance boundary. These arithmetic statements concern ordinary finite values and valid pointers. [Evidence: native RVAs `0x20FC29–0x20FCF9`; helpers `0x02C7A0`, `0x02C4A0`, `0x024860`.]

Only after that admission does the refresh itself test the cached C pointer. Refresh requires C nonnull, full 32-bit C `+0x34` exactly 5, and 16-bit descriptor word `+0x7A` containing mask `0x1000`. Failure of any refresh test goes directly toward actor construction with D's existing state; it does not reject an otherwise admitted actor activation. For example, full C selector `0x105` fails the exact-5 test despite its low byte. [Evidence: native RVAs `0x20FCFE–0x20FD19`, target `0x20FFBA`.]

## Descriptor changes, seed and setup order

For a successful refresh, D's full 32-bit role at `+0x28` is compared with exact value 6. Every other full-width value causes a full 32-bit copy from C `+0x3C` to D `+0x34`, followed by a byte copy from C `+0x40` to D `+0x58`. Exact role 6 skips only those two copies. In particular, a value with low byte 6 and nonzero upper bytes is not exempt from those copies.

The routine next reads the full 32 bits at C `+0x30`, adds the low 32-bit half of D's identifier `+0x48` with 32-bit wrap, and calls imported `srand` with that complete result. No signed clamp, zero substitute, high identifier half or actor position contributes to this sum. It then invokes setup `0x1C7730` with D and full second argument 1. The role-6 exception does not skip the seed or setup call. Setup's return value is not used for another admission test; the caller immediately rereads D's word at `+0x7A`. [Evidence: native RVAs `0x20FD1F–0x20FD4F`.]

Setup is a mutation boundary. Its low-byte-nonzero second argument skips its later stat/setup phase and the mask-`0x0200` action-selection/random-scalar phase, but its earlier equipment/classification branch can still change D. The generic route still reaches six direct `rand` calls, storing their full 32-bit results at D `+0x7B4`, `+0x8CC`, `+0x69C`, `+0x354`, `+0x584`, then `+0x46C`. Its early word-mask-`0x0040` return reaches none of those draws; special bytes `0x80..0x89` at D `+0x30` take a separate returning path, with one direct draw for byte `0x88` and none for the others. The complete earlier generic equipment branch can have additional draws and is not expanded here. For the reached ordinary full kind-`0x75` at D `+0x2C`, with D role not 6 and word mask `0x0018` clear, its early branch appends full 32-bit value 92 to the collection at D `+0x10AC`, then stores full 32-bit 0 at D `+0x10B8` and appends full 32-bit candidates 17, then 96, at D `+0x10BC`, despite the setup argument being 1. Existing entries are retained. Before the argument gate, the generic route also copies D's low 16 bits at `+0x34` to item words at `+0x8D8` and `+0x7C0`, in that order. These are original side effects before actor construction, not a pure stat query or reinitialization of a fresh descriptor. [Evidence: original file `005c7730.c`; native RVAs `0x1C7758–0x1C7882`, `0x1C7E1F–0x1C7E3B`, `0x1C81A6–0x1C8260`.]

The supported image imports `rand` from `MSVCR110.dll` at IAT RVA `0x2FC468` and `srand` from the same DLL at IAT RVA `0x2FC4B4`. The activation seed call occurs before setup's draws, the item adjustment calls below, and the later nested-record draws. There is no intervening direct seed call in the inspected continuation through actor construction. No saved-state restoration is established by this local sequence. This does not define the runtime RNG algorithm, ambient thread state, earlier world seeds or a total draw count across unclosed callbacks. [Evidence: `binary/Cube.exe` PE imports and native activation call sites.]

## Later refresh mutations and flag precedence

After setup, a set mask `0x0200` in D word `+0x7A` skips nine item-adjustment calls. On that set-bit route, byte D `+0x10E8` being nonzero additionally ORs mask `0x2000` into the same 16-bit word. A zero byte does not clear an existing `0x2000`. If mask `0x0200` is clear, the caller likewise does not clear `0x2000`; instead it invokes `0x0C7E80` on the records at D offsets `+0x8C8`, `+0x7B0`, `+0x698`, `+0x350`, `+0x580`, `+0x468`, `+0x238`, `+0x9E0`, then `+0xAF8`, in that order. Every call receives binary32 `0.05` with bits `0x3D4CCCCD` and a zero byte option. Role 6 has no exception from this stage. [Evidence: native RVAs `0x20FD4F–0x20FE32`.]

For these specific zero-option item adjustments, the item-relative 16-bit member `+0x10` is interpreted as signed. Values below 2 return without a write or draw. Otherwise helper `0x03CA60` converts its binary32 input by, in order, subtracting 1, multiplying by binary32 `0.05`, adding 1, dividing binary32 1 by that result, and subtracting the quotient from 1. Each arithmetic operation rounds to binary32. The adjustment subtracts binary32 `0.05` from that rounded result. A nonpositive ordinary result stores item word 1 with no draw. A positive result passes through `0x0462F0`: subtract the input from 1, divide 1 by that result, subtract 1, multiply by 20, then add 1, with binary32 rounding after each operation. Its result is truncated to signed 32 bits and lower-clamped to 1. One direct `rand` then selects by signed remainder over the inclusive integer span from that lower bound through the original signed item word; the chosen low 16 bits are stored. The nonzero-option upper-expansion branch is not reached here. These two numeric helpers are leaves with no random/seed calls. Invalid conversion, nonpositive divisor and floating-point exceptional cases are not repaired by this contract. Consequently each of the nine calls contributes zero or one ordinary direct draw, in the stated record order. [Evidence: original files `004c7e80.c`, `0043ca60.c`, `004462f0.c`; native RVAs `0x0C7E80–0x0C7F5C`, including the original shared tail, `0x03CA60–0x03CA94`, `0x0462F0–0x046323`.]

The routes then meet at D's nested collection at `+0xF6C`. Its outer headers are visited in increasing storage order at stride `0x0C`; each inner collection is visited in increasing record order at stride `0x11C`. An inner record with full 32-bit first member zero is left unchanged. For other records, predicate `0x034870` examines the item beginning at record `+4`; it rejects first-byte values 0, 12, 13, 20, 21, 23, 24 and 25, and also rejects first-byte 11 unless the following byte equals 14. A rejected record has no following context-derived writes in this loop.

For an admitted record, the low 16 bits of C `+0x3C` are copied to record `+0x14` first. If the item first byte at record `+4` is one of 3, 4, 5, 6, 7, 8 or 9, record byte `+0x10` is then set to C byte `+0x40` plus 1 with byte wrap. A first direct `rand` draw whose signed remainder by 20 is zero increments that byte with wrap. A second direct draw whose signed remainder by 100 is zero increments it again with wrap. Both draws occur even if the first test fails. Only after both tests is the resulting byte compared unsigned with 4 and replaced by 4 if greater. There is no earlier clamp of C's byte: for example, `0xFF` plus 1 wraps to zero before the draws. Admitted other item kinds receive the 16-bit copy but no two-draw byte update. Neither a negative nonzero first member nor full role 6 adds another rejection at this loop. [Evidence: native RVAs `0x20FE32–0x20FFB4`; predicate `0x034870–0x0348A1`, iterator steps `0x068DB0` and `0x02C720`.]

## Construction copies, persistence and later flag use

All the reached refresh writes above mutate the original D object obtained from P's descriptor collection. They occur before allocation of the separate `0x1E60`-byte actor at `0x20FFBA` and its constructor call at `0x20FFDB`. The descriptor is not consumed or erased by the inspected activation loop. The ordinary successful continuation does not restore its old fields after copying them to the actor. Allocation/constructor failure and exception unwinding are not given a rollback or lifetime guarantee here. [Evidence: native RVAs `0x20FFB4–0x21000E`, `0x210433–0x210453`.]

The new actor pointer is placed in W's actor map under D's full identifier before the following state copies. Among the relevant copies, D full `+0x34` becomes actor full `+0x190`, D byte `+0x28` becomes actor byte `+0x60`, D byte `+0x58` becomes actor byte `+0x1A8`, and the appearance copy from D `+0x74` to actor `+0x78` copies D's 16-bit word `+0x7A` into actor `+0x7E`. Thus exact full-width role 6 preserves the descriptor's existing `+0x34/+0x58` for these actor copies, while its nested item records can nevertheless have received the context writes above. The descriptor-role comparison is not interchangeable with the later low-byte actor discriminator. [Evidence: native RVAs `0x20FFF2–0x210059`; appearance assignment `0x059800`.]

Within the inspected direct activation sequence, mask `0x1000` is a refresh test and is not cleared afterward. Mask `0x0200` controls the post-setup branch and is tested again after the actor's later setup/amount query; if set then, helper `0x012780` multiplies actor binary32 components `+0x80`, `+0x84` and `+0x88` by 2.0, in component order with separate binary32 stores. This changes the actor's copied appearance components, not the descriptor's stored components or its flag word. Mask `0x2000` has only the conditional descriptor OR described above in this direct route; all other descriptor word bits survive that OR. There is no direct automatic clearing of these masks because C is missing, changes selector, or D's byte `+0x10E8` is zero. No absence-of-effect claim is extended to unaudited virtual cloning or other transitive behavior callbacks. [Evidence: native RVAs `0x20FD4F–0x20FD70`, `0x2103B8–0x2103E3`; scalar-vector helper `0x012780–0x0127B3`.]

After later actor placement/setup, the cached C pointer is restored locally at `0x21042D` and the next descriptor index is advanced. The lookup is not recomputed from the newly created actor or each descriptor's position in this loop. C's address is reused, but its fields are read separately at their stated use sites; this is not proof of a frozen context-value snapshot, synchronization, or parent storage lifetime under concurrent change.

## Explicit limits

The closed identity is an embedded `0x68`-byte record selected from P's integer `+0x60/+0x64` pair through the exact truncation and parent-table chain above. Its requested fields have concrete zero, random/captured-state, pending-entry copy and reset producers. Their complete earlier generation, C `+0x18/+0x28` production, every alias-based writer, P's coordinate and local-set producers, and descriptor masks/byte `+0x10E8` production remain unresolved outside those bounded families.

The contract does not establish world population distribution, an exhaustive actor-admission policy, message transport or receiver authority, short-record safety, every setup mutation/draw, complete actor construction or virtual behavior cloning, exceptional numerical recovery, concurrency, parent/descriptor lifetime beyond the reached ordinary accesses, or a server counterpart. Those gaps do not change the proven distinction between context acquisition, optional refresh and subsequent actor construction. No faction, quest, duration, timer or semantic region label is inferred from the numeric record fields.
