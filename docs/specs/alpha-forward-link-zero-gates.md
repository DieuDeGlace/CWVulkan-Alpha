# Forward-link zero gates in the original world update

This independent contract covers the selected role-zero actors in original client world routine RVA 0x20C510, particularly RVAs 0x20E419–0x20EB15. The supported image is `binary/Cube.exe`, SHA-256 `84a7a132a84d4282338e7ea45a1940d32066d64e39cbafed8f2418d5a6dc30bf`, image base 0x00400000. All addresses below are RVAs. Evidence paths are relative to `Documents/disassembled alpha cube world`. The original image, its instruction listing and individually identified original function exports are the sole evidence; no earlier contract or replacement implementation was read.

The category-specific maintenance has different zero rules. For category 0x13, numeric zero bypasses the two direct forward-link lookups in that maintenance and admits recovery or creation. For other categories, the maintenance performs the forward lookup even for numeric zero and can directly set the mapped key-zero actor's health to zero. A subsequent pass also performs forward lookups without a numeric-zero guard. These statements concern concrete routes and do not equate zero with a missing map entry.

## Inputs and gates

For selected actor A, the forward identifier F comprises two 32-bit words at A+0x11C8 and A+0x11CC. Each explicit numeric-zero test combines both words: F is zero only when both are zero. A low word of zero with a nonzero high word follows the nonzero route. A's own identifier is the separate eight bytes at +0x08/+0x0C. A candidate linked actor's reverse owner identifier is stored at +0x198/+0x19C. The item-category decision reads exactly one byte at A+0x1020. The role used for initial selection is exactly the byte at A+0x60, without a character-class or specialization interpretation. [Evidence: `decompiled/client/assembly.txt`, RVA 0x20CA3D–0x20CA50, 0x20E483–0x20E4A4, 0x20E512–0x20E52E.]

The initial creature-map traversal skips null actor pointers. It collects actor pointers whose role byte is zero into a temporary collection at RVA 0x20CA49–0x20CA50. That selection itself does not require a nonzero own ID, nonzero forward ID or positive health. The later category pass uses the saved pointers and does not re-test the role byte at its entry. Lifetimes and changes between these stages remain separate validity requirements. [Evidence: `decompiled/client/assembly.txt`, RVA 0x20C8E1–0x20C903, 0x20CA3D–0x20CA55; `decompiled/client/functions/004860b0.c`.]

The category maintenance is on the world-byte +0xB4 zero route. With that byte nonzero, the preceding alternate map pass finishes by jumping to RVA 0x20F942, bypassing the category maintenance and the later pass at 0x20EA07. On the zero route, helper RVA 0x077220 is called on world+0x94. It reads the 32-bit word at its input+0x10, hence world+0xA4, and returns true exactly when that word is zero. True skips the category pass to 0x20EA07. A nonzero word allows iteration of the selected temporary collection; an empty selected collection also skips to 0x20EA07. The world+0x94 collection's wider purpose is not named here. Its zero test is not evidence of a pause or elapsed-time condition. [Evidence: `decompiled/client/assembly.txt`, RVA 0x20DDEB–0x20DE24, 0x20DE90–0x20DEB6, 0x20E419–0x20E464; `decompiled/client/functions/00477220.c`.]

Lookup RVA 0x02F000 accepts the supplied eight-byte key without a numeric-zero rejection. It searches the creature map at world+0x04 through RVA 0x077D90. It returns zero when no equal entry exists and otherwise returns the entry's actor pointer, which may itself be null. Thus an absent key and an existing key with a null value both produce a null result to these callers. An equal key of eight zero bytes with a non-null actor pointer resolves normally. A creature's own ID is not consulted by this lookup. [Evidence: supported `binary/Cube.exe`, RVA 0x02F000–0x02F027; `decompiled/client/functions/0042f000.c`, `00477d90.c`.]

## Category 0x13: guarded lookup, recovery, then creation

At RVA 0x20E492–0x20E4B4, the first forward-ID test precedes the lookup. If F is zero, the lookup is bypassed, including any possible map entry with key zero. If F is nonzero, it is looked up; only a non-null result bypasses recovery. A missing entry or null mapped value takes recovery just as an initially zero F does. This gate does not test the resolved actor's role, health or reverse identifier. [Evidence: supported `binary/Cube.exe`; `decompiled/client/assembly.txt`, RVA 0x20E492–0x20E4C7.]

Recovery first clears F, low word then high word, and scans the creature map in its iteration order. It considers non-null actors B with role byte 5 and compares B's reverse owner ID directly against A's own ID, word for word. No nonzero requirement is imposed on either of those compared identifiers. In particular, reverse owner ID zero can match A's own ID zero. It cannot match a nonzero A own ID merely because A's forward ID is zero. The first matching B contributes B's own ID to F, low word then high word. The map entry key containing B is not copied to F. [Evidence: `decompiled/client/assembly.txt`, RVA 0x20E4BA–0x20E580.]

The recovery scan can inspect an actor in map entry zero because it is an enumeration, not a lookup by F. Conversely, a recovered B whose own ID is zero makes F remain numerically zero even if B was held under some other map key. Neither outcome changes the numeric test used by the next stage. Own-ID/map-key agreement is not enforced by this recovery. [Evidence: `decompiled/client/assembly.txt`, RVA 0x20E500–0x20E52E, 0x20E564–0x20E580; map-data helper `decompiled/client/functions/00468c90.c`.]

At RVA 0x20E586–0x20E5B6, the refresh marker is cleared and F is tested again. Zero again bypasses the direct forward lookup. A nonzero F is looked up a second time; a null result skips the linked-actor refresh. Thus initial zero followed by a recovered nonzero own ID can lead to a forward lookup, but an unrecovered or recovered-zero F cannot resolve map key zero through this stage. The second lookup also exposes a possible mismatch: recovery can copy B's own nonzero ID even though only another entry key actually contains B. [Evidence: supported `binary/Cube.exe`; `decompiled/client/assembly.txt`, RVA 0x20E586–0x20E5B6.]

For a nonzero F resolving to a non-null actor, changed cached inputs can cause a reset and rebuild of that actor. The refresh marker is set before the reset. This dependent refresh has its own item/numeric helpers and is not the zero-ID clearing/health-store route used by other categories. Whether refresh occurs or is skipped, the routine then updates A's +0x1D44 snapshot and copies the item into A+0x1D48 before considering creation. [Evidence: `decompiled/client/assembly.txt`, RVA 0x20E5BC–0x20E6DA.]

Creation is considered only after those snapshots. A set refresh marker suppresses it. Otherwise the routine re-reads F and suppresses creation if either word is nonzero. Only a still-zero F proceeds to the byte-at-A+0x124 bit-0x10 gate; a set bit suppresses creation, while a clear bit admits the creation branch. Zero does not suppress creation merely because a non-null map entry zero already exists. There is no direct lookup of F = zero between these gates and creation. [Evidence: `decompiled/client/assembly.txt`, RVA 0x20E6DF–0x20E70D.]

The creation branch starts its candidate ID at eight-byte zero, scans keys of entries with non-null actor pointers, retains the least key below the candidate under signed high-word/unsigned low-word ordering, and subtracts one with 64-bit wraparound. A zero key does not lower the initial zero candidate. The resulting ID is nonzero under this arithmetic, including the wrap from the least signed 64-bit key. The new ID is written into A's forward field before allocation, construction and map insertion. On the successful path it supplies both the new actor's own ID and its insertion key. The new actor is reset, receives A's own ID as its reverse owner ID and role byte 5, then receives position, numeric and behavior configuration. Allocation/collision failure behavior is not closed here. [Evidence: `decompiled/client/assembly.txt`, RVA 0x20E70D–0x20E894.]

The subsequent configuration call at RVA 0x20E8FC supplies A's own identifier to helper RVA 0x1EE7A0. This is a different key from F. That helper's owner lookup has no numeric-zero rejection. Therefore A own ID zero can cause an independent lookup of map key zero after creation, even though the direct forward-zero lookups were bypassed. On an admitted owner lookup, the helper writes the new actor's own ID to the resolved owner's forward field. It does not use that owner lookup to perform the other-category direct health-zero store. The helper's nested configuration is not a whole-world health or identity guarantee. [Evidence: `decompiled/client/assembly.txt`, RVA 0x20E8E8–0x20E8FC, 0x1EE99A–0x1EEA19; `decompiled/client/functions/005ee7a0.c`.]

## Other categories: lookup before clearing

When the category byte differs from 0x13, the branch at RVA 0x20E906 immediately passes the address of F to RVA 0x02F000. There is no low/high OR test before this call. Numeric F = zero therefore can resolve a non-null actor B held at map key zero. This lookup depends on the entry key, regardless of B's own ID or reverse owner ID. [Evidence: supported `binary/Cube.exe`; `decompiled/client/assembly.txt`, RVA 0x20E483–0x20E48C, 0x20E906–0x20E91B.]

With a non-null B, the routine scans the resident collection beginning at B+0x1178. Any record whose first byte equals 7 exits this maintenance branch without clearing F and without the health-zero store. The inspected retention test imposes no scalar, duration, embedded-owner-ID or source-ID comparison on that resident record. It is sufficient for the selector byte to occur. This can retain a numerically zero F after a successful key-zero lookup. [Evidence: `decompiled/client/assembly.txt`, RVA 0x20E921–0x20E993.]

If lookup returned null, or if the non-null B has no resident selector-7 record, the routine clears A's low forward word and then its high forward word. It then tests the saved lookup result. If B was non-null, it writes the 32-bit zero bit pattern to B+0x16C, the health field, without calling generic hit or fatal resolution. There is no positive-health check, role check, own-ID check, reverse-ID check or B-versus-A pointer exclusion before that store. Consequently F = zero can directly zero the health of a non-null mapped key-zero actor, including A itself if that map entry points to A, when no resident selector-7 record retains the branch. [Evidence: supported `binary/Cube.exe`; `decompiled/client/assembly.txt`, RVA 0x20E995–0x20E9C5.]

An absent key zero and an existing null-valued key zero both cause only the clearing of F at this boundary; the saved null result skips the health store. This other-category route performs no recovery scan and creates no replacement linked actor. It also does not use A's own ID or B's reverse owner ID to decide whether zero is looked up. [Evidence: `decompiled/client/assembly.txt`, RVA 0x20E906–0x20E9CD.]

## Later forward and reverse lookups

The subsequent pass beginning at RVA 0x20EA07 is reached even when the world+0x94 count gate skipped category maintenance. It traverses the creature map, skips null actor pointers, and looks up each actor's current forward ID at RVA 0x20EA65 without a numeric-zero test. This occurs before the designated-actor pointer check against world+0xB8 and before the item-category check. Thus category 0x13 with a still-zero F can resolve map key zero in this later pass. If A is the designated actor, the result is non-null and category is 0x13, the routine copies the result's low 16 bits of level at +0x190 to A+0x1030 and its 32-bit value at +0x194 to A+0x1024. This portion does not write the forward result's health. [Evidence: `decompiled/client/assembly.txt`, RVA 0x20EA07–0x20EAA9.]

The same pass then considers actors whose current role byte is 5. It looks up their reverse owner ID at +0x198/+0x19C without a numeric-zero guard. A reverse ID of zero can therefore resolve map key zero. If a non-null owner resolves but its forward ID differs from the role-5 actor's own ID, the role-5 actor is reset, its health becomes zero, its role becomes 3 and its reverse ID is cleared. This is a health mutation of the role-5 actor being checked, not a health-zero store to the actor resolved by the reverse key. A selected actor still having role zero does not enter this role-5 subsection. [Evidence: `decompiled/client/assembly.txt`, RVA 0x20EAAF–0x20EB0B.]

| Route with numeric forward ID zero | Direct lookup of forward key zero | Immediate consequence within that route |
| --- | --- | --- |
| Category 0x13, first maintenance gate | Bypassed | Clear and recovery scan |
| Category 0x13, post-recovery refresh gate, F still zero | Bypassed | Snapshot updates, then creation gates |
| Other category maintenance | Performed | Resident selector 7 retains it; otherwise clear F and zero a non-null lookup result's health |
| Later all-creature pass | Performed | Designated category-0x13 actor may receive the mapped actor's stored item level/value; no forward-result health store here |

Numeric zero, null actor pointers, absent map entries, own ID zero and reverse owner ID zero therefore remain distinct inputs. The inspected integer tests and copies themselves use no random draw. Creation and configuration invoke nested allocation, appearance, numeric and behavior dependencies whose full effects and random order are outside this scope. The contract establishes local branch/read/store order for valid native containers and readable retained actor pointers. It does not prove synchronization against concurrent mutation, every alias of an actor pointer under multiple keys, whole-frame final health, later lifecycle outcomes, all upstream world gates or a server counterpart.
