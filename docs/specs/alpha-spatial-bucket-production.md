# Alpha resident spatial bucket production and bounded scan order

Status: FINAL / STABLE / HELD after complete author readback.

This contract closes the ordinary new-chunk publication pass that supplies the resident buckets read by client helper RVA `0x209480`, together with the bucket constructor/destructor and a bounded third-axis consumer-order relation. The supported original image is `binary/Cube.exe`, base `0x00400000`, SHA-256 `84a7a132a84d4282338e7ea45a1940d32066d64e39cbafed8f2418d5a6dc30bf`. Evidence paths are relative to `disassembled alpha cube world`; bare function filenames are under `decompiled/client/functions`. Original instructions in the scoped regions were checked against the image and `decompiled/client/assembly.txt`. The individually identified file `005e4850.c` reports a failed decompilation for native RVA `0x1E4850`; its relevant native instructions supply the evidence instead. No reconstruction, prior contract, replacement implementation or runtime observation supplies facts here.

## Resident storage and reference identity

Let W be the world receiver, C the chunk object reached through the world/parent tables, and R an ordinary spatial record in C's collection at `+0x0C`. That collection has three 32-bit beginning/end/allocation-end pointers at C `+0x0C/+0x10/+0x14`, and consecutive records at stride `0x188`. Index helper `0x04B560` returns the beginning pointer plus that stride times the supplied full 32-bit ordinal. Its logical count is queried by `0x04E890`. These records are different objects from the bucket headers and bucket nodes. [Evidence: files `0044b560.c`, `005a0e00.c`; native RVAs `0x1EDF67–0x1EE048`.]

C `+0xAC` is a 32-bit pointer to an array of 1,024 eight-byte bucket headers. Each header contains a 32-bit list-sentinel pointer and a separate full 32-bit count. The local array index is 32 times local Y plus local X. Thus the array is Y-major/X-minor even though the world and parent pointer tables use X as their outer coordinate. A header is a list object, not an eight-byte record pointer/size pair for a contiguous array of R values.

Each ordinary bucket node occupies `0x18` bytes: two 32-bit links, then a 16-byte reference payload. The payload is ordered as the R pointer, C's full signed 32-bit X coordinate, C's full signed 32-bit Y coordinate, then R's full 32-bit ordinal in C's `0x188` collection. The R pointer is the first payload member; `0x209480` loads it from node `+8` before reading R's selector. The three remaining members identify the owning chunk/ordinal in the publication pass; they are not copies of R's position or size. [Evidence: payload constructor `0x1C38A0`, node constructor `0x208A20`, allocation/link constructor `0x06D590`; native RVAs `0x1EDFF0–0x1EE02D`, `0x209C68–0x209C89`; files `005c38a0.c`, `00608a20.c`.]

Chunk constructor `0x2240F0` allocates `0x2004` bytes for this array, stores the element count `0x400` in the leading four-byte allocation cookie, constructs 1,024 headers at stride 8, then stores the address after the cookie at C `+0xAC`. Header constructor `0x2240D0` starts its count at zero and creates a separate self-linked sentinel using `0x06D590`. Consequently every ordinary freshly constructed bucket is empty but has a nonnull sentinel. Allocation failure and partial construction unwinding are outside this ordinary storage relation. [Evidence: `006240f0.c`, `006240d0.c`; native RVAs `0x2242C7–0x224321`, `0x2240D0–0x2240EE`.]

## New-chunk admission and publication timing

The reached routine `0x1E4850` takes full signed 32-bit chunk X/Y inputs and rejects either component outside `[0,65536)`. Its preceding work requests the surrounding parent objects through `0x1DA280`; the full parent-generation dependency is not reconstructed here. It then queries the requested resident chunk through `0x034D10`. A nonnull existing chunk returns before new allocation, generation seed or bucket population; this route does not clear and rebuild an already resident chunk's buckets. The new route allocates a `0xC8`-byte C, invokes `0x2240F0`, stores the requested X/Y pair at C `+0x60/+0x64`, and performs broader generation. [Evidence: native RVAs `0x1E4889–0x1E49D2`.]

On that new route, the direct seed at `0x1E49B5` is the wrapping 32-bit sum of W `+0x800188`, the Y input shifted left 16, and the X input. This precedes the wider generation and its unclosed nested random consumers. It does not make a complete generation draw contract. The bucket publication pass itself at `0x1EDF67–0x1EE048` contains no direct random or seed call; its reached indexing, numeric conversion, payload and list helpers contain none either.

The broader generator appends constructed R values to C `+0x0C` through `0x1A0E00`, including the concrete call sites `0x1E9E15`, `0x1EA9B6` and `0x1EBEFB`. That helper copies a record into the current logical end and advances the end by `0x188`; when capacity is exhausted it calls a separate capacity helper. It does not publish a bucket reference. The tail publication occurs after these reached generation/copy operations and after the inspected saved-state application call at `0x1EDE46`. Complete record distribution, every generator branch and capacity failure are unclosed. [Evidence: `005a0e00.c`, native call-site regions and `0x1EDE27–0x1EDE60`.]

Only after the bucket publication loop finishes does the routine store C in its parent's chunk-pointer table at `0x1EE05A`. The source table slot is selected from the requested chunk coordinates, with X-major/Y-minor placement in the parent's 64-by-64 table beginning at parent `+0x10018`. Thus ordinary bucket references are constructed before this final resident-chunk pointer publication. This is an ordered native mutation relation, not a claim of atomic publication, locks or concurrent visibility. [Evidence: native RVAs `0x1E48C2–0x1E4952`, `0x1E6B63–0x1E6B96`, `0x1EE032–0x1EE05A`.]

## Exact coordinate conversion and membership

The bucket pass starts R ordinal zero when C's signed logical record count is positive, visits ordinals in increasing order, and queries the current count again at each continuation. It does not freeze a separate copy of all records or counts. For each R, it reads the signed 64-bit position component at R `+0x10` first, then the component at R `+8`. These are Y and X respectively in the coordinate accessors used here. R's third position component at `+0x18` is not used to choose the bucket.

For each of those two components, helper `0x069060` converts the signed 64-bit input through a binary64 store, divides it in binary64 by the exact integer 8, then calls conversion helper `0x28D946` to obtain a signed 64-bit integer by truncation toward zero on the ordinary finite representable route. The temporary integer is next passed to `0x02F570`, which performs signed 64-bit division by 65,536 with truncation toward zero. Only the low 32 bits of that latter quotient become the global cell argument. The Y result is obtained first; the call to `0x02F640` receives the resulting ordered X/Y pair and the newly created C as its explicit chunk argument. [Evidence: native RVAs `0x1EDF83–0x1EDFE1`; helpers `0x0120B0`, `0x069060–0x06909D`, `0x02F570–0x02F581`, `0x28D946–0x28D9BA`.]

For ordinary fixed positions in the supported nonnegative world-coordinate range, this chain is exactly truncation of the raw fixed component by 524,288, producing eight-coordinate cells. The actual binary64 and narrowing boundaries above still matter for arbitrary signed 64-bit inputs; the contract does not replace them with an unlimited integer formula. On exact ordinary negative inputs, small negative coordinates can truncate into cell zero: raw fixed values from -524,287 through -1 produce zero, whereas -524,288 produces cell -1. Very large raw inputs, invalid floating conversions and high quotient halves are not given invented rejection or recovery behavior.

Getter `0x02F640` requires both full signed 32-bit cell arguments in `[0,2097152)`. With its explicit nonnull C argument, it derives a lower bound from C `+0x60` multiplied by 256 in 32 bits and divided signed by 8 with truncation, and the corresponding lower bound from C `+0x64`. It admits each cell component at the lower bound and rejects it at or above that bound plus 32. For the admitted chunk-coordinate range, these lower bounds are exactly 32 times C's coordinates. It then uses each cell's remainder by 32 and returns the address at C's bucket-array pointer plus eight times the local Y-major index. Missing/invalid global cells return null. This helper does not allocate a missing chunk or bucket. [Evidence: `0042f640.c`; native RVAs `0x02F640–0x02F714`.]

The supplied chunk boundary is substantive: a record whose computed cell lies outside its owning C's 32-by-32 cell rectangle is skipped by this publication pass. It is not inserted into a neighboring chunk instead. At the upper coordinate edge of C, equality selects a cell outside C and is rejected by this explicit-chunk check. There is exactly one candidate bucket address for each visited R; there is no minimum/maximum footprint range, neighboring-cell expansion or loop over covered cells in this producer.

Accordingly, the established membership relation uses R's stored X/Y position, not its size, orientation, selector or state. The bucket pass never reads those other members to choose or admit a reference. A wide or rotated record is not duplicated across its horizontal footprint by this pass. This statement concerns the closed new-chunk producer; exhaustive exclusion of every possible alias-based list writer is not established.

The same getter has a separate null-explicit-chunk route: it divides the admitted global cell coordinates by 32, queries chunk `0x034D10`, then uses the same local bucket index. Chunk lookup admits full signed chunk coordinates `[0,65536)`, divides them by 64, obtains a parent from W's 1024-by-1024 pointer table at `+0xBC`, and reads the parent's local chunk slot at `+0x10018`. Absent parents or chunks yield null. This route explains consumer lookup without assuming it is the route used by the publication pass. [Evidence: files `0042f640.c`, `00434d10.c`; helpers `0x034D10`, `0x034A90`.]

## Ordering, duplicates and bounded record fields

For a nonnull bucket result, the publisher forms the 16-byte payload from the current R pointer, requested chunk X/Y and current ordinal, then appends it with `0x1F4B50`. That helper constructs a node before the sentinel, increments the full 32-bit list count, then joins the new node into the tail links. Its explicit maximum-length check is exact count `0x0AAAAAA9`, with length-error handling outside the ordinary relation. Existing entries are not searched for equal pointers, equal positions, equal record values or matching identities. [Evidence: `005f4b50.c`, `00608a20.c`; native RVAs `0x1F4B50–0x1F4B92`, `0x208A20–0x208A59`.]

The query traversal follows the sentinel's forward link, then successive forward links. Therefore references sharing a bucket appear in increasing source-record ordinal for one ordinary completed publication pass, with any skipped out-of-chunk records absent. Separate records with identical selectors and positions remain separate references. The append helper itself permits duplicate payloads if called repeatedly; it is not a set. The top-level existing-chunk return prevents this new-chunk path from simply appending its same pass again to an already resident C. No ordering across different buckets or unrelated producers is inferred.

Only the following R members are needed to distinguish membership from later query admission. The common record-header copier `0x068670`, reached by record copy `0x18EA10`, preserves the full selector at `+0`, both 32-bit halves of each signed 64-bit position at `+8/+0x10/+0x18`, full orientation member `+0x20`, full 32-bit size components at `+0x24/+0x28/+0x2C`, and byte `+0x30`. The consumer interprets the size components as binary32 and uses signed orientation remainder by 2 to decide whether to exchange its first two sizes. These are copied state, not values regenerated by the bucket append. [Evidence: files `00468670.c`, `0058ea10.c`; native consumer RVAs `0x209D04–0x209D7E`.]

Record constructor `0x18EAA0` initializes byte `+0x30` to 1. Its inspected stores do not initialize the selector, position, orientation or three sizes; reached callers must supply their values. A saved-state consumer in `0x04CDB0` can overwrite successive records' state byte `+0x30` when its incoming full count equals the current positive record count. That changes the byte without itself relocating the record or publishing new bucket membership. The completed bucket pass still includes records with state byte zero because it has no state-byte test. Complete state writers and persistence format are outside scope. [Evidence: `0058eaa0.c`, `0044cdb0.c`; native RVAs `0x18EAA0–0x18EAF6`, `0x04D3D6–0x04D42B`.]

Constructor `0x18EAA0` separately stores full `0xFFFFFFFF` at R `+0x178/+0x17C/+0x180`, and record copier `0x18EA10` copies those full values. The bucket payload's explicit chunk/ordinal fields do not prove that R `+0x178` receives the same ordinal. No first-positive producer for that record association is closed here; it remains a separate dependency.

## Third-axis retained-terrain-result ordering

The following relation is limited to the original consumer region `0x209ACB–0x20A12A`. Earlier in each axis attempt, call `0x19F0A0` returns a terrain result, retained in a local byte at `0x209AB5`. A false result enters the record scan. A true result also enters that scan for axis ordinal 2, the third axis; true results on the other axis ordinals bypass this scan. The retained result is not cleared when the third-axis scan begins. [Evidence: native RVAs `0x209AAE–0x209ACB`.]

The scan derives horizontal cell X/Y from the current candidate fixed position by signed division by 65,536, narrowing to the returned 32-bit component, then signed division by 8 with truncation. Its ordinary neighborhood is X-center minus one through X-center plus one, with X as the outer progression, and Y-center minus one through Y-center plus one as the inner progression. Each bucket list is traversed in forward order. This neighborhood is a query choice; it does not imply that the record publisher expanded R's footprint into those buckets. [Evidence: native RVAs `0x209ACB–0x209B44`, `0x20A0D8–0x20A0FB`.]

With the retained terrain byte already true, there is no flag test before the first candidate bucket lookup. If that candidate has invalid global cell coordinates, a missing parent/chunk, a final computed bucket address of zero, or an empty list, the reached completion path tests the retained byte before incrementing the inner Y coordinate. It stops the record neighborhood there. It does not skip the empty/missing/invalid first bucket and continue searching for the first nonempty bucket. The global-invalid branch reaches that test directly; the missing-object and empty-list branches first rejoin the common bucket-completion boundary. A corrupt nonnull bucket/header or null record pointer is not a checked missing case: valid list storage and referenced records are prerequisites. [Evidence: native RVAs `0x209B44–0x209C78`, `0x20A0C4–0x20A0DF`.]

For a valid nonempty first bucket, the retained true terrain byte does not stop before its first record and is not tested after each rejected record. The consumer can traverse the entire first list: it excludes full selectors 7, 6 and 9; searches the actor-relative map at `+0x1468` using the full 32-bit R pointer as an unsigned key and skips a present key; then, for selectors 1, 8, 2, 3 and 5, skips a zero byte at R `+0x30`. Other selectors bypass that byte requirement. A record that passes those filters reaches the orientation/size reads and the subsequent directional/overlap geometry, despite the preexisting terrain result. Rejection by any filter or geometry advances to the next node before any retained-terrain test. Only exhaustion of the list reaches the common bucket-completion test. With the retained byte true, that test stops before any Y increment or another bucket lookup. Map producers and the complete geometry arithmetic are not reconstructed here. [Evidence: native RVAs `0x209C80–0x209D7E`, `0x209D7E–0x20A0BE`, retained test `0x20A0CC–0x20A0D6`.]

If the first bucket's inner range is itself not entered, the separate inner-range completion test checks the retained byte before outer X progression. If the outer range is not entered, its completion test likewise preserves the terrain result before leaving this scan. These range guards are distinct from record rejection; ordinary nonoverflowing center-minus/plus-one ranges each contain three values. Integer overflow and malformed positions are not assigned a repaired neighborhood. [Evidence: native RVAs `0x209B20–0x209B3E`, `0x20A0EB–0x20A124`.]

The normal first-blocking-record exit is earlier than list completion. After a record passes the preceding filters, directional admission and overlap comparisons, the final vertical upper comparison accepts a block only on its strict-less side. Its accepted paths reach `0x20A10A`, establish a true result and immediately leave the record/neighborhood traversal through `0x20A120`; the common result test is at `0x20A12A`. This happens before the next-node advance at `0x20A0B8`, the inner-coordinate increment at `0x20A0D8`, or the outer-coordinate increment at `0x20A0F2`. Equality at that final upper comparison rejects this record and takes ordinary next-node progression. With an initially false terrain byte and no blocking record, bucket completion instead permits the remaining Y buckets and then the next X neighborhood row. [Evidence: native RVAs `0x20A08B–0x20A12C`.]

## Removal, reset and lifetime limits

The bucket node owns the copied 16-byte reference payload and its links; it does not own a copied `0x188` R object or R's nested allocations. C owns the record buffer separately. During chunk destruction `0x224390`, the bucket array is destroyed before the later record-buffer destruction/free at C `+0x0C`. The array destructor visits headers in reverse storage order on the ordinary path. For each header, `0x0DA480` first resets the sentinel links and count to the empty state, then deletes the former nodes in forward list order, then deletes that header's sentinel. It never dereferences or destroys the R pointer in a node payload. After all header destructors, the bucket-array allocation including its cookie is freed. [Evidence: `00624390.c`, `004da480.c`; native RVAs `0x2243EE–0x224414`, `0x224676–0x2246AD`, `0x28D800–0x28D84B`, `0x0DA480–0x0DA4BD`.]

The deleting wrapper `0x224760` invokes that chunk destructor and frees C itself when its low option bit is set. The established reference lifetime is therefore bounded by the continued existence and address stability of C's R buffer and the bucket nodes. This document does not promise that references survive later record-vector resizing, erasure, sorting, chunk replacement or destruction. No individual-record bucket-removal/reinsertion policy, independent live bucket rebuild, or complete world unload/reset caller admission is closed here. Changing R's selector, byte, position or size cannot be assumed to repair its already published bucket membership.

The unclosed dependencies are the complete spatial record generators and their random order, all alias-based list writers, parent acquisition/generation, saved-state safety, complete geometry and actor-map ownership semantics, individual record relocation/removal, exceptional allocation/conversion behavior, synchronization and a server counterpart. The closed producer supplies one center-selected reference per admitted ordinary source record, before final chunk publication, with the explicit ordering and ownership bounds above.
