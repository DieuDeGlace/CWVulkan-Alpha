# Original reroot reference acceptance boundary

Status: FINAL / STABLE / HELD. This independent, code-free contract covers one predecessor-walk boundary inside original client RVA `0x1A7EB0`: a retained pending coordinate whose current record is already the nearest/reference record. It does not revise or depend on earlier held contracts.

The supported image is `binary/Cube.exe`, SHA-256 `84a7a132a84d4282338e7ea45a1940d32066d64e39cbafed8f2418d5a6dc30bf`, preferred image base `0x00400000`. Paths are relative to `Documents/disassembled alpha cube world`. The statements below were confirmed directly from the original image instructions; no reconstruction, replacement code, runtime material, or earlier prose is evidence.

The reroot body first obtains a reference record by looking up the nearest list node's three coordinate words at RVA `0x1A85FB`, retaining the returned 32-bit pointer. It separately looks up the current retained pending key at `0x1A862A` and retains that returned 32-bit current-record pointer. The original call boundary is coordinate-record lookup RVA `0x1A9DA0`. [Evidence: `binary/Cube.exe`, RVAs `0x1A85E8–0x1A8608`, `0x1A8614–0x1A8633`.]

For a nonnull current record, the comparison at `0x1A86B0` tests **current-record pointer equality with the reference pointer before any predecessor-coordinate read**. Equality branches directly to the accepted-chain continuation at `0x1A878E`. Only inequality reaches reads of the current record's three 32-bit predecessor components at `+0x14`, `+0x10`, and `+0x0C`, in that instruction order, followed by the predecessor lookup at `0x1A86C5`. After following a predecessor, the new current pointer returns to the same equality check at `0x1A86B0`. [Evidence: `binary/Cube.exe`, RVAs `0x1A869C–0x1A86C5`, `0x1A8731–0x1A8739`, `0x1A878E–0x1A8799`.]

Consequently, when a retained pending key already identifies the nearest/reference coordinate and both ordinary lookups return its same valid record address, that chain is accepted immediately. It does not first follow, validate, or reject the reference record's existing predecessor. There is no requirement at this boundary that the reference's old predecessor be a different record, a self-reference, or a separately resolvable key. This conclusion concerns acceptance of that retained chain; later reference-record publication and predecessor rewriting are outside this short contract.

The ordinary conclusion requires a valid nonnull reference/current record, correct keyed storage, and stable readable pointers through the comparison. The initial current-pointer null test and the separate comparison at `0x1A8749` are not a general validation of a missing reference. Missing or corrupt map state, concurrent replacement, stale pointers, allocation failures before the check, and broader predecessor-cycle behavior are unclosed. No normalized malformed-state result, whole-reroot guarantee, or server equivalence is inferred.
