# Alpha server mode-word and spatial-association origins

Status: FINAL / STABLE / HELD after the author's complete saved-document readback. This is a bounded original-source contract. It establishes a server receive-and-copy route that can publish mask `0x0020`; it does not establish an autonomous server decision that first selects that mask. The inspected spatial-record routes establish initialization and preservation, but do not close a first nonnegative association producer.

## Supported evidence and notation

The evidence root is the relative identifier `disassembled alpha cube world`. The available original `binary/Server.exe` has SHA-256 `1ffbcbce251e1506a63c9ce18ab0009d5553fcbb9e6202be2bc3a7d870d34fb1` and length 1,718,784 bytes. Its PE header identifies x86 machine `0x014C`, PE32 optional-header magic `0x010B`, preferred image base `0x00400000`, image extent `0x001A8000`, entry RVA `0x0014B44B`, and raw COFF timestamp `0x51EA94D5`. These identify the inspected server image; the filename and timestamp do not authenticate a matching client build or a release history.

All routine and instruction addresses below are server RVAs relative to that image base. `S/name.c` means the original relative path `decompiled/server/functions/name.c`; the original instruction listing is `decompiled/server/assembly.txt`. Scoped listing instructions were checked against bytes in `binary/Server.exe`. Source listings supply navigation and data-flow context; the stated widths and constants are supported by original native instructions. No reconstruction, other contract, runtime launch, capture, or replacement implementation was used.

`C` denotes the server actor receiver established by its constructor, and `D` its embedded data receiver at `C+0x10`. `R` denotes the independently established server spatial-record family whose collection stride is `0x188` bytes. These are local descriptive identifiers, not claims that arbitrary objects sharing an offset have the same layout. Integer members described as raw bits have no stronger signed semantic type established here.

## Independent server receiver relationships

At actor constructor RVA `0x006400`, the eight-byte supplied identifier is copied to `C+0x08` and `C+0x0C` as two four-byte pieces. The same constructor calls data initialization RVA `0x007020` with `C+0x10`; the establishing instructions are `0x00642D–0x006441`. Consequently, the two-byte member at data-relative `D+0x114` is actor-relative `C+0x124` in this server image. This relationship is established within the server, without transferring a client offset. Evidence: `S/00406400.c`, `S/00407020.c`, and the corresponding original instructions.

A server relationship predicate at RVA `0x0CFCC0` independently reads the low byte of each actor's `C+0x124` and tests mask `0x20` at instruction RVAs `0x0CFD29` and `0x0CFD32`. Earlier role-byte and classifier-dependent exits remain significant: these final tests are not an unconditional replacement for the preceding predicate. The successful/unsuccessful result is established in the low result byte; unspecified upper result bits are not a full-width Boolean contract. The classifier at `0x00F710` and the broader meaning of role byte `C+0x60` are outside this audit. Evidence: `S/004cfcc0.c`.

The spatial family is established separately by constructor RVA `0x0C84B0`, copy routine `0x0C8420`, collection append `0x0D6670`, and an actual server hit-application consumer in `0x0CEA80`. Their matching constructor/copy tail, `0x188` collection stride, and consumer's four-byte `R+0x178` read establish the receiver relationship. An actor-data float at data-relative `+0x178`, and unrelated objects with a member numbered `+0x178`, are not this association member.

## Mode-word defaults, raw copies, and selective changes

Data initialization RVA `0x007020` stores a zero two-byte word at `D+0x114`, instruction RVA `0x0070DC`. Actor reset RVA `0x0110D0` passes `C+0x10` to data reset RVA `0x011360` at `0x0110DD`; that reset clears the same two-byte word at `0x011439`. Thus these inspected fresh/reset boundaries clear mask `0x0020` together with the rest of the word. They do not select a positive mode value. Evidence: `S/00407020.c` and the original instructions for `0x0110D0` and `0x011360`.

Assignment RVA `0x01DF70` copies the source's full two-byte `D+0x114` word to the destination's corresponding word, with the load/store at `0x01E023/0x01E02A`. Data copy construction RVA `0x022F90` likewise preserves the full word at `0x023042/0x023049`. There is no mask-`0x0020` stripping, sign conversion, or independent bit decision at either word transfer. For ordinary valid distinct objects, a source word `0x0020` yields that destination word, a source zero clears the destination word, and every other source bit is copied as well. Evidence: `S/0041df70.c`, `S/00422f90.c`, and their original instructions. This is value propagation, not proof of where the source first acquired its value.

Selective helper RVA `0x005570` receives `D`. Its first stack argument occupies four bytes but only its low 16 bits select word bits; its second argument also occupies a four-byte slot, with only the low byte deciding set versus clear. A nonzero decision byte sets the selected bits; a zero decision byte clears them. Other bits in the two-byte word are preserved. The helper has no ownership, health, role, or mask-specific admission and has no nested call. This establishes the callable ability to select mask `0x0020`, not a reached call supplying it. Evidence: `S/00405570.c` and native RVA `0x005570–0x005597`.

Sixteen identified instruction-aligned direct calls to this helper occur in world routine RVA `0x1322D0`. Their masks are `0x0008` once, `0x0080` three times, `0x0004` twice, `0x0010` six times, `0x0400` once, and `0x0001` three times. None selects bit `0x0020`. The call RVAs are `0x135E75`, `0x13792A`, `0x1379A0`, `0x1379D9`, `0x137A12`, `0x137ABC`, `0x13E65C`, `0x13E68A`, `0x140A2E`, `0x140AAB`, `0x140BB4`, `0x140C0F`, `0x140C1B`, `0x140C49`, `0x140C55`, and `0x14211C`. This is a bounded direct-call finding, not a proof excluding indirect calls, differently based pointers, wider copies, or all possible stores elsewhere in the executable.

## Concrete server input-to-resident publication

Receive worker RVA `0x026020` provides an actual route for the mode word to reach a resident actor. Its context supplies world pointer `W` at context `+0x00`, connection-selection storage through `+0x04`, a four-byte selection index at `+0x08`, an eight-byte actor-map lookup key at `+0x10`, and a pointer to a running byte at `+0x24`. At the inspected loop entry the running byte must be nonzero, the selected connection pointer nonnull, and the worker's failure state clear. This does not close the construction or lifetime of those context members. Evidence: `S/00426020.c`.

For incoming full-width message selector zero, the worker reads a four-byte payload length. The ordinary route requires nonzero length and a payload-receive helper result other than `-1`. It prepares a buffer, consumes an initial eight bytes into a separate temporary, and then snapshots the resident actor data. Those initial payload bytes are not the actor-map key at either of the two lookups described below. The scoped payload receive/buffer helpers at `0x0286B0`, `0x012D90`, and `0x015C90` are not a complete framing, decompression, validation, or short-read contract here. Evidence: `S/00426020.c`, especially native RVAs `0x026203–0x02625F` for the publication sequence.

The snapshot lookup uses the context's eight-byte key at `+0x10`. Under the world critical section, the worker looks up `C` and copy-constructs temporary `D` from `C+0x10`. It releases that section before decoding the payload into the temporary. It then reacquires the same section, repeats the actor lookup using the same context key, assigns the temporary to the newly returned actor's `C+0x10`, and releases the section. The exact native call order is snapshot lookup at `0x02620E`, copy at `0x02621D`, release at `0x026224`, decode at `0x026237`, reacquisition at `0x026241`, repeated lookup at `0x026250`, assignment at `0x026258`, and release at `0x02625F`. The two locks do not make the interval between snapshot and assignment indivisible, and this contract does not assume the repeated lookup returns the same pointer.

World locking helpers RVA `0x0D3DF0` and `0x0D5C60` pass `W+0x8000C0` to the imported `EnterCriticalSection` and `LeaveCriticalSection` routines, respectively. The associated imports are reached through image addresses `0x00558054/0x00558058`. This server lock identity is independently established. Recursive entry behavior, lock initialization/lifetime, all competing writers, and the worker's shutdown synchronization remain unclosed. Evidence: `S/004d3df0.c`, `S/004d5c60.c`, original instructions, and `binary/Server.exe` imports.

Lookup RVA `0x005420` uses the map at `W+0x04`; helper `0x130600` compares the complete eight-byte key. Its ordering compares the high four bytes as signed and, for equal high pieces, the low four bytes as unsigned. A match returns the pointer stored at node `+0x18`; a missing key returns null. This helper has no special rejection of an all-zero key. The worker has no intervening null check before accessing the returned pointer's `+0x10` on this publication route, so ordinary successful publication presupposes a valid mapped actor at both lookups. It does not establish safe missing/null handling or a rule creating the context key. Evidence: `S/00405420.c`, `S/00530600.c`, and the worker sequence.

Decoder RVA `0x015DD0` first reads an eight-byte field-presence mask. For the resident mode word it invokes the two-byte reader RVA `0x015260` with temporary `D+0x114`, at native RVAs `0x015F12–0x015F22`. When that word's presence entry is absent, the reader leaves the temporary word unchanged. When present with two available bytes, it copies the raw two-byte payload word and advances the buffer offset by two. No selected resident-word bit is filtered. The field-presence mask is separate from the copied mode-word bits; this document does not supply a complete packet schema or infer presence from resident mask `0x0020`. Evidence: `S/00415dd0.c`, `S/00415260.c`.

Combining these original operations closes a positive carrier route: an ordinary sufficiently complete message-zero update containing this field with raw value `0x0020` can publish that bit into the actor selected by the context key, through temporary decode and full-word assignment. A present zero word can clear it. An absent field preserves the earlier snapshot's word in the temporary, which is later assigned. The local publication sequence has no controlled-pointer comparison, role test, health test, or special `0x0020` admission between decode and assignment. This states the inspected local sequence, not the absence of upstream connection admission or other message handling.

For a present word with fewer than two available bytes, the word reader clamps its offset to the buffer length and leaves the destination word unchanged, while advancing its field index. The worker does not test a decoder result between the decode and the following lock/assignment sequence. These observations do not establish that malformed or partially received messages safely reach this point: preceding buffer construction, the entire decoder's other fields, socket failure handling, and allocation exceptions remain dependencies. No malformed-packet acceptance guarantee is supplied.

A separate server data-difference builder at RVA `0x016210` reaches two-byte field helper `0x014A80` for the same data-relative word, call RVA `0x0163FA`. The field helper selects the new word's two raw bytes when the force byte is nonzero or the old/new words differ; an equal word with a zero force byte is omitted. It records the corresponding presence entry without filtering mask `0x0020`. This shows that the server's selected-field representation can preserve the bit on output. It does not close every sender's routing, recipient filter, eventual delivery, or source of the force byte. Evidence: `S/00416210.c`, `S/00414a80.c`.

## Spatial-record initialization and preservation

Constructor RVA `0x0C84B0` establishes these direct defaults, in the order relevant to the tail: byte `R+0x30` becomes one; four-byte members `+0x34`, `+0x38`, `+0x40`, and `+0x44` become zero; embedded initialization runs at `R+0x48`; then full four-byte members `+0x178`, `+0x17C`, and `+0x180` each become `0xFFFFFFFF`, followed by four-byte `+0x184` becoming zero. The association store is native RVA `0x0C84DB`. The embedded initializer `0x006EF0` ends its known object extent at relative `+0x130`, ending at `R+0x178` exclusively when called at `R+0x48`; it does not overwrite this association default. The constructor is not a complete zero fill of the record, and unlisted prefix bytes or padding are not certified. Evidence: `S/004c84b0.c`, `S/00406ef0.c`.

Copy routine RVA `0x0C8420` transfers the association as one full four-byte raw member: source read `0x0C8468`, destination store `0x0C8471`. The surrounding record copy transfers the prefix and embedded members, then tail members `+0x170`, `+0x174`, `+0x178`, `+0x17C`, `+0x180`, and `+0x184`. No sign conversion, default substitution, ordinal calculation, or association validation occurs at that four-byte transfer. Thus a valid source association of zero, a positive signed-32 value, or `0xFFFFFFFF` is preserved as identical bits. This does not make every such source value reachable from a native generator. Evidence: `S/004c8420.c` and original instructions.

Collection append RVA `0x0D6670` uses begin/end/capacity pointers and advances the live end by `0x188` after copying the appended record. It invokes `0x0C8420`; if the supplied record is already inside the old collection, it recovers that record's array position across capacity growth before copying. That temporary position is used to locate the source after relocation; it is not written into association member `R+0x178`. The append therefore preserves the source association rather than assigning the destination's new ordinal. Capacity growth at `0x0CE8E0`, allocator failure, exception cleanup, invalid/interior source pointers, and general pointer lifetime are not fully specified. Evidence: `S/004d6670.c`, especially native RVAs `0x0D6705–0x0D670A`.

Their enclosing generators' complete input admission and all preceding nested producers are not closed here. These stores are preservation boundaries, and their existence does not establish that the copied source was nonnegative. Evidence: scoped regions of `S/004e0740.c`, `S/005104e0.c`, `S/00524540.c`, and their original instructions.

## Actual server association use and remaining origin boundary

Inside server hit application RVA `0x0CEA80`, instructions `0x0CF1B3–0x0CF1BF` use the actor's full four-byte members `C+0x1B0` and `C+0x1B4` as inputs to container lookup `0x006290`. When the returned container is nonnull, the scan traverses its record range from container `+0x0C` to `+0x10` in `0x188`-byte steps. A candidate must have full four-byte selector `R+0x00` equal five, then raw four-byte association `R+0x178` equal the actor's full four-byte `C+0x1B8`, then nonzero byte `R+0x30`. The association comparison itself is raw equality and has no separate nonnegative admission. Evidence: native RVAs `0x0CF1C4–0x0CF1FA`.

The scan counts array positions separately. On its first matching record it calls state helper `0x0D8C90` with that record and a zero state byte at `0x0CF209`; later it stores the separately counted ordinal into an outgoing local value at `0x0CF224`. The association is not replaced with that ordinal in this sequence. The helper's inspected body changes state byte `R+0x30` and associated state/presentation data when its old state differs; it has no direct association store. Its event-allocation helper and the subsequent outgoing publication are not a complete transitive mutation/lifetime contract here. Evidence: original hit-application instructions and `S/004d8c90.c`.

This independently closes server receiver identity, a real equality consumer, default construction, raw record copies, append preservation, and several concrete default-producing generation routes. It does not prove a descriptor-ordinal association. Zero or a positive signed-32 association would be preserved by the verified copy path, and the equality consumer does not reject it by sign, but no inspected route establishes the first such source assignment. A complete spatial-record file/socket decoder, all indirect writers, differently based stores, enclosing generator dependencies, descriptor activation correspondence, removal/reconstruction, and backing ownership/lifetime remain unresolved. The actor-data message-zero decoder above is not identified as a decoder for this `0x188`-byte record family.

The resulting origin limits are distinct. For resident mode mask `0x0020`, the server has a verified input-decode-to-resident carrier and full-word copy/reset boundaries, while the upstream rule that first chooses the incoming bit remains unclosed. For spatial association `R+0x178`, the server evidence in this audit supplies defaults and preservation, but does not establish a first nonnegative producer. Neither limit supports a claim that the behavior is absent from all original server paths, that client/server offsets generally coincide, or that fields with equal numeric offsets share an identity.
