It describes the second child update at client RVA `0x03ACE0`, including its terrain/path continuation and ordinary low-byte returns, and separately establishes selected producers and copy/reset boundaries of the 24 bytes consumed by the third child at `0x0DBF20`. ## Inputs and arithmetic conventions

At `0x03ACE0`, the child object supplies its full 64-bit key at child `+0x08`. Its four stack arguments, in argument order, are the subject actor, world, signed 32-bit update amount, and an output-aggregate argument. The last argument has no direct use in this routine. Below, the subject is **A**, the actor found through the key is **T**, and the world is **W**. The lookup uses W's map at `+0x04`; it does not substitute T's stored identifier for the child key. An absent entry or null mapped pointer returns low byte zero before the actor mutations described below. There is no additional direct self-pointer, zero-key, health, class or relationship test at that admission boundary. This is a statement about the reached helper, not the root's earlier admission or object lifetime. [Evidence: `decompiled/client/functions/0043ace0.c`; native RVAs `0x03ACFA–0x03AD33`.]

Actor positions at `+0x10`, `+0x18` and `+0x20` are three signed 64-bit fixed-point components, with 65,536 integer units per coordinate unit. Subtractions and additions in this caller retain 64-bit wrap. Its scalar SIMD operations round to binary32 at each arithmetic operation; signed-integer conversions and x87 stores have the separate boundaries stated below. Claims about scalar comparisons below concern ordinary finite operands under ordinary floating-point controls. NaNs, unmasked floating-point exceptions, invalid pointers, corrupted containers and concurrent mutation are not given a repaired or safe interpretation here.

## Prefix effects and direct-route result

The mask-`0x0040` decision precedes the amount update, component clearing, terrain queries and path operations. T's position minus A's position is measured with helper `0x03AC20`: X, Y and Z products are each retained at 64 bits, interpreted as signed and divided by 65,536 with truncation toward zero, then accumulated in X/Y/Z order with 64-bit wrap. Here both product operands are the same displacement. A's word mask is set only when the signed 64-bit result is strictly greater than `0x400000`; equality and smaller results clear it. Other bits are preserved. [Evidence: `decompiled/client/functions/0043ac20.c`, `0043ace0.c`; native RVAs `0x03AD39–0x03ADF5`, `0x03AC20–0x03AC9E`; integer helpers `0x28DA90`, `0x28D9E0`.]

When A's discriminator byte is 5, helper `0x044DB0` is queried and its x87 result is stored as binary32. The signed update amount is converted to binary32, multiplied first by binary32 `0.001` (bits `0x3A83126F`) and then by binary32 `0.1` (bits `0x3DCCCCCD`). That rounded factor multiplies the first rounded query result; A's existing `+0x16C` is added, and the result is stored there. A second query is rounded to binary32 for the upper comparison. Only if the stored result is greater than that second value is a third query made and rounded into `+0x16C`. Thus the ordinary call count is two, or three on the upper replacement; the third result is not assumed equal to either earlier result. No lower clamp or positive-update admission appears here. The internal stat relation of `0x044DB0` is not closed by this audit. [Evidence: native RVAs `0x03ADF5–0x03AE63`; constants at image RVAs `0x2FD870`, `0x2FCB7C`.]

The displacement is then recomputed. Each signed 64-bit component is converted through an x87 binary32 store before binary32 multiplication by exactly `2^-16`. The squared measure begins with rounded Y-square, adds rounded X-square, then adds rounded Z-square. A's three `+0x40` components are cleared to positive zero before the comparison. A measure strictly less than 16 returns low byte zero, leaving that clearing and earlier prefix effects in place; equality continues. [Evidence: native RVAs `0x03AE63–0x03AF67`; constants at RVAs `0x2FCD94`, `0x345E78`.]

The next gate is helper `0x209480`, with W as receiver and arguments A, A's position address, T's position address, and the binary32 sum of A's and T's `+0x80`. Its low byte is tested. This document does not substitute a visibility or collision rule for that helper's broad geometry dependency. On a nonzero result, path state is cleared through `0x02EF10`. The X and Y displacement components are multiplied by 5; the vertical component is positive zero multiplied by 5. Their binary32 squared measure is accumulated Y-square plus X-square, then Z-square. Above 900, and only above 900, the measure is widened exactly to binary64 for the reached square-root routine, its result is rounded back to binary32, and binary32 reciprocal length is formed. Each component is multiplied by that reciprocal and then by 30, with separate binary32 rounding. At 900 there is no normalization. The three results are stored at A `+0x40/+0x44/+0x48`, followed by low-byte result 1. No direct current-position write occurs. [Evidence: `decompiled/client/functions/00609480.c` for the bounded gate; native caller RVAs `0x03AF67–0x03B070`; constants at RVAs `0x2FCE24`, `0x2FD874`, `0x2FCD78`; reached square-root thunk `0x28D9C8`.]

## Terrain sampling and corrected coordinate

Only a zero low-byte result from `0x209480` enters the terrain continuation. A mutable local coordinate is initialized from T's current position. X and Y remain those sampled values throughout the two vertical searches. Each terrain query calls `0x02F860` on W with the six 32-bit halves of that coordinate in X/Y/Z order and a final full-width zero option. The caller tests only the low five bits of the returned four-byte cell record's last byte. Values 0 and 2 are the accepted pair for the tests below; no independent test of flag `0x40` is added by this child. [Evidence: native RVAs `0x03B073–0x03B175`.]

The downward search begins at T's sampled coordinate. For a low-five-bit value of 0 or 2, local Z is reduced by 65,536 with 64-bit wrap and a local signed 32-bit count is incremented. A count above 20 returns low byte zero. Consequently it can query 21 successive locations, beginning at the sampled Z and ending 20 units below it; after the 21st accepted-pair result it advances once more and returns without querying that next coordinate. The actor's actual position is not changed by these advances.

At the first other low-five-bit value, the count is reset and the upward search queries that same coordinate again. It does not assume the earlier record is reusable. A value of 0 or 2 accepts the present coordinate. Any other value adds 65,536 to local Z and increments the count; a count above 20 returns zero. This phase likewise allows at most 21 queries, including the repeated first coordinate, and may advance to an unqueried 22nd location before returning zero. The two phases therefore preserve query order and permit intervening storage changes to matter; they are not one scan with a cached turning-point record.

The terrain getter's coordinate conversion differs from the path-grid conversion below. At `0x02F860`, a negative signed 64-bit component is first reduced by 65,536 with 64-bit wrap; each resulting component is divided by 65,536 with signed truncation toward zero, keeping the low 32-bit quotient. Division order is Z, Y, X, followed by the integer-coordinate getter `0x02F7E0`. In the ordinary nonoverflow range, both this getter and the path-grid conversion map a negative exact unit boundary one integer below that boundary; neither should be silently replaced with ordinary mathematical floor at those boundaries. [Evidence: `decompiled/client/functions/0042f860.c`, `0042f7e0.c`; native RVAs `0x02F860–0x02F90C`.]

With this zero option, integer X/Y must be in `[0, 0x1000000)` for the column lookup. The lookup uses `0x034D10`; its two integer cell coordinates must be in `[0, 65536)`, and its parent lookup `0x034A90` admits `[0, 1024)` in each dimension. Missing pointers are returned rather than loaded or generated here. The column address uses the Y remainder before the X remainder, in a 256-by-256 array of 32-byte records. `0x02F7E0` returns the shared record at RVA `0x36AFC4` for a missing column or Z below the column's signed base. At or above base plus count it returns RVA `0x36AFC0` for positive Z and `0x36AFBC` otherwise. For an in-range stored record, low-five-bit zero at nonpositive Z, without flag `0x40`, is replaced by `0x36AFBC`. [Evidence: `decompiled/client/functions/004347a0.c`, `00434d10.c`, `00434a90.c`; native RVAs `0x02F7E0–0x02F854`, `0x0347A0–0x03486D`.]

Initializer `0x2F9720` establishes the record at RVA `0x36AFC0` as bytes `FF FF FF 00`; `0x2F9750` establishes `0x36AFC4` as `C8 C8 C8 01`; `0x2F9780` establishes `0x36AFBC` as `FF FF FF 82`. Their low-five-bit values are respectively 0, 1 and 2. These are initialized-record facts, not an inference from zero-filled image storage. For a consistent in-range column, `0x02F730` simply returns the stored four-byte record; its separate out-of-range shared-record initialization branches are not needed by this ordinary reached interval. No allocation, actor-position write or random draw occurs in the audited zero-option lookup chain. Column allocation, streaming and concurrent lifetime are separate dependencies. [Evidence: native RVAs `0x02F730–0x02F7DB`, `0x2F9720–0x2F97A7`; `binary/Cube.exe`.]

## Path setup and work budget

After accepting a corrected terrain coordinate, the caller forms a binary32 vertical value equal to A's `+0x88` multiplied by 0.5. `0x02C460` converts the triple positive-zero, positive-zero, half-height into a 24-byte fixed-point triple: X, then Y, then Z are multiplied by 65,536 in binary32, stored as binary32, then converted to signed 64-bit integers by the reached truncation helper `0x28D946`. There is no negative-coordinate extra decrement in this conversion.

The two reached `0x02C7A0` calls subtract that fixed vertical triple from A's current position first, then subtract the corrected terrain coordinate. Each component subtraction wraps at 64 bits. Helper `0x02C4A0` converts this difference to binary32 by signed 64-bit conversion through a binary32 store, followed by binary32 multiplication by `2^-16`, in X/Y/Z order. The caller's squared measure begins with X-square, adds Y-square, then Z-square. Below 16, it clears path state, clears the three `+0x40` components again, and returns low byte zero. Equality proceeds. [Evidence: native RVAs `0x03B175–0x03B241`; helpers `0x02C460`, `0x02C4A0`, `0x02C7A0`; original files `0042c460.c`, `0042c4a0.c`, `0042c7a0.c`.]

A nonzero A `+0x1464` retains the existing path setup, including its stored start/goal coordinate triples and radius; the freshly corrected terrain coordinate is not copied into that existing setup. A zero count instead clears path state and establishes a new fixed start at A's current position plus a converted vertical offset. That offset is positive-zero, positive-zero, binary32 `0.1` minus the separately rounded binary32 half-height. Addition uses `0x02C800` with 64-bit component wrap. The start is copied to A `+0x1428`, and the corrected terrain coordinate is copied to A `+0x1440`; both are complete 24-byte copies through `0x02C5B0`.

The fresh-setup cell admission converts goal Y before goal X: signed 64-bit division by 65,536, retention of the low signed 32-bit quotient, then signed division by 256 with truncation toward zero. This particular conversion has no negative extra decrement. The resulting X/Y pair is passed to `0x034D10` on W. A null result returns zero after the clearing and both coordinate copies have already occurred. A nonnull result permits, in order, `0x1A9F90(W,A)`, storage of binary32 2.0 at A `+0x1458`, `0x1AAAB0(W,A)`, and `0x1A7C90(W,A)`. Only after these calls does the caller again clear A's three `+0x40` components. [Evidence: native RVAs `0x03B241–0x03B369`; helpers `0x02C800`, `0x02C5B0`, `0x034D10`.]

After either retained or fresh setup, a zero 32-bit `+0x1410` ends with low-byte result 1. Otherwise a separate local work count begins at zero. The caller admits at most ten additional pairs of `0x1AAAB0(W,A)` followed by `0x1A7C90(W,A)`. Before each pair it tests A's `+0x1464` as signed 32-bit: above 50 ends with result 1; 50 still permits the remaining admission tests. When the count is nonzero, it examines the last list node, obtained from sentinel `+0x04`, and reads its three 32-bit coordinate payloads at node `+0x08/+0x0C/+0x10`.

For this comparison the goal `+0x1440` is converted by `0x02F040`. That helper divides each signed 64-bit component by 65,536 with truncation toward zero and subtracts one for every originally negative component, retaining a 32-bit result. It computes Z, Y, X in that order. Node minus converted-goal differences, squares and additions are all retained at 32 bits; the addition order is Z-square plus Y-square, then X-square. The signed 32-bit sum is converted to binary32. A strict binary32 comparison of squared A `+0x1458` greater than this value ends with result 1; equality permits another pair. A zero list count omits this node-distance test.

The work count increments after each complete pair and stops at ten. The caller does not recheck `+0x1410` inside this bounded repetition. If a nested call clears it, later repetitions still depend on the list-count/distance tests and local ten-pair budget. Fresh setup can therefore reach one initial pair plus ten additional pairs; retained setup can reach ten pairs. These are call-count bounds, not promises that a complete route is found. Result 1 can accompany empty state or an exhausted budget. [Evidence: native RVAs `0x03B36B–0x03B447`; `decompiled/client/functions/0042f040.c`.]

## Closed path-state relations and open search dependencies

Reset helper `0x02EF10(A)` clears the two tree containers at A `+0x140C` and `+0x1414`, reestablishes their sentinel links, and stores zero counts at `+0x1410` and `+0x1418`. It detaches the coordinate list, sets `+0x1464` to zero, and deallocates its old nodes. It then sets `+0x1408` to the first tree's sentinel and clears the additional container at `+0x1468`. The helper itself does not clear `+0x1428`, `+0x1440`, `+0x1458`, `+0x145C`, A's current position, or its three `+0x40` components. The caller's explicit component clearing must therefore retain its own timing. [Evidence: `decompiled/client/functions/0042ef10.c`; native RVAs `0x02EF10–0x02EFB6`, reached tree-clear helper `0x02CA20`.]

At the beginning of `0x1A9F90`, this reset is performed again. The converted start triple is copied to the three 32-bit fields `+0x141C/+0x1420/+0x1424`; start conversion is repeated for a local triple, `+0x145C` is set to zero, and the goal is converted. For ordinary signed differences whose absolute values and arithmetic remain representable, the initial scalar weights the larger horizontal absolute difference by 10, the smaller by 4, adds ten times the vertical absolute difference, and doubles the sum. The native intermediate integer arithmetic is 32-bit; the final signed integer is converted to binary32 and truncated back to signed 32-bit, so large representable integers can be rounded at that conversion. The first 24-byte keyed record contains, in successive 32-bit fields, 1, that converted scalar twice, then the integer start X/Y/Z. It is inserted using `0x1A9E50`; `+0x1468` is then cleared before the helper's spatial-record gathering. Extreme signed absolute-value and float-to-integer invalid cases are not assigned ordinary mathematical absolute-value behavior here. [Evidence: native RVAs `0x1A9F90–0x1AA0A8`; `decompiled/client/functions/005a9f90.c`.]

The subsequent gathering in `0x1A9F90`, including spatial-record kind tests, extents and insertion into `+0x1468`, is not fully closed. Neither are all neighbor-generation, geometry, scoring, tie and container-order dependencies of `0x1AAAB0`. The latter's entry does establish a bounded relation: zero `+0x1410` returns; otherwise unsigned `+0x1418` above 500 or unsigned `+0x1410` above 20,000 clears path state and returns. Equality at either limit is admitted. In the admitted case it converts the goal; zero `+0x1418` then returns. Its initial candidate scan queries records by the traversed coordinate keys through `0x1A9DA0`, retaining the first available record or a later record only on a strictly smaller signed record field `+0x08`. Equal values retain the earlier traversed choice. The exact coordinate-key traversal ordering remains a container dependency. The chosen entry is removed from `+0x1414` before the goal-coordinate equality test; an equal triple returns without the later expansion. All other expansion geometry remains explicitly unresolved. [Evidence: native RVAs `0x1AAAB0–0x1AABF7`, `0x1AD2F9–0x1AD300`; original file `005aaab0.c`.]

The scoped record helper `0x1A9E50` uses a three-component 32-bit key, obtains its record slot through `0x1A7A70`, and overwrites all six successive 32-bit record fields from its input. It publishes the coordinate key into the second container through `0x1A7700` before possibly changing `+0x1408`. The selected pointer changes when it was the sentinel, or when the new signed record field `+0x04` is strictly smaller than the corresponding field of the current selection; equality preserves the old selection. The lookup/comparison helpers and allocation behavior remain dependencies for exact key ordering and exceptional failure. [Evidence: native RVAs `0x1A9E50–0x1A9F80`.]

Helper `0x1A7C90` closes a narrower list-production relation. It converts the stored start and goal, in that order, and clears the existing list/count. Its first coordinate is the converted goal unless `+0x1408` differs from the first tree's sentinel; then it uses the three 32-bit key components referenced by that selected node. It prepends that coordinate to the list. A match with the converted start returns immediately. Otherwise, a local signed traversal count, initially zero, is checked against signed A `+0x1410`; a count strictly greater ends traversal, while equality still permits another lookup. Each attempted lookup increments the local count first and calls `0x1A9DA0(A,current X,current Y,current Z)`. A null record ends traversal. A nonnull record supplies its next coordinate from signed 32-bit fields `+0x0C/+0x10/+0x14`; an unchanged triple ends traversal without another insertion. A changed triple is prepended, and traversal can end when that triple matches the start.

Thus the original selected/goal coordinate remains at the list's tail, while each reached predecessor is added at its front. Each node has two 32-bit links and a 12-byte coordinate payload. The 32-bit count increments before the newly allocated node is linked into the list; the explicit capacity check uses maximum `0x0CCCCCCB` and can call an exception routine rather than return ordinarily. This helper does not write A's actual position or its three `+0x40` components. It returns no path-success value used by this caller. A partial predecessor chain remains a possible ordinary list result. [Evidence: `decompiled/client/functions/005a7c90.c`, `005a6b60.c`; native RVAs `0x1A7C90–0x1A7E54`, lookup `0x1A9DA0`.]

## Stream preservation and replacement of the reference bytes

The original body-state stream wrappers also contain this interval. Their shared field counter places body `+0x1B0` at zero-based field 40 among 48 successive field operations. Its presence is represented by bit 40 of the 64-bit presence word, equivalently mask `0x100` in its high 32-bit half. The field is a raw 24-byte aggregate, with no coordinate transformation or ID lookup. This closure establishes the body-field operation; complete message dispatch, actor selection, source authority and receiver publication are not inferred from it. [Evidence: original files `004ccfa0.c`, `004cd3e0.c`, `004cdaa0.c`; respective native anchors `0x0CD319`, `0x0CD97C`, `0x0CDFCB–0x0CDFD2`; shared counter initialization and one-field increments in their reached field helpers.]

The in-memory decoder `0x0CCFA0` uses `0x0CC5C0` for this field. An absent presence bit advances the field counter and leaves the destination unchanged. With the bit present and 24 available bytes, the helper copies three successive 64-bit chunks, advances the input cursor by 24, advances the counter and returns 24. With fewer than 24 available bytes, it moves the cursor to the available end, advances the counter and still returns 24, but does not copy a partial reference field. That helper's return therefore does not certify that the reference was updated. Integer-overflow and invalid-buffer cases remain outside its ordinary valid-buffer relation. [Evidence: native RVAs `0x0CC5C0–0x0CC647`.]

The socket-body decoder `0x0CD3E0` instead reaches `0x0CC650`. A missing bit leaves the reference unchanged and advances the counter. A present field requests the remaining part of 24 bytes directly into the destination, advancing the destination after positive partial reads. A complete read returns 24 and advances the counter. A receive result of zero advances the counter and returns zero, preserving any already-written prefix. A result of minus one returns minus one without advancing the counter, likewise without restoring an already-written prefix. This differs materially from the in-memory decoder's whole-field availability check; neither route initializes an absent field to zero. [Evidence: native RVAs `0x0CC650–0x0CC6C0`; reached socket thunk `0x227234`.]

The difference producer `0x0CDAA0` uses `0x0CBC80`. With force byte zero it compares the three 64-bit component bit patterns exactly; complete equality advances the counter without queuing the field. Any difference, or any nonzero force byte, queues a descriptor containing the source address and full 32-bit length 24, then sets the presence bit and advances the field counter. This operation queues a pointer and extent, not a detached 24-byte snapshot. Allocation/exception and later gathered-copy lifetime remain dependencies. The sender's separately reached body snapshot copy is evidence of a concrete copying boundary, not a guarantee about every caller of this general difference helper. [Evidence: native RVAs `0x0CBC80–0x0CBD38`, `0x069F19–0x069F81`.]

## Return, random and remaining limits

The ordinary low-byte result from `0x03ACE0` is fully separated from path completion: zero is used for failed key/pointer admission, the initial sub-16 displacement, either exhausted terrain scan, the corrected sub-16 displacement, or failed fresh-setup cell admission. One is used after a nonzero direct-route gate and after the admitted path-work continuation, including zero `+0x1410`, list count above 50, strict list-distance admission, and ten-pair budget completion. Only the low byte is established as the decision result; the remaining return-register bits are not a full-width Boolean contract. Earlier writes are not rolled back when a later return is zero.
