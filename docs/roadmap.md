# AlphaVulkan roadmap

AlphaVulkan is CubeVulkan's sister engine: a Vulkan engine for **Cube World Alpha**, built
the same way. It reads content only from the owner's own Alpha install, every system is
written clean-room from a spec in `docs/specs/` (see [the process](CLEANROOM.md)), and
behaviour is checked against the game's own output.

The checked items below are the inherited handoff, not a new certification of
native parity or provenance. The continuation retains final native gameplay,
visual, save, network and clean-room audits as release gates.

Differences from the Steam engine that shape the plan:

* Alpha's content is in four SQLite stores (`alpha-data-stores.md`), not loose files.
* AlphaVulkan itself is 64-bit. Only an extractor mod that loads into Alpha's own process
  has to be 32-bit, because the game is.
* Alpha's `Cube.exe` is a plain 32-bit PE with no SteamStub, and the world is generated by
  `Server.exe`. An Alpha extractor would be a 32-bit mod DLL.
* No Steam account: saves stay local (`Save/characters.db`, `Save/worlds.db`), and multiplayer
  talks Alpha's own protocol to `Server.exe`.
* Native visual behavior follows `alpha-rendering.md`. The shared Steam water
  surface, swimmable shallows and bank reeds are explicit owner-requested extensions.
